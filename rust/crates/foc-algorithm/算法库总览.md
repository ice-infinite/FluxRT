# FOC Algorithm Rust

这是相邻 `lib` C 算法库的 Rust `no_std` 迁移工程。目标不是机械改名，而是保持算法行为可对照、实时路径不分配内存、芯片无关，并能直接用于 Cortex-M 裸机或 RTOS 工程。

## 当前结论

- 原 C 库：63 个生产模块可编译，64/64 个原始测试通过。
- Rust 四个阶段已完成：63/63 个生产模块已迁移，66/66 个 Rust 测试通过。
- 已验证目标：Windows 主机、`thumbv7em-none-eabi`、`thumbv7em-none-eabihf`。
- Rust 核心：`#![no_std]`、禁止 `unsafe`、无堆分配、无全局可变状态、无具体 MCU HAL 依赖。
- 原目录 `lib` 未修改；Rust 工程位于独立的 `lib-rs`。

完整逐模块状态和后续实机验证重点见 [算法库移植状态.md](算法库移植状态.md)。算法迁移完成不等于成品电调或关节驱动器已通过实机验收。

最终验收记录见 [算法库完成报告.md](算法库完成报告.md)。

需要按用途查找全部 63 个算法、源码位置和主要 API 时，查看 [算法库总览与对接指南.md](算法库总览与对接指南.md)。

  -> Id/Iq PI

## 快速使用

在上层 Rust 固件的 `Cargo.toml` 中使用本地路径依赖：

```toml
[dependencies]
foc-algorithm = { path = "../lib-rs" }
```

基础电流环示例：

```rust
use foc_algorithm::{
    FocBasicInput, FocBasicParam, FocBasicState, PiParam, SvpwmParam,
};

let current_pi = PiParam {
    kp: 1.0,
    ki: 100.0,
    ts: 0.000_05,
    out_min: -12.0,
    out_max: 12.0,
    integrator_min: -6.0,
    integrator_max: 6.0,
};
let param = FocBasicParam {
    id_pi: current_pi,
    iq_pi: current_pi,
    svpwm: SvpwmParam { v_bus: 24.0 },
};
let mut state = FocBasicState::default();

// 在固定周期控制路径中调用。theta_e_rad 必须是电角度，不是机械角度。
let pwm = state.update(
    &param,
    &FocBasicInput {
        ia: 0.0,
        ib: 0.0,
        ic: 0.0,
        id_ref: 0.0,
        iq_ref: 1.0,
        theta_e_rad: 0.0,
    },
);

// 将 pwm.duty_a / duty_b / duty_c 写入定时器比较寄存器。
```

示例参数只用于说明 API，不是任何具体电机的可直接烧录参数。实际项目必须根据采样周期、母线电压、电机参数、传感器方向与功率级限制整定。

## RT-Thread / 裸机接入边界

建议把本库作为纯算法层：

1. 驱动层负责 ADC/PWM/编码器、采样同步、死区、Break 和故障关断。
2. 控制层持有 `FocBasicState` 等状态，在固定采样周期内调用 `update`。
3. 应用层负责启停状态机、目标斜坡、通信、参数存储和诊断。

不要在电流环中动态创建对象、分配内存、打印日志或获取互斥锁。状态对象应在初始化阶段静态创建，并由唯一控制上下文修改。如果在 ISR 内运行，先实测 `sinf/cosf` 的最坏执行时间；高频控制可换成芯片 CORDIC、查表或预计算角度正余弦接口。

## 数值和安全约束

- 输入参数应为有限浮点数；`NaN/Inf` 不属于当前有效输入域。
- 所有角度单位为 rad，角速度为 rad/s，采样周期为 s。
- `FocBasicInput::theta_e_rad` 是电角度：`机械角度 × 极对数 + 零位偏置`。
- `SvpwmParam::v_bus <= 0` 时输出安全中点占空比 `0.5/0.5/0.5`。
- PI/PID 的积分限幅和输出反算抗饱和行为保持 C 版逻辑。
- `#[repr(C)]` 用于稳定数据布局准备，但当前没有导出 `extern "C"` 符号，不能把本 crate 当作现成的 C ABI 静态库。
- EKF/UKF 模型回调使用 `Option<extern "C" fn>`，没有堆分配或动态派发；未配置完整模型函数时更新返回 `0.0` 且保持估计状态不变。
- 强化学习 Q 表固定为 8×4；超过容量或索引非法时拒绝更新。当前策略是确定性贪心选择，不包含探索随机数。
- 神经网络拓扑固定为 2 输入、3 个 `tanh` 隐层节点、1 输出；权重训练和量化不在本库内完成。
- 遗传算法的 `mutation_signal` 必须由调用方提供；本库不绑定随机数源。MPC 的运算次数随 `candidates` 线性增长，实时固件必须给该参数设置经 WCET 验证的上限。
- 硬件过流、驱动器故障、欠压、过压和过温必须由独立保护路径处理，不能依赖算法返回值代替。

## 与 C 基线的有意差异

Rust `MtpvState::update` 会在每次搜索前清除 `valid`。原 C 实现一次找到可行点后，如果下一次搜索没有可行点，`valid` 可能错误保留为 1；Rust 版修正为无可行点时 `valid = 0`，并返回 `Id=-current_limit, Iq=0` 的退化结果。其余当前迁移模块以原 C 测试向量为行为基线。

# Rust FOC 算法库总览与对接指南

本文是 `foc-algorithm` Rust `no_std` crate 的总入口，用于快速查找 63 个已迁移算法及其源码位置。Rust 版与相邻 `../lib` C 库按算法行为对照，但把多个 C 目录合并进按功能组织的 Rust 模块。

## 1. 怎么接入

全 Rust 固件可在 `Cargo.toml` 中直接引用：

```toml
[dependencies]
foc-algorithm = { path = "../lib-rs" }
```

然后从 crate 根导入类型。`src/lib.rs` 已重导出全部公共接口：

```rust
use foc_algorithm::{FocBasicInput, FocBasicParam, FocBasicState};
```

本库是纯算法层：

- `#![no_std]`，没有堆分配、全局可变状态和 MCU HAL 依赖。
- 所有实时状态由调用方持有，通常采用 `Param + State + State::update()`。
- `#[repr(C)]` 只为稳定布局和后续互操作准备；当前 crate 没有完整导出 C ABI 函数。
- 纯 C/RT-Thread 工程若想调用 Rust，应建立单独的 FFI wrapper crate，生成 `staticlib`。指针解引用和其他 `unsafe` 只放在包装边界，核心 crate 保持安全 Rust。
- ADC/PWM/编码器/故障关断、采样同步、死区和启停状态机仍由具体项目负责。

推荐分层：

```text
板级 HAL / RTOS 驱动
        ↓
项目适配层：单位、极性、电角度、状态机、保护
        ↓
foc-algorithm：变换、控制、观测、调制
        ↓
PWM duty / 控制结果
```

## 3. 按需求快速选择

| 目标 | 建议入口 |
|---|---|
| 有感 PMSM 电流环 | `FocBasicState::update` |
| 位置-速度-电流三环 | `CascadeState::update` |
| d/q 电流 PI | 两个 `PiState::update` |
| 编码器角度平滑、速度估计 | `PllState::update` |
| 中高速无感 | `SmoPllState` 或 `BemfPllState` |
| 零速/低速无感 IPMSM | `HfInjectionState` 或 `RotatingHfState` |
| 全速域无感 | `HfBemfState` |
| BLDC 六步 | `six_step_from_sector` 加 `BemfZeroCrossState` |
| 转矩/电流优化 | `MtpaState` |
| 高速弱磁区 | `WeakeningState`、`MtpvState` |
| 高级控制研究 | `AdrcState`、`SmcState`、`MpcState` 等，必须重新整定和验证 |

## 5. 典型调用链

### 5.1 有感 FOC

```rust
let duty = foc_state.update(
    &foc_param,
    &FocBasicInput {
        ia,
        ib,
        ic,
        id_ref,
        iq_ref,
        theta_e_rad,
    },
);
// 将 duty.duty_a / duty_b / duty_c 写入定时器比较寄存器。
```

`theta_e_rad` 必须是电角度而不是机械角度：

```text
theta_e = mechanical_angle * pole_pairs + electrical_offset
```

### 5.2 中高速无感

```text
ADC/PWM换算出的 vαβ/iαβ
          ↓
SmoState/BemfState
          ↓
SmoPllState/BemfPllState
          ↓
FocBasicInput.theta_e_rad
```

反电动势在零低速不足，必须提供开环启动、有感切换或高频注入路径。

### 5.3 RT-Thread/其他 RTOS

- 在初始化阶段创建所有状态对象和任务，控制 ISR 内不分配内存。
- ISR 中完成同步采样、核心算法和 PWM 更新，或只采样/通知高优先级控制线程；选择必须由 WCET 实测决定。
- 通信、日志、参数保存和训练放在低优先级线程。
- 停机、故障恢复、控制模式切换时调用相应 `reset()`。

## 6. 选择高级算法前的限制

- `MpcState::update` 的循环次数为 `max(candidates, 2)`；库不擅自截断，产品必须限制候选数并实测 WCET。
- 神经网络只负责固定拓扑推理，不负责训练、量化、模型签名和安全认证。
- Q-learning 固定为 8 个状态、4 个动作；在线更新必须被电流、电压、速度和状态机安全包络限制。
- EKF/UKF 使用固定函数指针回调，无堆和动态派发；回调本身也必须固定时间、可重入、无阻塞。
- `HinfState`、`LqrState`、`MpcState` 等是与原 C 库一致的基础标量/小模型实现，不是通用矩阵求解框架。
- 高级控制算法通过单元测试只证明实现与参考向量一致，不证明实际电机闭环稳定。

## 7. 每次移植必须核对

1. `ts` 与真实调用周期一致，多速率控制环分别设置。
2. 电流、电压、速度、角度的单位、比例和符号一致。
3. 相序、编码器方向、电角度方向和零位正确。
4. 输出限幅、积分限幅、斜坡和复位策略符合硬件边界。
5. 目标 MCU 的软/硬浮点 ABI、`libm` 性能、最终链接 map 和栈水位通过测量。
6. 先通过单元测试，再做 SIL/HIL，最后低压限流上板；主机测试和交叉构建不能替代实机证明。
7. 硬件过流、驱动器故障、欠压、过压和过温必须有独立快速关断链。

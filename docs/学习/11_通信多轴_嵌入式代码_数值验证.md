## 一、通信层不应接管所有实时细节

通常快速电流环在驱动器本地执行，网络承载位置、速度、转矩参考和反馈。主站是否承担位置环，取决于系统架构和同步能力。即使网络周期 1 ms 很稳定，本地 ADC 与 PWM 是否同步仍是另一项工作。[S13][S28]

建议把命令表示为“值、单位、目标执行时刻、序号、有效期限、模式和约束”。收到一帧校验正确的数据，不表示这条命令足够新、来自正确状态或符合当前机械边界。迟到、重复、乱序、丢失与失联应分别定义策略。

## 二、L21：计算资源够了，总线可能先不够

示例假设每轴每 1 ms 需要一帧命令和一帧反馈，每帧按包含开销的估算长度 150 bit，经典 CAN 速率 1 Mbit/s。N 轴利用率为：

$$U=\frac{N\times2\times1000\times150}{10^6}=0.3N.$$

四轴已经 120%，在这个假设下物理上排不完，尚未加入仲裁、重发和其他消息。与此同时 MCU 预算可能只有 84% 占用。说明“CPU 够”不能推出“系统够”。

150 bit 是实验假设，并非所有标准帧固定长度或严格最坏填充值。实际计算需要具体标识符、负载、帧格式、位填充、间隔、仲裁优先级和错误模型。CAN FD 的数据段速率与载荷提升可能改善情况，但同样需要重算，不能只把“5 Mbit/s”乘进全部帧段。[S22]

## 三、CANopen/EtherCAT 名词怎样落到行为

对象字典描述参数和过程量；SDO 常用于配置访问，PDO 常用于周期/事件过程数据；CiA 402 将驱动状态、控制字/状态字和模式组织起来。CSP、CSV、CST 的不同之处在于网络周期下发的是位置、速度还是转矩参考，以及哪些调节环在驱动器或主站完成。

分布式时钟能帮助对齐设备时间，但不能自动证明应用任务、采样触发和实际功率输出同时发生。你需要从主站命令时间一直追到 PWM 生效时间。L21 仅做资源预算图，不模拟 CAN 仲裁或 EtherCAT 时钟，不是总线协议一致性测试工具。[S13][S28]

## 四、算法代码与驱动代码分离，才方便 MATLAB 对照

推荐算法核心采用显式状态与定步长输入：

```c
/* 接口示意，不是可直接替代功率驱动的完整程序。 */
void foc_step(FocState *state, const FocInput *in,
              const FocParams *params, FocOutput *out);
```

状态包括积分器、滤波器、估计角/速度和状态机；输入包括本周期测量快照与时间；输出包括占空比、诊断和允许状态。不要把硬件读写、串口等待和动态内存混进数学函数。这样同一组 CSV 可以送给 MATLAB、C 单元测试和后续 Rust 实现。

`volatile` 只约束相应编译器优化，不提供完整线程同步、原子性或缓存一致性。共享测量结构应采用双缓冲、版本计数、短临界区等适合 MCU 的机制；DMA 场景还要按芯片缓存架构处理。接口设计先保证一致快照，再追求少拷贝。

## 五、L22：定点误差来自输入、系数、乘法与输出各层

Q15 可将实数近似映射到整数 $q\approx round(x2^{15})$，但正一通常无法精确表示为有符号 16 位最大值。两个 Q15 相乘要使用足够宽的中间结果，再按定义舍入和缩放，不能先窄位溢出再做饱和。

L22 对输入与正余弦进行 Q15 量化，使用足够精确的宽中间计算，观察 dq 变换误差。**它是量化误差实验，不是目标 MCU 实际定点指令仿真，也不覆盖所有 C 整数溢出语义。**后续必须在 C/Rust 实现里明确使用宽整数、舍入方式、饱和顺序，并做位级对照。

把输入幅值从 0.9 改成 1.2，应该先定义量程与饱和，而不是期待 Q15 自动“变成更大范围”。把 d/q 两个分量同时置大，还要考虑合成矢量范围，不能只检查各自单轴。

### Q129. CAN 与 CAN FD 有哪些关键区别？

**参考回答：**经典 CAN 单帧数据载荷最多 8 字节；CAN FD 最多 64 字节，并允许数据阶段相对仲裁阶段使用更高速率，需控制器、收发器和物理网络满足要求。CAN FD 不是把经典 CAN 波特率简单调高。

工程还要考虑协议兼容、终端、线长、支线、EMI、错误处理、数据长度编码和上层负载。经典节点与 FD 帧共网的可行性不能只依据“都是 CAN 接口”。

**易错点：**以为 64 字节载荷总比多个短帧延迟小，忽略仲裁优先级、阻塞时间和数据阶段速率。[S22]

#### 新增案例：把原理放进具体情境

CAN FD 允许更长数据和数据段加速，但仲裁段仍遵循对应规则；不能把标称数据速率当作整帧所有位都在该速率发送。

#### MATLAB验证 / 工程推演任务

用 L21 假设重新区分仲裁与数据段，列消息负载与频率。基础脚本未实现完整帧编码和位填充。

### Q130. 怎样估算多电机总线负载？

**参考回答：**对每类命令/反馈列出周期、载荷、标识符格式，再计算包含协议开销、位填充、帧间隔以及必要重发裕量的占线时间。CAN FD 仲裁和数据阶段速率不同，应分段计算。

总利用率仅反映平均资源，还需分析最高优先级和低优先级报文的最坏响应时间。调试日志和参数读写不能无预算地与实时控制竞争。

**练习：**四个关节，每轴 1 kHz 下行加 1 kHz 上行，先列 8000 帧/秒，再核算每帧实际时间；不要只用 `8000 × 8 字节` 推结论。

#### 新增案例：把原理放进具体情境

每轴命令加反馈 2 帧/ms、每帧假设 150 bit，四轴在 1 Mbit/s 下需 120% 总线时间。只算 8 字节载荷会明显乐观。

#### MATLAB验证 / 工程推演任务

运行 L21，改变帧率或批量打包方案，重新计算预算；注明150bit为估算假设，不是所有帧固定长度。

### Q131. 仲裁、重发和错误怎样影响指令延迟？

**参考回答：**CAN 采用基于标识符的非破坏仲裁，低优先级报文可能等待。已经发送中的一帧一般不能被普通更高优先级帧中途抢占，因此长帧也影响阻塞时间。错误重发增加抖动，持续错误还可能导致节点进入错误被动或 bus-off。

控制程序必须把“消息最终可靠送到”和“在截止期前送到”分开设计。对于过期运动指令，迟到交付未必仍有价值。

**工程落点：**记录排队时间、发送时间、接收时间和执行时间，并对网络异常制定受限恢复，不让重连自动执行积压指令。[S22]

#### 新增案例：把原理放进具体情境

高优先级周期报文可能不断赢得仲裁，低优先级诊断报文延迟会很大；平均总线利用率低于100%也不自动满足每条消息截止期。

#### MATLAB验证 / 工程推演任务

列三种优先级报文及周期，手推一次同时到达的发送顺序；将重发与错误风暴列为独立异常测试。

### Q132. 多轴为什么需要时间戳或统一执行时刻？

**参考回答：**如果各轴收到即执行，先后到达的命令会造成相位偏差。可以让命令包含执行时刻，在各驱动器上同步时钟并提前缓存；也可在共同同步事件时采纳最新有效指令。

必须处理时钟偏差、指令迟到、序号重复、跨回绕和队列溢出。统一时间戳只有在双方时基可比较、调度可兑现时才有意义。

**易错点：**给每帧加上 MCU 自己的计数值，就宣称多个设备已同步；还要建立时钟偏移、漂移与误差边界。

#### 新增案例：把原理放进具体情境

两轴同一时刻收到命令，不代表同一时刻执行；反过来有目标时间戳的命令可提前接收并在共同时间执行。时间基准和迟到策略必须定义。

#### MATLAB验证 / 工程推演任务

画发送、到达、目标执行、PWM生效四个时刻，计算轴间偏差；L21只能提供预算，不模拟分布式时钟。

### Q133. PDO、SDO、对象字典和心跳分别做什么？

**参考回答：**CANopen 对象字典描述设备参数及其访问方式；PDO 用于时间敏感过程数据交换；SDO 用于参数读写等服务数据访问；心跳用于节点可用性与状态监督。具体映射、传输类型和周期由设备配置决定。

PDO 简洁但不是自动给每个变量提供确认；SDO 的请求响应也不适合无限挤占快速控制周期。心跳存在不代表运动命令未超时，更不证明相电流闭环正常。

**工程落点：**把网络状态、驱动运行状态、运动命令年龄和硬件保护状态分开管理。[S13]

#### 新增案例：把原理放进具体情境

把全部反馈都通过请求—应答参数访问，会造成额外事务和不确定延迟；周期过程量与低频配置应采用合适不同通道。

#### MATLAB验证 / 工程推演任务

为电流反馈、速度目标、固件版本和电机参数分别选择过程/配置路径，并说明原因；参考CiA官方定义而非自行混用术语。

### Q134. CiA 402 控制字、状态字与驱动状态机是什么关系？

**参考回答：**控制字由主站请求状态动作，状态字反映驱动器当前状态及相关标志，二者通过规定的驱动状态机和转移条件关联。典型流程涉及禁止启动、准备上电、已上电、操作使能与故障等状态。

主站不能仅写一个常量就假定驱动已经使能，必须读取状态并核对条件。设备还可能有厂商扩展和可选行为，应遵循其对象字典与实现说明。

**易错点：**把 CANopen 的 NMT 节点状态与 CiA 402 功率驱动状态当成同一个状态机。[S13]

#### 新增案例：把原理放进具体情境

控制字请求使能，不表示状态字已确认驱动可运行；驱动还有自身状态和故障准入。上位机应观察状态迁移，而不是只持续发送同一使能值。

借用 L19 的请求与实际状态区别，画主站请求和驱动确认两条线；本包不实现完整CiA402协议栈。

### Q135. CSP、CSV、CST 中主站与驱动器分别做什么？

**参考回答：**循环同步位置、速度、转矩模式分别以位置、速度、转矩目标作为同步过程数据输入。通常主站负责轨迹/协同，驱动器按模式保留相应局部闭环；CSP 常由驱动器执行位置及更内层环，CSV 主要执行速度及电流环，CST 主要执行转矩/电流控制。

具体还看插值、前馈对象、单位与厂商实现。必须确认同步周期、命令保持、迟到处理以及模式切换行为。

**追问：**在主站实现位置环时选哪种模式？取决于分层方案和延迟预算，不能只因为名称里有“位置”就选择 CSP。[S13]

#### 新增案例：把原理放进具体情境

CSP、CSV、CST下发不同参考量，位置环/速度环所在层随架构改变。越外层在网络中，越要考虑采样同步、延迟和数据年龄。

#### MATLAB验证 / 工程推演任务

分别画三个模式的主站与驱动器边界，标出电流环位置；不能只更改报文名称就声称支持同步模式。

<a id="q136"></a>
### Q136. 通信同步、控制周期同步和 PWM 同步是一回事吗？

**参考回答：**通信同步解决消息与时钟组织，控制同步解决各轴何时采样/计算/采纳目标，PWM 同步解决功率开关载波相位。三者可以协同，但没有自动等价关系。

例如 EtherCAT 的分布式时钟可作为精确事件时基，应用仍需把事件接到真实采样与控制链路。多轴 PWM 有时选择错相以降低母线纹波，而不是所有载波严格同相。

**工程落点：**分别给出时间基准、目标同步精度、可测量标记和最坏误差，不只说“用了 EtherCAT，所以同步”。[S28]

#### 新增案例：把原理放进具体情境

EtherCAT时钟同步精度高，不意味着应用线程抖动或ADC触发误差自动为零。整条时序链必须逐段闭合。

#### MATLAB验证 / 工程推演任务

把L21预算扩成时钟偏差、接收延迟、任务抖动、输出装载四栏；真实数值需测量，不能由协议名字推断。

### Q177. 写 Clarke、Park 和反 Park，并说明如何测试。

**参考回答：**使用同一套幅值和方向约定。本文两相简式为 `alpha=ia; beta=(ia+2*ib)/sqrt(3)`，只适用于零序可忽略且两相有效的条件。Park 与反 Park 互为旋转矩阵的逆。

**测试：**在 0、π/2、π、3π/2 等角度验证已知矢量；遍历多角度，做 `Park → inverse Park` 往返；验证 $\alpha^2+\beta^2\approx d^2+q^2$；再用三相对称正弦验证 dq 为常值。

**易错点：**只测试 θ=0，会漏掉 sin 项符号错误；只测试 Ia=0，会漏掉通道映射和幅值问题。代码见附录 C。[S18][S19]

#### 新增案例：把原理放进具体情境

坐标变换随机往返误差小是基础，还要验证符号、功率系数和零序条件。只有正向转换单个样例不足。

#### MATLAB验证 / 工程推演任务

运行MATLAB selftest_math并对照Python验证记录；新增θ=0、π/2与三相功率测试，明确MATLAB需在你本机实际执行。

### Q181. 写故障前后波形的环形缓冲区。

**参考回答：**推荐把“高速采样记录”和“后台读取/导出”分开设计。单生产者单消费者队列可用独立读写索引与 acquire/release 发布，但 ISR 是否允许所用原子操作，要核实目标平台是否无锁；`volatile` 不提供并发同步。

故障录波若采用循环覆盖，可让控制上下文独占数据区，触发后再记录固定数量样本，随后发布冻结快照；读者只读取冻结区，避免边覆盖边导出。若消费者也实时读取，则覆盖策略和读索引所有权必须另行设计，不能混用两种方案。

**数据建议：**每条包含采样序号、时间、Ia/Ib、Id/Iq、参考、电压、角度、母线与状态。禁止在 ISR 分配内存或把 SD 写完成作为控制继续的条件。

**测试：**绕回、满/空、触发时刚好绕回、故障后样本计数、重复触发、导出期间重新使能以及消费者滞后。

#### 新增案例：把原理放进具体情境

故障后才开始记录，会丢掉故障起因。环形缓冲要覆盖前历史、触发后窗口和冻结动作，同时不能阻塞ISR。

#### MATLAB验证 / 工程推演任务

设计容量为N的单生产者缓冲，测试绕回、触发接近末尾和读取并发；本题提供工程练习，不含已验证目标平台无锁实现。

### Q183. 写通信命令解析与超时处理。

**参考回答：**先验证长度、类型、版本、CRC、序号和参数范围，再原子提交完整的新命令快照；在校验前不得更新目标值。对网络数据不要直接 `reinterpret_cast` 为结构体，避免对齐、填充、大小端和非有限浮点输入问题。

```text
receive(frame):
    校验长度/版本/目的轴/CRC
    解码到临时结构；检查有限值、范围、模式和执行时刻
    拒绝过期、重复或超出允许时间窗的命令
    发布完整命令快照及接收时间

control_tick(now):
    读取一致快照
    若命令年龄超限：执行预定失联策略
    否则按状态机许可和变化率限制生成参考
```

**测试：**截断、错误长度、大小端、CRC、序号回绕、旧包重放、长时间失联和恢复。CRC 是差错检测，不是对抗恶意伪造的身份认证。

#### 新增案例：把原理放进具体情境

合法CRC但序号旧、长度错或模式不允许的命令仍应拒绝。命令超时应使用单调时间，不受系统时间校正影响。

#### MATLAB验证 / 工程推演任务

编写表驱动测试包含重复、乱序、边界值、失联与恢复；不要把本练习声称为完整CANopen/EtherCAT栈。

### Q184. 把浮点算法改成定点，需要处理什么？

**参考回答：**为每个物理量选择量程与 Q 格式，分析加乘和积分的中间位宽。乘法后明确右移/除法、舍入和饱和规则，避免有符号溢出等未定义行为。积分器通常需要比输入更大的动态范围。

Q15 的 -1 可精确表示而正 1 不能，`(-1)×(-1)` 必须饱和到最大正值。附录 C 用宽整数乘法、对称舍入与饱和实现 Q15 乘法，避免依赖负数右移行为。

**测试：**最大/最小值、正负乘积、半 LSB、长期积分和正常工作分布；除了最大误差，还比较闭环稳定与极限环。

#### 新增案例：把原理放进具体情境

Q15乘积通常需要至少32位中间结果，两项相加还要检查额外范围。先溢出后饱和已经丢失真实符号。

#### MATLAB验证 / 工程推演任务

运行L22看量化误差，再在C/Rust中用显式宽整数复现舍入与饱和；Python/MATLAB双精度宽乘积不等于MCU位级执行。

<a id="q185"></a>
### Q185. 怎样设计 PC 上的单元测试？

**参考回答：**把变换、PI、限幅、角度、标定、协议和状态机做成独立模块；硬件输入用可控快照替代，输出以结构体表示，不在数学函数中访问寄存器。使用固定向量、随机性质测试和日志重放组合验证。

除了典型值，还测试非法参数、NaN/Inf、计数回绕、长时间饱和、复位和多实例隔离。内存检查器可发现越界等错误，但不能证明算法稳定，也不能覆盖 MCU 的所有并发/缓存行为。

**交付物：**测试源码、固定随机种子、编译参数、PASS/FAIL、误差阈值与未覆盖项。附录 C 的主机测试是入门样例，不代替 PIL、HIL 或上板测试。[S09]

#### 新增案例：把原理放进具体情境

PC测试可覆盖数学边界和状态逻辑，却不能测实际ADC建立时间、DMA争用与门极输出。测试范围应写进报告。

#### MATLAB验证 / 工程推演任务

以坐标、PI、角度、FSM、异常输入五组建立测试清单，分别标纯数学、模拟对象和目标硬件三层验证。

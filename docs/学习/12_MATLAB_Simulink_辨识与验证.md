## 一、先用公式脚本，再搭积木模型

学习初期，MATLAB 脚本能让每个状态、导数、积分器和限幅都看得见。Simulink 适合把这些关系组织成多速率图模型，并连接更复杂的物理对象与代码生成。两者不是竞争关系：先在脚本确认坐标和单位，再在 Simulink 检查调度、接口和求解器行为。

核心 24 个 `.m` 实验按基础 MATLAB 函数编写，不调用 `tf`、`bode`、`lsim`、`pidtune`、`fmincon`、`c2d` 等专用工具箱接口。频响用复数代数，RL 用解析离散更新，PMSM 用自写 RK4。这样可以把模型本身与工具箱使用分开。当前环境没有 MATLAB，兼容目标为 R2020b 或更新版本，但并未做版本认证。

## 二、先查实验到底在求哪个方程

连续对象 $\dot x=f(x,u)$、离散控制器 $u[k]=g(x[k],z[k])$ 与控制器内部状态 $z[k+1]$ 有不同更新节奏。一个 PWM 周期内控制电压如何保持、角度在哪一时刻测量，都影响离散模型。

L11 以控制周期 50 μs、每周期两个 RK4 对象子步实现。减半对象子步但保持控制周期不变，是检查数值积分收敛；减半控制周期则改变控制系统本身，不能把两者混为同一个“精度测试”。平均值逆变器适合看控制动态，开关模型适合看纹波和采样条件，寄生电路模型才适合研究尖峰和米勒误导通。

## 三、从零生成一个 Simulink RL＋PI 模型

可选目录 `matlab/simulink` 提供 `build_rl_pi_model.m`，运行时使用 `new_system/add_block/add_line` 建立 Step→误差→PI→RL→反馈，保存到 `results_matlab/simulink/course_rl_pi.slx`，然后仿真。需要 MATLAB 与 Simulink；没有生成好的 `.slx` 冒充已执行结果。

```matlab
startup_course
check_environment
model = build_rl_pi_model();
```

这个入门模型使用**连续、未限幅 PI**，Kp≈1.2566、Ki≈628.32，对应理想 500 Hz 设计；RL 为 `1/(0.0004*s+0.2)`。它不是 L07 的离散、限幅 200/800 Hz 比较模型，因此两者波形不同并不表示错误。下一步可手动加入离散积分器、采样保持、4 V 限幅和反算，再用完全相同参数对照 L07/L08。

脚本在同名模型已打开或目标文件存在时停止，避免覆盖未保存工作。**该脚本也未在本环境原生执行**；具体版本的块路径/参数差异需在本地确认。[N03][N04]

## 四、L20：通过输入输出辨识 R 和 L

锁定 RL 精确离散模型为 $i[k+1]=a i[k]+b u[k]$。用记录构造：

$$Y=\begin{bmatrix}i[2]\\i[3]\\\vdots\end{bmatrix},\quad
\Phi=\begin{bmatrix}i[1]&u[1]\\i[2]&u[2]\\\vdots&\vdots\end{bmatrix},\quad
\hat\beta=\arg\min\|\Phi\beta-Y\|^2.$$

MATLAB 用 `Phi\Y` 求最小二乘，不要显式求逆 `(Phi'*Phi)^-1`。然后：

$$\hat R=(1-\hat a)/\hat b,\quad\hat L=-\hat R T_s/\ln\hat a.$$

检查 $0<a<1$、b>0、矩阵秩与条件数后再接受参数。持续激励不足时，即使残差很小也未必能区分参数。L20 使用正负激励并加确定性小噪声，默认参考得到 R≈0.200016 Ω、L≈0.399988 mH。

**这些很小的误差来自合成模型，并非实机辨识精度。**此外电流噪声同时出现在 Y 和 Φ 中，是带自变量误差的问题，普通最小二乘可能有偏；实际还需仪器误差、逆变器电压重构、温度和独立验证数据。[S08]

## 五、训练/辨识数据与验证数据分开

L20 图中主要展示拟合用数据和残差，适合教学，但不能充当独立泛化验证。实践时用一组激励估参，再用另一组幅值/频率/温度下的数据检验预测，记录偏差。将电阻增加而仍用旧模型，观察残差是否与电流同方向相关，有助于判断缺失的是参数还是随机噪声。

对机械惯量辨识，先明确已知的是真实轴转矩还是 iq 推算转矩。未知摩擦、负载、减速器效率都会进入估计；仅靠一条自由加速曲线同时辨识所有项通常欠缺信息。设计多个不同转矩/速度工况，而不是把软件拟合成功当作参数可信。[S08]

## 六、MIL、SIL、PIL、HIL 各回答一个不同问题

MIL 检验模型/算法闭环；SIL 检验编译后的软件行为；PIL 让目标处理器执行以检查数值和性能；HIL 用实时对象连接控制硬件，检验接口、时序和异常场景。它们不自动等价于真实高压功率级试验，也不能互相替代。要在报告中明确对象模型、实际运行代码、处理器和接口边界。[S09]

## 七、Rust 与 MATLAB/Simulink 的衔接路线

最轻的路线是先约定 CSV 输入输出：MATLAB 生成测试向量，Rust 在主机运行控制函数并输出结果，再回到 MATLAB 对比。这样不需要一开始就处理 MEX、动态库和代码生成授权。

进一步可以将 Rust 算法封装成 C ABI，在兼容工具链下使用 MEX 或 Simulink 导入接口；显式管理状态、内存、数组长度、浮点单位与错误码，不能让 Rust panic 跨越 FFI 边界。

截至本次查证，MathWorks Embedded Coder Team 发布了 **Simulink Support Package for Rust Code**，提供 Rust Importer 与 Rust Wrapper 路线，页面标注相关版本与产品依赖；它是可选的额外集成工具，**不是本实验包的运行前提，也未在此验证**。本地应以该官方页面的具体兼容性与许可证要求为准。[N02] 对 C Caller，动态状态与调用时序仍要按官方限制设计，不能认为任意有内部静态状态的函数放进去都自然获得正确 Simulink 语义。[N01]

### Q137. 怎样搭建完整电机闭环模型？

**参考回答：**至少包含供电与母线、逆变器、电机电磁模型、机械负载、传感/量化/延迟、控制器和保护。先写出模型边界与假设，再使用电机参数建立可重复的测试工况。

建议先用简单模型验证控制符号和单位，再逐步增加非理想因素。模型输出应包括相电流、dq、电压、角度、转矩、速度及能量量，避免只看一条转速曲线。

**追问：**怎样判断仿真不是“自己证明自己”？用独立测量参数和未参与调参的工况进行交叉验证。[S08]

#### 新增案例：把原理放进具体情境

平均值FOC必须包含电压实现、电流、转矩与机械反馈。只给一个一阶“速度响应”对象无法用来验证dq解耦与电角度错误。

#### MATLAB验证 / 工程推演任务

逐段审阅L11，确认真实对象状态与控制器测量的隔离，画出未包含的开关和传感器模型。

### Q138. 平均值逆变器与开关模型各验证什么？

**参考回答：**平均值模型用周期平均电压表达调制，适合控制结构、较低频动态、轨迹和参数扫描；开关模型显式表示开关动作，更适合电流纹波、采样窗口、死区等研究，但计算步长和运行成本更高。

再精细的开关模型也未必包含布局寄生、器件实际温度和所有 EMI 路径。根据要验证的问题选择模型保真度，不是模型越复杂就一定越正确。

**工程落点：**先说明“本次模型能验证什么、不能验证什么”，再引用仿真结果。[S08]

#### 新增案例：把原理放进具体情境

研究速度阶跃时平均值模型通常更高效；研究采样毛刺或电流纹波时，平均电压会把关键现象抹掉。模型复杂度应由待回答问题决定。

#### MATLAB验证 / 工程推演任务

把L06、L09、L11的输入、输出、状态和省略项列成对照表，禁止用其中一个模型为所有问题下结论。

### Q139. 连续模型和离散控制器怎样匹配时间设置？

**参考回答：**控制器以明确采样周期执行，连续电机模型由求解器积分，之间通过采样和保持连接。固定步长要能正确表达控制/PWM 事件关系；多速率模型需处理速率转换和数据一致性。

仿真求解器步长不是 MCU 的真实控制周期，也不是自动包含运算延迟。代码生成通常要求离散、确定的任务设置和可实现的数据类型。

**易错点：**把仿真自动变步长取得的稳定结果，直接当成固定周期 MCU 实时稳定性的证明。[S05][S09]

#### 新增案例：把原理放进具体情境

把RK4子步从25μs减到12.5μs，控制周期仍50μs，是积分精度测试；把控制周期也改成25μs，则控制系统本身改变。

#### MATLAB验证 / 工程推演任务

做两组独立修改并比较结果，记录KiTs及速度环分频是否随控制周期正确更新。

### Q140. 为什么仿真稳定，上板却振荡？

**参考回答：**检查模型是否遗漏采样/执行延迟、角度延迟、PWM 更新、限压、量化、噪声、死区、传感器极性、饱和、实际负载和参数温漂。还要核对单位与标幺转换是否与代码一致。

排查顺序应从硬件测量与时间链路开始，不要一上来改高级算法。先让模型复现已观察到的异常，再讨论参数修改，才能建立可解释的闭环。

**工程落点：**用上板日志离线重放控制器，比较同输入下模型与代码输出，区分算法误差和外设/时序误差。

#### 新增案例：把原理放进具体情境

仿真理想角度无延迟、母线固定、电流无偏置，实机则可能同时存在这些非理想，因而原参数失稳不意味着理论全部错误。

#### MATLAB验证 / 工程推演任务

从L11逐项加入一种非理想，建立影响矩阵；先找最敏感项，而不是立即更换算法名字。

<a id="q141"></a>
### Q141. 怎样加入死区、延迟、噪声、量化和限幅？

**参考回答：**死区需与电流方向和开关策略相关；延迟可分别放在采样、角度、计算和执行路径；量化按真实 ADC/编码器分辨率实现；噪声既考虑随机成分，也考虑开关相关误差；限压随母线变化，并加入抗饱和。

不要只在理想电流上添加白噪声就认为模拟了全部硬件。开关毛刺、削顶和采样盲区是结构性误差，模型形式不同。

**追问：**怎样做鲁棒性实验？给参数、延迟和测量误差设合理范围，组合扫描并报告失败边界，不只展示成功样本。

#### 新增案例：把原理放进具体情境

死区误差、ADC噪声、量化和电压圆限幅作用于不同链路位置，放错注入位置会模拟不同物理问题。

#### MATLAB验证 / 工程推演任务

在L11信号链旁标出每一种应注入的位置，再分别链接L08/L09/L10的局部实验。

<a id="q142"></a>
### Q142. MIL、SIL、PIL、HIL 分别验证什么？

**参考回答：**MIL 在模型层验证算法；SIL 在主机运行生成或实现代码，与模型比较；PIL 在目标处理器运行代码，检查数值与执行性能；HIL 用实时仿真对象与真实控制硬件交互，测试控制器 I/O、实时性与故障反应。

名称的具体组织可因工具变化，但验证边界要清楚。HIL 的被控对象仍是模型，不能替代真实功率级、热、电磁兼容和机械可靠性试验。

**易错点：**把“程序能在仿真器运行”称为已经完成 HIL；必须说明哪部分真实、哪部分模拟、接口如何闭环。[S09]

#### 新增案例：把原理放进具体情境

在PC运行生成代码可以验证部分数值行为，但不能测目标MCU的中断抖动；HIL也不自动覆盖真实MOSFET热失效。

#### MATLAB验证 / 工程推演任务

给每项测试标MIL/SIL/PIL/HIL/实机层级，并写“能证明/不能证明”，避免将一个PASS推广到整个驱动系统。

<a id="q143"></a>
### Q143. 自动生成代码怎样与手写驱动/通信结合？

**参考回答：**把算法核心与硬件抽象分开，明确输入、输出、状态、初始化/复位和调用周期；手写或厂商驱动负责采样、PWM、通信、保护与板级管理。避免模型和手写代码同时写同一状态或寄存器。

代码生成时需要审查数据类型、资源、静态/动态分配、重入性、错误处理和调用图，并保存生成配置以便复现。

**工程落点：**可以生成算法而保留独立安全监督，但算法函数的 `Enable=false` 是否真的关闭硬件必须单独验证，不可想当然。[S09][S20]

#### 新增案例：把原理放进具体情境

自动生成的控制函数还要由定时器ADC链按正确周期调用，外围驱动与保护不能因为代码生成而省略。模型采样时间与调用周期不一致会改变积分和滤波。

#### MATLAB验证 / 工程推演任务

用可选Simulink脚本生成入门模型，先理解连续版本；再列真实部署时需要手动对接的时钟、驱动、状态与数据接口。

### Q144. 怎样证明代码与模型一致并满足实时性？

**参考回答：**构造代表性输入和边界序列，比较关键内部状态及输出误差；对固定点/单精度定义容差，而不是要求所有浮点逐位相同。再测目标平台执行时间、栈、RAM、Flash 与任务截止期。

对保护、模式切换、参数更新和复位也做一致性测试。代码与模型一致只能证明转换/实现层面符合预期，不能证明原模型满足现实需求。

**交付物：**模型版本、代码版本、编译配置、测试向量、误差统计、执行时间和未覆盖项。[S09]

#### 新增案例：把原理放进具体情境

模型与代码都画出类似波形不足以证明一致，应输入相同数据、同一初值和同一时序，再比较逐样本误差和边界行为。

<a id="q145"></a>
### Q145. 怎样辨识电阻、电感、磁链和极对数？

**参考回答：**电阻可在已知稳态电流和电压下估计，注意逆变器压降与线量换算；电感可由受控激励下的电流动态辨识，需考虑转子位置；磁链可通过已知速度下的反电动势或模型辨识；极对数可由机械一圈对应电周期计数得到。

测试必须限定电压、电流、时间和机械运动范围。不同方法在低速、高速、锁轴和带载时的适用性不同，不应把工具输出当作无需核对的真值。

**工程落点：**至少用另一方法或独立工况复核关键参数。[S08]

#### 新增案例：把原理放进具体情境

一次电压阶跃可帮助辨识RL，但真实转子移动会引入反电动势。磁链、惯量和极对数又需要不同激励与前提，不能套同一个拟合器。

#### MATLAB验证 / 工程推演任务

用L20理解锁定RL辨识，再写各参数对应的可测量量、激励和安全边界；标明哪些参数未在脚本中辨识。

<a id="q146"></a>
### Q146. 为什么电感随转子位置与电流变化？怎样测 Ld/Lq？

**参考回答：**转子凸极性使不同磁轴的磁路磁阻不同；电流增大导致磁饱和，磁链—电流斜率变化。若存在交叉饱和，d 轴响应还会受 q 轴偏置影响。

可先对齐或识别转子磁轴，再沿 d/q 方向施加受控小信号/脉冲，在指定偏置电流和频率下辨识。结果应注明增量还是割线电感、温度和工作点。

**易错点：**用转子任意位置的单次 LCR 读数，直接宣称测出了两个独立轴的完整电感。[S08]

#### 新增案例：把原理放进具体情境

同一相电感随转子位置、偏置电流变化，区分Ld/Lq需要受控对齐和合适激励；LCR小信号值不等于大电流动态增量电感。

#### MATLAB验证 / 工程推演任务

建立角度×电流的采样表，先在常参数模型验证处理程序，再考虑真实测量；本包未提供真实电感地图。

<a id="q147"></a>
### Q147. 怎么辨识惯量和摩擦？负载未知怎么办？

**参考回答：**可用机械方程 $J\dot\omega=T_e-T_L-B\omega-\tau_f$ 建立辨识模型。在已知或可估计电磁转矩下，通过加减速、稳态和双向实验区分惯量与摩擦；需要关注速度微分噪声。

负载未知且变化时，惯量与负载转矩可能难以唯一分离，要增加工况、额外传感或先验约束，并报告不确定性。不要把所有残差都塞进一个“摩擦系数”。

**追问：**为什么空载惯量参数上机后不好用？安装后的负载、耦合弹性和传动摩擦改变了被控对象。[S08]

#### 新增案例：把原理放进具体情境

已知电磁转矩并不意味着已知净加速转矩，摩擦与外负载会改变惯量拟合。仅用一次自由加速同时拟合所有参数可能不唯一。

#### MATLAB验证 / 工程推演任务

设计正反转、不同转矩和不同速度的实验，先分析可辨识性，再写最小二乘；不要把软件返回数值当作物理可信。

<a id="q148"></a>
### Q148. 怎样测电流环、速度环的阶跃和频率响应？

**参考回答：**电流环应尽量避免机械外环干预，选择安全电流与转速工作点；速度环测试时内环应已验证。小幅阶跃/扫频用于线性分析，大幅变化用于测试限流、限压和恢复。

测量应保留指令、反馈、实际执行量与限幅标志，确认测试没有长期饱和，否则不能按线性模型解释带宽。扫频范围和激励应避开可能损伤机构的条件。

**工程落点：**报告幅值、频率、采样、滤波、供电、负载和温度，保证别人能重做实验。[S02]

#### 新增案例：把原理放进具体情境

电流环阶跃看电流与电压，速度环阶跃还受惯量和限流，机械扫频则可能激励共振。相同测试形式对应的激励边界不同。

#### MATLAB验证 / 工程推演任务

分别用L07、L11、L16写指标定义，区分参考响应与扰动响应；真实扫频必须先限定能量和机械条件。

<a id="q149"></a>
### Q149. 转矩脉动、速度波动、谐波和效率怎么测？

**参考回答：**转矩脉动需合适带宽的转矩测量或明确的估计方法，速度波动要考虑编码器量化；电流谐波需要足够采样率、同步长度和合理频谱处理；效率则需一致功率边界和校准仪器。

简单时均 $V$ 乘时均 $I$ 不总等于真实输入功率，尤其存在纹波时应考虑 $\langle v(t)i(t)\rangle$。输出机械功率需转矩与速度对应同一时间/边界。

**易错点：**以软件 Iq 乘 Kt 作为独立转矩测量，再用它证明同一个 Kt 模型非常准确。

#### 新增案例：把原理放进具体情境

效率需要同一时间边界的输入与输出功率，速度接近零时很小的输出功率可能让比值对误差极敏感。转矩脉动也要说明归一化方式。

#### MATLAB验证 / 工程推演任务

用L03核对相对峰峰纹波定义，再用L05功率平衡；不能把理想损耗缺省当作真实100%效率。

<a id="q150"></a>
### Q150. 为什么不能只凭母线或空载电流评估控制？

**参考回答：**母线平均电流反映电功率的一部分，不能直接描述相电流纹波和磁化电流。空载通常转矩需求小，不能检验满载电流能力、转矩线性、热和电压边界。

更小的空载电流可能来自更好控制，也可能因为实际速度、母线、负载或角度策略不同。比较需同工况，并结合温升、相电流、转矩、跟随误差和稳定裕量。

**追问：**哪几个图最值得同时看？相电流、Id/Iq、Vd/Vq/限幅、角度/速度、母线以及故障时序。

#### 新增案例：把原理放进具体情境

空载母线电流小，只说明该工况输入功率小；低速大转矩时相电流可很大，高速铁耗又可能上升。单点数据无法代表全包络。

#### MATLAB验证 / 工程推演任务

根据Pdc与dq功率关系构造低速大电流、高速小电流两点，说明各自功率和器件应力不同。

<a id="q151"></a>
### Q151. 示波器、电流探头、功率分析仪和测功机各测什么？

**参考回答：**示波器用于瞬态、时序和开关波形；电流探头提供相电流波形但需校零并注意带宽/饱和；功率分析仪用于准确功率与效率；测功机提供可控机械负载和转矩/速度测量。

测高侧 VGS、开关节点或浮动电压，应使用满足差模、共模和安全额定值的差分/隔离方案。不能把普通接地探头地夹随意接到相端，也不能以断开示波器保护地作为替代办法。

**工程落点：**记录探头型号、量程、带宽、校准和连接方法；测量链本身也是误差和风险来源。

#### 新增案例：把原理放进具体情境

示波器适合时序和瞬态，功率分析仪测能量效率，测功机提供轴侧负载与转矩。电源显示平均电流不能替代高速相电流探头。

#### MATLAB验证 / 工程推演任务

为L11、L18、L24对应的真实验证分别选择仪器和测量边界，记录带宽、采样同步与校准要求。

<a id="q152"></a>
### Q152. 怎样制定完整验证计划？

**参考回答：**按需求建立矩阵：电源上下限、速度/转矩包络、环境温度、冷/热机、不同电机批次、连续与重复负载、通信负荷、传感异常和复位恢复。每项给出激励、合格阈值、保护条件和证据文件。

故障注入优先从仿真、HIL 和低能量台架开始，不能直接短接大功率母线来“验证保护”。长期测试还应监控温漂、错误计数和资源泄漏。

**交付物：**需求—测试追踪表、原始数据、统计结果、失败记录和未覆盖边界；附录 D 提供可复制模板。[S09]

#### 新增案例：把原理放进具体情境

冷机空载通过后还要验证温度、母线、负载、初始角度、参数分散和故障恢复。测试矩阵比一条漂亮曲线更能界定能力。

#### MATLAB验证 / 工程推演任务

使用模板建立正常/边界/异常三类工况，并明确每项当前是仿真、计划还是实测，不填不存在的通过记录。

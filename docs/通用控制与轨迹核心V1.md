# FluxRT 通用控制与轨迹核心 V1

## 1. 当前结论

P4.2 已拆成多个可独立验收的软件门。当前已完成 **P4.2A 参考规划核心**、
**P4.2B 级联控制核心**、**P4.2C 配置/ABI/默认关闭目标接线**和 **P4.2D 双仿真软件门**：

- `Torque / Velocity / Position` 使用既有产品契约枚举和 SI 单位；
- `Passthrough / TorqueRamp / VelocityRamp / PositionFilter /
  TrapezoidalTrajectory / ExternalSynchronized` 由同一固定容量状态机处理；
- 产品硬限制始终存在，命令只能进一步收紧电流、转矩和速度限制；
- 位置目标经过多圈软限位，第一次使能或模式/InputMode切换先输出预置拍；
- 非法配置、非法命令和缺失反馈均为事务式拒绝，不推进ramp/trajectory状态；
- `Position P -> Velocity PI -> Torque -> Iq`在独立纯Rust模块中完成，转矩常数由配置传入；
- 转矩前馈占用PI输出余量，最终转矩限制和电流换算限制不能被前馈绕过；
- PI饱和使用既有反算anti-windup，transition拍用实测Iq预置输出，模式变化没有transition
  标志则fail-closed；
- `ConfigBundle -> MotionRuntimeConfig`是唯一配置映射，控制周期、电流/速度/软限位、
  基础SPMSM转矩常数和规划参数都从批准配置派生；
- 配置schema V2兼容读取V0/V1，旧记录迁移后motion必为关闭，不会升级后自动使能；
- 独立motion ABI把配置、enable/disable与逐拍step分开；planner+cascade只在两者都成功时
  整体提交，任何失败都返回`Id/Iq=0`安全输出；
- `motion-control` Cargo feature和`FOC_MOTION_CONTROL_CANDIDATE`均默认关闭；默认四档
  目标镜像没有motion符号，既有实时V20/V19 ABI和ISR调用路径未改变。
- Rust PC直接调用产品`MotionReferencePlanner + MotionCascadeController`，MATLAB独立实现
  同一状态机；共享8类SI场景，但两端不读取彼此结果；
- Python比较器冻结23列trace，逐字段核对D0～D4、feature-off、transition、限制与反馈故障；
  8类场景、192行对拍、15个连续通道零差异，修复后全回归通过。

当前仍**没有**把motion输出接入既有电流环/ADC ISR，没有RT-Thread服务或实机入口，也没有
把仿真候选环路增益批准为当前电机正式参数。P4.2D的S3只证明两套软件engine对共同契约
一致，不能写成目标闭环运动控制已经可用。

## 2. 架构位置

```text
ProductCommand（P1.1）
        │ 已由命令仲裁选择
        v
MotionReferencePlanner（P4.2A，本阶段）
  InputMode + hard/command limits + soft position limits
        │ MotionReference，全部SI单位
        v
MotionCascadeController（P4.2B，已完成纯核心）
  Position P -> Velocity PI -> Torque/Iq -> Current Loop
        │
        v
配置/ABI/目标默认关闭接线（P4.2C，已完成软件门）
        │
        v
双仿真（P4.2D，S3已完成）/ 无功率owner（P4.2E0，已完成）
        │
        v
combined realtime与WCET（P4.2E1）/ 分模式实机（P4.2E2）
```

参考规划属于 `foc-control`，因为它包含模式切换和有状态输入处理。纯公式仍可调用
`foc-algorithm`，但RT-Thread、协议、HAL、寄存器和Flash都不得进入该模块。

## 3. P4.2A 输入与输出

实现文件为 `rust/crates/foc-control/src/motion.rs`。

### 3.1 输入

- `MotionPlannerConfig`：控制周期、产品硬电流/转矩/速度限制、ramp速率、位置滤波带宽、
  梯形轨迹加减速度和多圈软限位；
- `ProductCommand`：沿用P1.1冻结的104 B产品命令，不复制枚举或单位；
- `MotionFeedback`：只提供机械多圈位置、机械速度及各自有效位，用于切换预置。

P4.2C已把启用位、转矩/速度ramp、位置滤波带宽、轨迹加速度/减速度加入`AxisConfig`。
关闭配置要求这五个值全为零；启用配置要求全部为有限正数，并要求有效的位置P和速度PI。
这是一组可迁移字段，不是当前电机的正式调参值。

### 3.2 输出

`MotionReference` 分离：

- 规划后位置、速度、转矩参考；
- 速度和转矩前馈；
- 实际生效的电流、转矩、速度限制；
- 当前 `ControlMode / InputMode`；
- transition、转矩/速度限幅、正/负软限位标志。

前馈保持独立，便于遥测区分来源。P4.2B已在PI/P输出与前馈相加后再次执行最终限制；
P4.2A的参考限制仍不能单独替下游控制器承诺最终输出已经受限。

### 3.3 P4.2B级联

实现文件为`rust/crates/foc-control/src/motion_cascade.rs`。`MotionCascadeConfig`只接收
控制周期、位置P、速度PI和`torque_constant_nm_per_a`，不保存板卡类型或临时电机数值。
`MotionCascadeFeedback`提供机械位置、机械速度和实际q轴电流及有效位；
`MotionCascadeOutput`输出位置/速度误差、最终转矩、`Id=0/Iq`命令和两组独立标志。

三种模式的数据流为：

| 模式 | 计算路径 |
|---|---|
| Torque | 规划转矩 → 有效转矩/电流双限幅 → `Iq = torque / Kt` |
| Velocity | 速度误差 → Velocity PI + torque feed-forward → 最终限幅 → Iq |
| Position | Position P + 规划速度 + velocity feed-forward → 速度限幅 → Velocity PI + torque feed-forward → 最终限幅 → Iq |

`Kt`是以后由Motor配置映射得到的机械转矩常数，不在核心中按当前电机写死；`Id=0`是本阶段
表贴PMSM基础路径，后续MTPA/弱磁在明确的下游层修改d/q分配，不侵入轨迹规划器。

### 3.4 P4.2C配置映射与ABI

`motion_config.rs`执行唯一映射：

```text
dt = 1 / Board.control_frequency_hz
Imax = min(Motor.continuous_current_a, Inverter.maximum_phase_current_a)
Kt = 1.5 * pole_pairs * flux_linkage_v_s
Tmax = Kt * Imax
```

该`Kt`只适用于当前基础SPMSM路径；凸极转矩、MTPA和弱磁必须在后续电机模型中显式扩展，
不能悄悄改动这里的含义。`foc_motion_bridge.h`冻结独立V1子ABI：管理面配置/使能与实时
`step`分离，输入继续复用104 B `foc_product_command_t`，输出为64 B定宽结构。C适配器只在
安全的Disabled、功率输出关闭、无活动故障guard下允许换配置或使能；初始化后始终保持关闭。

### 3.5 P4.2D双仿真代码结构

P4.2D按三个互不覆盖的写入区并行实现：

| 层 | 实现 | 边界 |
|---|---|---|
| Rust PC | `foc-sim/src/motion_contract.rs`与`foc-motion-contract-check` | 直接调用产品planner/cascade；失败拍联合回滚，不复制控制律 |
| MATLAB | `simulink/run_motion_control_contract.m` | 独立实现`f32`顺序、ramp/filter/trajectory、PI/限幅/回滚；不读取Rust结果 |
| 契约/比较 | `motion_control_matrix_v1.json`、Python比较器、PowerShell入口 | 8类场景、23列trace、独立engine身份和motion专属容差 |

8类场景为`feature_off / torque_ramp / velocity_ramp / position_filter /
trapezoidal_trajectory / mode_switch / command_limit / invalid_feedback`。场景内的P/PI、ramp和
轨迹参数标识为仿真候选，只用于确定两端算法语义，不能写回approved配置。

最终一键门输出Rust、MATLAB和跨端比较三组PASS，共192行；`ok/planner_disabled/
planner_missing_position`分别为173/16/3行。15个连续通道零差异，离散状态和flags精确一致。
详见[P4.2D motion双仿真验证](performance/2026-09-30-P4.2D-motion双仿真验证.md)。

## 4. InputMode 语义

| ControlMode | InputMode | P4.2A行为 |
|---|---|---|
| Torque | Passthrough | 直接接受转矩目标，受有效转矩限制 |
| Torque | TorqueRamp | 按`N*m/s`对转矩目标限速 |
| Torque | ExternalSynchronized | 接受已经外部同步的目标，仍执行本地硬限制 |
| Velocity | Passthrough | 直接接受机械角速度目标 |
| Velocity | VelocityRamp | 从切换时实测速度按`rad/s^2`推进 |
| Velocity | ExternalSynchronized | 接受外部同步目标，仍执行本地硬限制 |
| Position | Passthrough | 位置目标只做多圈软限位 |
| Position | PositionFilter | 一阶离散滤波，并用有效速度限制约束每拍位移 |
| Position | TrapezoidalTrajectory | 按最大速度、加速度和减速度生成无超调参考 |
| Position | ExternalSynchronized | 接受外部同步位置/前馈，仍执行本地限制 |

其它组合继续由 `ProductCommand::validate()` fail-closed。Voltage/Duty/Current 不会被
偷偷映射为某个运动模式。

## 5. 限制顺序

```text
产品硬限制（配置）
        ∩
命令临时限制（只能更小）
        ↓
InputMode参考规划
        ↓
位置软限位 / 参考与前馈组合限位
        ↓
P4.2B级联控制器最终转矩/电流限位（已实现）
        ↓
既有C侧输出验证与硬件保护
```

命令未携带limit flag时使用产品硬限制；携带flag时取两者较小值。协议或上位机以后可以
请求更保守的限制，但不能通过一个命令放宽设备配置的硬边界。

## 6. 切换与失败语义

`MotionReferencePlanner::default()`为关闭状态，必须显式`set_enabled(true)`。使能会清除
旧状态。首次有效命令或Control/InputMode变化时：

1. 位置和速度状态从有效机械反馈预置；
2. 既有转矩参考被钳入新限制；
3. 输出带`TRANSITION`标志；
4. 当拍不追赶远端目标，P4.2B用实测`Iq * Kt`预置Velocity PI输出；
5. 下一拍才按所选InputMode正常推进。

所有检查在状态提交前完成。错误返回时规划器整体不变，避免坏包让轨迹偷偷前进一步。
位置模式要求位置和速度均有效；速度模式要求速度有效；任何声明有效但非有限的反馈都拒绝。

级联控制器还会独立检查状态变化：首次使用、ControlMode或InputMode改变时若缺少
`TRANSITION`标志则拒绝；transition拍若没有有效实测Iq也拒绝。预置输出仍受新限制约束，
因此“无扰”只承诺在新边界允许范围内保持已施加转矩，不会为了连续性越过安全上限。

## 7. 默认关闭与目标镜像

`foc-control`定义：

```toml
[features]
default = []
motion-control = []
```

`motion`、`motion_cascade`和`motion_config`只在`cfg(test)`或显式`motion-control` feature下
编译；motion ABI也由bridge同名feature控制。Kconfig候选仅在Diagnostic把feature传给Cargo，
Production即使遗留开关也只编译无Rust引用的关闭桩。默认`.config`关闭候选，map中无motion
符号。配置schema/管理ABI升级会改变BIN哈希，但默认四档ROM/RAM尺寸保持不变，且实时ISR
没有新增调用或WCET负担。

## 9. 本阶段证据边界

P4.2A～C达到S1（Rust单元/全量Host）和S2（四档默认关闭与临时Diagnostic候选交叉构建）。
P4.2D达到S3：Rust/MATLAB独立engine对8类场景和192行trace严格一致，15个连续通道在
当前输出精度下最大绝对差均为0；修复后全量回归与默认关闭四档构建/map通过。既有测试覆盖
schema V0/V1迁移默认关闭、配置事务分类、SI映射、ABI
默认关闭、guard、失败安全输出，以及“planner成功但cascade失败”时的整体回滚。既有闭环仿真
仍验证旧速度路径。

P4.2E0又完成默认关闭、单执行上下文的应用层motion owner：错误owner/source/sequence不会推进
core，命令过期、timeout、motion error和外部fault全部fail-closed，disable不能清除Failed锁，
恢复必须通过安全guard。全量Host现为25/25，默认四档哈希与P4.2D相同；临时Diagnostic
candidate-on只证明交叉编译通过。owner与adapter没有真实消费者并被GC，motion仍未接ISR，
故当前没有板端WCET，也不能证明真实电机控制质量。完整设计与证据见
[P4.2E0 motion owner与无功率生命周期](performance/2026-09-30-P4.2E0-motion-owner与无功率生命周期.md)。

目标接线不得让管理线程和ADC ISR同时修改同一个management/adapter。P4.2E1必须让ISR独占
realtime context，管理线程只发布固定快照/原子请求；motion正确接点位于Rust内部反馈更新后、
电流参考选择前，并与current PI形成一次combined realtime事务。C侧先调motion ABI再调旧
realtime ABI会丢失当拍反馈、形成双FFI和数据竞争，因此不是允许的实现路线。

P4.2E1结构现已按上述边界落位：双槽dispatcher只在屏蔽ADC IRQ的短临界区提交索引，Break
保持可抢占；combined一次完成motion与旧快环并保留C侧`fault_epoch`/commit门。route无命令
不再回退旧速度环，配置必须用同一bundle revision和与基础FOC精确一致的频率/电机/PI参数。
P4.2E1B现已加入真实Diagnostic活调用者：`foc_motion_probe.*`持续检查输出关闭与fault epoch，
mode 0/1经过相同ADC ISR/dispatcher/platform路径，六个注入点覆盖configure、combined和commit。
最终candidate `s` ROM 130340 B、RAM 20664 B，剩余732 B Flash；板端mode 0/1各完成
1200/1200次且均为0 miss，完整ISR最坏分别为11275/12157 cycles，独立最坏值差为882 cycles，
mode 1距12750-cycle阶段门尚余593 cycles（4.65%）。六个one-shot注入均进入fault并保持duty 0，
未再出现HardFault。测试后已恢复默认Diagnostic（110660 B/22472 B），map中无candidate符号，
板端保持disabled、fault 0、duty 0和物理Vbus 0。该证据关闭无功率S4执行门，但不证明powered
控制质量；该结果只作为P4.2E2分模式计划、双仿真和独立受限实机门的前置。详见
[P4.2E1单写者dispatcher与combined realtime](performance/2026-09-30-P4.2E1-单写者dispatcher与combined-realtime.md)
和[P4.2E1B无功率motion目标执行门](performance/2026-09-30-P4.2E1B-无功率motion目标执行门.md)。

P4.2E2现已把双仿真从固定反馈数学对拍扩展到动态机械plant。Torque采用0.002 N·m、100 ms
硬时限；Velocity采用5 rad/s、500 ms；Position采用0.2 rad、2 s。Rust直接复用产品
planner/cascade，MATLAB保留独立公式，Python同时检查identity、31,392行23列trace和三种
模式的峰值/末端/超调门。三者全部PASS，默认目标BIN哈希未变化。模型只包含一阶Iq响应、
惯量、粘滞摩擦和负载，不包含逆变器、ADC、真实电流环、观察器或传感器；Torque下一步只能
进入独立S5检查表评审，Velocity后置，Position继续等待P4.1D。详见
[P4.2E2逐模式低功率双仿真门](performance/2026-10-01-P4.2E2-逐模式低功率双仿真门.md)。

Torque随后进入目标S4：`foc_motion_torque_trial.*`固定0.002 N·m、0.08 A和1,200拍，平台只允许
该状态机内部arm，普通`foc_start`固定拒绝；传感器less启动仍使用CM4.4的2 s对齐、5 s升速、
582 rpm和0.8 A上限，只有ClosedLoop后才计Torque有效tick。第1,200拍提交后同ADC ISR关闭
Gate/MOE/CCER。candidate专用能力档把通用调参、trace、相电压采集和数学诊断裁掉，ROM/RAM为
124,100/14,184 B；真实板端无功率mode 1为12,233/12,750 cycles、0 miss，六点注入均
fail-closed。源码已恢复candidate默认关闭，板上暂留安全停机的候选等待一次powered S5。
详见[Torque候选S4无功率门](performance/2026-10-01-P4.2E2-Torque候选S4无功率门.md)。

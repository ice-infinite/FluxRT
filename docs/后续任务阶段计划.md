# FluxRT 后续任务阶段计划

## 1. 文档用途

本文是 FluxRT 从既有基线到后续产品化的统一执行清单，用来直接回答：以前完成了什么、
证据在哪里、下一步是什么、前置条件是什么、是否需要转电机、怎样才算完成。后续每完成一个阶段，都必须同时更新本文状态和
[工程操作日志](工程操作日志.md)。

三个编号体系含义不同：

- 本文 `A0～A28`：按实际整改时间连续排列的**执行批次**；
- [整改架构与职责分配](整改架构与职责分配.md)中的 `A0～A9`：长期**架构工作包**；
- [ST与VESC工程改进路线图](ST与VESC工程改进路线图.md)中的“阶段 0～8”：长期
  **技术方向**。

执行批次可以同时覆盖多个架构工作包，但不能改变各层职责。本文是进度入口，技术原理
仍以整改路线、架构分配和对应性能报告为准。

## 3. A0 之前的工程基础

进入性能整改编号前，工程已经完成以下基础工作：

- 建立 NUCLEO-G431RB + X-NUCLEO-IHM16M1 的 RT-Thread 工程，使用 24 MHz HSE、
  32.768 kHz LSE 和 170 MHz 系统时钟；

这些工作是后续 A0～A28 的前置基线，不代表闭环、观察器、参数或产品化已经完成。详细
过程可从[工程操作日志](工程操作日志.md)的 `LOG-20260923-001～003`、
[C与Rust混合架构](C与Rust混合架构.md)、[MATLAB联合仿真](MATLAB联合仿真.md)和

## 5. A18：Calibration 构建档与数据契约

状态：**已完成（S1/S2；未烧录）**。结果和三档哈希见
[A18 专项报告](performance/2026-09-24-A18-Calibration构建档与标定契约.md)。

### 目标

建立 `Diagnostic / Calibration / Production` 三档，后续辨识和高频缓冲放入 Calibration，
避免继续把 Diagnostic 塞到 128 KiB Flash 极限。三档必须共用相同的关断、过流、deadline、
输出复核和默认不启动规则。

### 实际落点

- `build.ps1`、`custom.cmake`：新增并隔离构建目录；
- `foc/include/foc_build_profile.h`：集中校验三选一主宏并派生能力；共享 Kconfig 继续只管
  硬件/算法选项，避免三档通过同一 `.config` 串档；
- `applications/`：Calibration 只提供停机标定命令，不恢复任意运行期调参；
- `foc/platform/stm32g431/`：只编入所需 ADC/固定窗能力；
- `profiles/calibration/`：规划保存板卡标定记录、版本、温度和证据哈希。

### 完成门

1. 三个构建目录不能互用 CMake cache 或 Rust 静态库；
2. 三档均通过 Host、Rust、交叉构建和 size/map；
3. Calibration 上电仍保持输出关闭，必须显式进入标定状态；
4. Production 继续不包含 4 KiB 固定窗和标定 Shell；
5. 记录三档 BIN 哈希、ROM/RAM 和功能矩阵；
6. 不烧录、不运行电机即可完成本阶段。

以上六项均已满足。Calibration 的目标板停机确认和真实多点数据属于 A19，不回填为 A18
证据。

## 7. A20：动态相序与采样窗

### 前置条件

A19 标定通过；用户再次确认低功率运行条件；电机空载可自由旋转；电流限制、软件 trip、
急停命令和脚本 `finally` 停机有效。

### 工作内容与完成门

- 先开环、低速、短时，不直接闭环；
- 同步记录 U/V/W、电流、PWM、母线、ADC 触发和控制拍；
- 验证 U/V/W 相序与正反转符号；
- 确认开关边沿污染、钳位、满量程和可用采样窗；
- 比较实测相电压、`duty × Vbus`、死区模型和三相重构；
- 多次重复后结果一致，且每次最终安全停机。

示波器是该阶段的正式验收工具。没有示波器时可采软件数据做预筛查，但不能确认开关边沿
和 ADC 触发位置。

## 8. A21：实时性重新验收

Diagnostic/Calibration 的 ADC1 从一 rank 增加到四 rank 后，电流采样时刻虽未改变，JEOS
和 ISR 入口会延后。本阶段重新测：

- ADC 触发到 ISR、ADC 触发到 CCR 生效的实际延迟；
- 同一拍 `total/pre/control/post` 和独立段峰值；
- trace 关闭/开启、采集关闭/开启下的平均值和 WCET；
- 丢采样、deadline miss、CORDIC 回退和控制错误；
- 12 kHz 周期内的安全余量。

若余量不足，先评估采样时间、DMA/双缓冲、ISR 数据搬运和诊断裁剪；不能直接降低保护或
删除超时检查来换时间。

## 9. A22：质量判定与安全回退

平台层为每拍相电压生成状态：未配置、未标定、有效、过期、开路嫌疑、低端/高端饱和、
三相不一致。控制层只接收已经换算的物理量和有效位。

完成门包括：

- Host 注入每类坏数据都能得到确定状态；
- 运行中坏数据不会继续送入观察器；
- Hybrid 模式自动回退 `CommandModel`，并记录原因和次数；
- 持续故障按配置降级或安全停机；
- 恢复条件有滞回，不能在有效/无效间每拍抖动。

## 10. A23：C/Rust 快速输入 ABI

计划在版本化输入快照中加入：三相电压 V、有效位、来源、序号、采样年龄和实际 `dt`。

必须同时完成 C `_Static_assert`、Rust size/alignment/offset 测试、ABI/version 提升、未知枚举
拒绝、旧版本拒绝和 Host C ABI 测试。硬件寄存器和 ADC 原始码仍留在 C 平台层；Rust
只接收校准后的物理量，不接收 STM32 HAL 类型。

## 11. A24：Rust PC 与 MATLAB 联合仿真

在 `foc-sim` 与 MATLAB/Simulink 中加入同一组传感器非理想：偏置、增益误差、量化、
采样延迟、PWM 边沿污染、丢样和饱和。比较三种电压源：

```text
CommandModel：补偿后的命令电压
Measured：    仅使用通过质量门的实测电压
Hybrid：      按转速、采样质量和故障状态融合/回退
```

Rust 目标端和 PC 使用同一控制实现，MATLAB 保持独立公式用于交叉核对。完成门是正常与故障
场景都可重复、字段同源、误差在预先定义的容差内；仿真通过不等于实机通过。

## 12. A25：观察器实机 A/B

在同一固件、同一工况和同一安全包络下，分别运行 CommandModel 与 Hybrid，不同时修改
PI、SMO、PLL 或 Rev-Up。比较启动成功率、接管时间、BEMF、PLL 相位误差、速度方差、
失锁次数、相电流和完整 ISR WCET。

没有编码器时只能评价重复性和内部健康，不能宣称角度更准确。Hybrid 无一致收益或失效
回退不可靠时，默认继续使用 CommandModel。

## 13. A26：参数辨识与 revision 2 候选

按风险从低到高执行：

1. Rs：定向保持，记录真实端电压、电流和绕组温度；
2. 平均 L：受限双极性短脉冲，拟合高频电流斜率；
3. Ld/Lq：多个电角度和电流点重复；
4. 磁链：需要可信端电压和独立转速/角度真值；
5. 每项均保存原始证据、算法版本、误差、重复次数和安全条件；
6. 只生成未批准 revision 2 候选，不自动写入运行 profile。

具体拒绝门见[参数辨识采集与筛查流程](parameters/参数辨识采集与筛查流程.md)和
[参数候选与审批流程](parameters/参数候选与审批流程.md)。

## 14. A27：闭环整定

使用已批准参数依次整定电流 PI、SMO/PLL、Rev-Up、开环到闭环接管、速度 PI 和电压限幅。
每次只改变一类参数，并在 PC/MATLAB 先回归。实机覆盖正反转、多个目标转速、冷启动、
热启动、加减速和有限负载；没有独立速度/角度真值时仍不能完成最终验收。

## 15. A28：产品化与移植验收

最后完成 Break/驱动故障、软件过流、母线过欠压、ADC 丢样、相电压故障、观察器失锁、
CORDIC 故障、deadline miss 和参数损坏注入；完成长时间温升、多板多电机、掉电恢复、
参数双副本/CRC/迁移和国产 MCU 平台替换验证。

只有完整验收矩阵通过后，才能讨论把 `closed_loop_enable` 或相电压 Hybrid 改为生产默认。

## 16. 每个阶段的共同完成定义

每个批次至少满足：

1. 代码位于架构规定层，没有硬件依赖倒灌到 Rust 算法；
2. 默认关闭时旧行为不变，失败路径保持输出关闭；
3. Host/单元测试覆盖正常值、边界值和故障值；
4. 涉及目标代码时完成交叉构建、ROM/RAM 和固件哈希记录；
5. 涉及快环时记录完整 ISR WCET，而不是相加独立峰值；
6. 涉及仿真时区分模型证明和实机证明；
7. 涉及电机时先获得用户对本次工况的许可，并在异常和正常退出都停机；
8. 原始数据、脚本、配置和报告可由 Git 路径与 SHA-256 追溯；
9. 更新本文状态、对应专项报告和[工程操作日志](工程操作日志.md)；
10. 未达到独立真值门时，明确保留“未验证”结论。

## 17. 更新规则

- 开始任务：把对应阶段从“待开始”改为“进行中”，在操作日志写开始基线；
- 遇到门槛：只有确实无法继续时标“阻塞”，写明缺少仪器、授权或外部状态；
- 完成任务：填入报告路径、测试结果、固件哈希和 Git 提交，再标“已完成”；
- 任务拆分：使用 `Axx.1/Axx.2`，不要随意改变后续编号含义；
- 方案变化：保留原决定和否决原因，不覆盖历史结论；
- Git 操作：优先小提交和 `git revert`，不使用破坏性 reset 清理用户工作区。

当前官方兼容主线的正式下一步是 A26 用 ST Motor Profiler 辨识实物 `Rs`/`Ld`/`Flux` 并复测
观察器获取时间，随后是 A27 带载与独立真值；实测/Hybrid 支线的下一步仍是 A19。A19 只允许
停机静态多点标定；在标定通过前不新增动态电压阶跃、不把 ADC 原始码接入观察器、不提高
profile revision 或 approvals。

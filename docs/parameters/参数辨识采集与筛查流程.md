# 参数辨识采集与筛查流程

## 1. 当前能力边界

当前 Diagnostic 固件有两条相互隔离的采集路径：10～50 Hz 文本 trace 提供三相电流、
Id/Iq、dq 电压指令、占空比、母线电压、强制角和观测器信息；A17 另有 12 kHz、256 拍
的 PC0/PC3/PC1 三相 BEMF ADC 原始码固定窗。后者目前只在停机状态使用，尚未标定为
电机端电压。这些数据适合检查信号链和参数趋势，但不等于电机参数辨识仪器：

| 参数 | 当前能做 | 当前不能做 |
|---|---|---|
| `Rs` | 定向末段用 `abs(Vq_command/Iq)` 做筛查；停机相电压原始码可验证采集链 | 缺已标定动态端电压和绕组温度，不能审批 |
| `Ls` | 已有 12 kHz 固定缓冲骨架 | 尚无安全电压阶跃、已标定电压和动态采集，不能拟合 |
| 磁链 | 无 | 缺实测端电压和独立转速/角度真值 |

因此工具的正式结果只有两类：采集不安全/不完整时拒绝；采集健康时输出
`screening-only` 报告并继续拒绝 revision 2。它不会修改候选、CRC、审批位或固件。

## 2. 文件布局

```text
profiles/
├─ schema/fluxrt-identification-session-v1.schema.json
└─ identification/
   ├─ sessions/      人工填写的工况、固件身份、能力和证据哈希
   ├─ evidence/      原始 CSV 与串口日志
   └─ reports/       工具生成的确定性筛查报告

tools/foc_identification_tool.py
tests/profile/test_foc_identification_tool.py
foc/runtime/foc_phase_voltage_capture.c
simulation/capture_phase_voltage_window.py
```

session 引用的 CSV 和日志都必须位于工程内并匹配 SHA-256；固件也应复制到 session 的
不可变 evidence 目录。历史固件没有归档时只能把 `firmware_image_path` 写为 `null`，
保留当时记录的 SHA-256，分析器会明确增加“不可重新校验”阻断项。禁止把历史 session
指向会被下次构建覆盖的 `cmake-build/fluxrt.bin`。报告记录 session 自身 SHA-256；改动
任一已归档原始证据都会让 `test.ps1` 失败。

## 3. 安全采集协议

当前只允许已经验证过的开环筛查工况：

1. Diagnostic 固件，profile revision 1，审批位 0；
2. 电机空载并可自由旋转，电源约 12.3 V、外部限流不高于 2 A；
3. 软件相电流跳闸 1.15 A，启动给定 0.8 A；
4. `closed_loop_enabled=false`，582 rpm 开环，50 Hz trace，最长 5 s；
5. 脚本必须先 `foc_stop`，异常和正常退出都再次 `foc_stop`；
6. 运行结束要求 dropped/error/deadline miss/Rust fault 全为 0；
7. 相电流、母线电压、状态和硬件故障位越界时，分析工具直接拒绝。

执行命令：

```powershell
python simulation/capture_hardware_trace.py `
  --port COM6 --duration 5 --target-rpm 582 --rate-hz 50 `
  --control-hz 12000 `
  --output profiles/identification/evidence/<session-id>/trace.csv `
  --allow-motor-run
```

采集后先计算三份哈希：固件、CSV、日志；再填写 session JSON。最后运行：

```powershell
python tools/foc_identification_tool.py analyze `
  profiles/identification/sessions/<session-id>.json `
  --output profiles/identification/reports/<session-id>.json

# 回归只读检查
python tools/foc_identification_tool.py analyze `
  profiles/identification/sessions/<session-id>.json `
  --output profiles/identification/reports/<session-id>.json --check
```

5.8266 Ω 不是可写入 profile 的辨识结果。它比 Workbench 5.29 Ω 高约 10%，可能同时
包含绕组温升、逆变器管压降、死区、控制器指令与实际端电压差异。没有温度和端电压时
无法把这些因素分开。

本次观察器在开环运行中不可靠、运行段出现较多 dq 电压限幅；这不会使本次安全健康
检查失败，但进一步说明不能从本次运行反推出磁链或闭环参数。

## 5. A17 相电压原始码固定窗

A17 已实现 PC0/PC3/PC1 对应 U/V/W 的 ADC1 注入采样、PC9 `IO_BEMF` 短时使能和
256×16 B 固定缓冲。12 kHz 下窗口为 21.33 ms，只在 Diagnostic 中存在。采集命令与
脚本如下：

```powershell
python simulation/capture_phase_voltage_window.py `
  --port COM6 `
  --output profiles/identification/evidence/<session-id>/phase_voltage_raw.csv
```

`start` 只在功率级未 arm 时成功；armed 期间平台拒绝 `foc_start`；脚本无论成功还是
异常都会执行 `foc_phase_capture stop` 和 `foc_stop`。本次无功率实机得到 256 个连续样本，
但由于没有电压标定和动态 PWM 工况，`actual_phase_voltage_measured` 仍必须为 `false`。
完整结果和证据哈希见
[`A17 相电压只读采样与固定窗`](../performance/2026-09-24-A17-相电压只读采样与固定窗.md)。

## 6. 形成 revision 2 前必须补齐

1. A17 已接入 IHM16M1 的 BEMF1/2/3 原始码；下一步校准三路偏置、增益、实际分压和
   有效采样窗，并用示波器核对；
2. A17 已增加 12 kHz 短时固定缓冲；下一步在安全 Identify 状态下采集动态电压/电流，
   仍不得在 ISR 中经 115200 文本串口实时输出；
3. 在专用 Identify 状态下做低占空、限时、限流电压阶跃，超时/过流/采样异常立即关断；
4. 记录绕组温度或冷态参考温度；
5. 磁链辨识还必须有独立转速/角度真值，不能使用同一个 SMO/PLL 的估计值作为真值；
6. 三项参数都得到重复采集和误差报告后，才允许生成未审批 revision 2。

下一步先做静态多点标定、示波器对拍、动态相序和新增 ADC 序列后的 WCET；这些门通过
前不把相电压接入控制律，也不执行新的电压阶跃。

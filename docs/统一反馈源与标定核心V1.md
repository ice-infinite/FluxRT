# FluxRT 统一反馈源与标定核心 V1

## 1. 当前结论

P4.1A 已在 `foc-control::feedback` 建立板级无关、无堆、`no_std` 的反馈选择与标定核心。
P4.1B1 已增加独立管理 ABI、目标中立 C adapter，并将批准后的更新接到既有配置事务；
P4.1B2 已补齐 Rust PC 与 MATLAB 两套独立反馈传感器故障模型和 D0/D2/D3/D4 对拍。
P4.1C 已在 `applications/` 增加默认关闭的单 owner 管理服务，负责超时、取消、配置事务暂存
和外部 commit/readback 确认后的收尾。
各阶段都复用 P1.1 已冻结的 68 B `ProductFeedbackSnapshot`，不会再创建第二套产品反馈语义。

当前只完成软件架构门：Sensorless、ABZ 增量编码器和 Hall 的输入归一、质量门、主备回退、
标定证据生命周期及事务暂存。它没有读取 GPIO/定时器、没有驱动电机、没有写 Flash，也
没有改变当前默认 Sensorless 快环。

## 2. 责任边界

```text
C platform adapter（P4.1B1 已完成目标中立层）
  原始 ABZ/Hall/observer 状态 -> SI 单位 + 显式有效位
                            |
                            v
foc-control::feedback（P4.1A 已完成）
  校验 -> 新鲜度/连续样本 -> 主备选择 -> ProductFeedbackSnapshot
  标定证据 -> ReadyForReview -> FeedbackCalibrationUpdate
                            |
                            v
foc-rt-bridge::feedback_abi（P4.1B1 已完成）
  定宽ABI -> 原位上下文 -> Axis/Calibration pending patch
                            |
                            v
config_transaction（P4.1B1 已接 pending；真实执行/Flash 未接）
  validate -> apply plan -> confirm -> commit/readback
                            |
                            v
applications::foc_feedback_management（P4.1C 已完成，默认关闭）
  owner/timeout/cancel -> stage+validate -> 等待外部commit -> finish
```

各层所有权如下：

| 层 | 应负责 | 不应负责 |
|---|---|---|
| C platform | 定时器/GPIO/EXTI、计数器扩展、原始 Hall 状态、硬件故障 | 回退策略、标定批准、配置持久化 |
| `foc-control::feedback` | 质量门、迟滞、统一快照、标定证据完整性 | HAL、RT-Thread、Flash、PWM、转动动作 |
| `foc-rt-bridge` | 定宽 C ABI、原位上下文、结构转换和事务暂存 | 重写 Rust 选择策略、自动提交 Flash |
| 管理服务 | 独占会话、超时/取消、调用平台标定动作、提交事务 | 直接改 ISR 正在使用的配置 |
| Rust PC / MATLAB | 独立传感器模型、故障注入、D0～D4 对拍 | 冒充目标板或实机证据 |

## 3. 统一输入和输出

平台适配器最终应把每个来源归一成 `FeedbackSourceSample`：

- 单位固定为 rad、rad/s；
- `sequence` 按来源独立递增，支持 `u32` 回绕；
- `sampled_at_us` 只用于短窗口新鲜度判断，使用半范围回绕规则；
- `sampled_at_ms` 属于长运行遥测时间域，不能从已回绕的微秒值临时相除；
- 没有对应 `valid_flags` 的浮点字段必须为 `0.0`；
- 未声明方向有效时 `direction` 必须为 0；
- 未知枚举、未知位、NaN/Inf、非规范字段和重复/倒退序号全部拒绝。

输出继续使用 `ProductFeedbackSnapshot`。没有可用来源时输出的 `valid_flags=0`；失效宽限拍
也不会继续暴露旧有效值，而是置 `DEGRADED`，超龄时再置 `STALE`。

## 4. 各反馈源最低质量门

| 来源 | 必须有效的数据 | 必须具备的质量 |
|---|---|---|
| Sensorless | 机械速度、电角度、电角速度 | 方向有效 |
| Hall | 机械速度、电角度、电角速度 | 方向有效、已标定 |
| ABZ 增量编码器 | 机械位置、多圈位置、机械速度、电角度、电角速度 | 方向有效、已标定、已找到 Index |

Absolute Encoder、Resolver 和 Fused 枚举虽在产品契约中预留，但 P4.1A 明确返回
`UnsupportedMode`，不能用零值或 Sensorless 路径伪装支持。

## 5. 主备选择和故障回退

路由器状态只有四种：

| 状态 | 含义 |
|---|---|
| `Acquiring` | 尚在积累互不重复的合格样本，输出不可用于控制 |
| `Primary` | 主来源已获取；单拍失效期间角色可保持，但输出立即 fail-closed |
| `Fallback` | 备用来源已获取并接管，快照显式带 `DEGRADED` |
| `Lost` | 主来源连续失效且没有已获取的备用来源 |

三个阈值彼此独立：

- `acquire_good_samples`：初次获取要求的连续新样本；
- `loss_bad_samples`：进入失效/切换备用前的连续坏评估拍；
- `recovery_good_samples`：从备用切回主来源要求的连续新样本。

重复读取同一个好样本不会增加 good 计数；超龄或质量失败的每个路由评估拍会增加 bad 计数。
这既防止“一份旧数据被重复算作已稳定”，也允许故障门具有确定的时间迟滞。主备模式相同
时必须关闭 fallback；主备不同时必须显式开启，含糊配置直接拒绝。

## 6. 标定生命周期

```text
Idle -> Collecting -> ReadyForReview -> Approved -> Idle
           |                 |
           +----错误-------->Failed --安全复位--> Idle
```

开始、批准、完成和失败复位均要求：Axis=`Disabled`、驱动输出关闭、活动故障为 0。会话使用
非零 token；过期 token 只返回错误，不改变当前会话。

### 6.1 ABZ 所需证据

1. 方向为 `-1` 或 `+1`，且达到最小样本数；
2. Index 已被稳定捕获；
3. 电角度 offset 有限且位于 `(-2π, 2π)`；
4. 配置策略提供非零 CPR。

### 6.2 Hall 所需证据

1. 方向为 `-1` 或 `+1`；
2. 六个扇区编码必须是 `0..5` 的完整排列，无重复、无 6/7、无高位垃圾；
3. 方向和序列均达到最小样本数。

任一坏证据会把会话锁存到 `Failed`。`approve()` 只产生
`FeedbackCalibrationUpdate` 并进入 `Approved`，不会修改 active 配置。P4.1B1 的
`foc_rust_feedback_stage_config_update()` 只把结果写入已有事务的 pending Axis/Calibration
组；调用者仍必须依次执行 config validate、apply、commit/readback，全部成功后才调用
`finish_applied()`。标定模块不会自行切换 active 配置或写 Flash。

## 7. P4.1B1 管理 ABI 与 C adapter

独立 ABI 版本为 `0x00010000`，不修改 V19/V20 每拍快环布局。固定结构大小为：router config
40 B、source sample 64 B、calibration policy 28 B、route decision 84 B、calibration update
40 B、status 40 B；调用者提供 8 字节对齐、至少 512 B 的原位上下文。

推荐调用顺序：

1. `foc_rust_feedback_init()` 初始化路由和标定上下文；
2. C adapter 把 observer、ABZ 或 Hall 原始状态规范化为统一 sample；
3. `ingest()` 后由 `route()` 产生统一 68 B 快照；
4. Disabled、输出关闭且无故障时开始标定，逐步提交方向/Index/offset/Hall 证据；
5. `approve()` 取得不可直接生效的 update；
6. 配置事务 begin 后调用 `stage_config_update()`，再由配置 ABI validate/apply/commit；
7. 只有回读确认成功才调用 `finish_applied()`。

C adapter 不读取寄存器，也不拥有定时器扩展：不可用来源归一为 `STALE`，不可靠、未标定
或缺 Index 归一为 `DEGRADED`，无有效位的数值清零。真实 GPIO/Timer/EXTI 接线属于后续目标
平台工作，不能由 Host adapter 测试代替。

## 8. 当前验证

- 8 个核心 Rust 测试覆盖获取、超时、主备回退/恢复、回绕序号、未知枚举、非规范字段、
  ABZ/Hall 完整标定、坏证据锁存、危险状态和过期 token；
- 3 个 bridge Rust 测试覆盖 ABI 布局/路由、标定更新暂存和危险状态/过期 token/坏指针重试；
- 1 个严格警告 C Host 目标覆盖三类 adapter 的有效、降级、过期、NaN 和坏方向负例；
- 严格 Clippy `-D warnings` 通过；
- 全量 Python、Rust、C Host 和既有闭环仿真通过；
- 四个 Cortex-M4F 构建档通过；管理 ABI 已进入 M4F archive，默认快环仍不调用路由或 adapter。

P4.1B2 使用同一 SI profile、trace schema 和 comparison gate，但两端不互相调用：Rust PC
复用真实 `FeedbackRouter`，MATLAB 独立实现状态和传感器模型，最后由 Python 比较器核对。
共同场景固定为 16 个评估拍、5 个 case、80 行：

| case | 目的 | 结果 |
|---|---|---|
| `feature_off` | 关闭新模型 | 与原理想 Sensorless 位置/速度逐行等价 |
| `nominal` | 编码器量化与1拍延迟 | 第2拍获取主编码器 |
| `encoder_drop_fallback` | 第6～9拍丢脉冲 | 第7拍切Hall，第12拍恢复编码器 |
| `encoder_index_missing` | 永久缺Index | 不接收编码器，稳定使用Hall备用 |
| `hall_wrong_order_and_primary_drop` | 主编码器丢脉冲且Hall错序 | 第7拍进入Lost，valid清零；第12拍重获编码器 |

这里的 D2/D3/D4 只覆盖反馈传感器子契约，不代表整个闭环控制、功率级或实机已完成同等级
相关性。生成结果位于被忽略的 `simulation/results/feedback/`，可用
`simulation/run_feedback_sensor_gate.ps1` 重现。

## 9. P4.1C 默认关闭的管理服务

`applications/foc_feedback_management.*` 是单一 RT-Thread 管理 owner 可调用的确定性协调器，
本身不创建线程、不注册 Shell，也不读取硬件。初始化后固定为 `Disabled`，只有调用者提供
Disabled、输出关闭且无故障的 guard，并显式 `set_enabled(1)` 后才接受会话。当前目标没有
这个调用点，因此四档默认行为不变。

服务状态固定为：

```text
Disabled -> Idle -> Collecting -> ReadyForReview -> Staged -> Idle
                         |              |             |
                         +----异常/超时/不可回滚-----> Failed
```

关键约束：

- `owner_id` 必须非零；另一 owner 只能得到 `NotOwner/Busy`，不能提交证据或取消会话；
- timeout 为 1～600000 ms，按无符号 elapsed 处理 `u32` 回绕；超时会请求安全关断、取消/回滚，
  并锁存 `Failed`，必须在安全 guard 下恢复；
- `force_safe` 回调由目标适配器提供，初始化、显式停用、取消、超时和错误路径都会调用；
- `approve_and_stage()` 只执行 config begin、Axis/Calibration stage 和 validate，不执行
  volatile apply，也不擦写 Flash；
- 外部参数服务完成 apply、commit 和 readback 后，只有 config 已回到 `Idle` 且
  `active_revision` 等于预期 revision，`finish_committed()` 才关闭标定会话；
- Editing/Validated/ApplyPrepared/VolatileApplied 可在安全状态取消并回滚；一旦进入
  CommitPrepared 或 StorageFault，服务不会猜测 Flash 结果，而是保持 `Failed` 和关断要求。

Host fake service 覆盖默认关闭、危险 guard、owner 争用、完整编码器证据、等待外部 commit、
取消回滚、时间回绕超时、坏证据恢复和 CommitPrepared 不可回滚。目标四档会编译本源文件，
但因为尚未注册目标实例，链接器将函数段丢弃，BIN 尺寸和 SHA-256 与 P4.1B2 完全相同。

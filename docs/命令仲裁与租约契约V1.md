# FluxRT 命令仲裁与租约契约 V1

## 1. 结论与范围

P1.2 已在 `rust/crates/foc-control/src/command.rs` 建立固定容量、`no_std`、无堆分配的
产品命令仲裁纯逻辑。它消费《产品公共契约 V1》的 `ProductCommand`，但尚未接入 C ABI、
通信协议、Shell、目标管理任务、ISR 或 PWM，因此不会改变当前板上行为。

本阶段解决的是“哪一个来源的哪一组合法命令可以交给后续状态机”，不负责：

- 执行 Axis 状态迁移或直接打开输出；
- 定义 CAN/UART/USB 数据帧；
- 保存 `AppConfig`；
- 判断 Break、driver、母线或功率级已经恢复；
- 决定产品最终采用 coast、brake 还是其它超时动作。

## 2. 数据模型

每个配置来源使用一个固定槽，槽内彼此分离：

| 对象 | 生命周期 | 说明 |
|---|---|---|
| `setpoint` | 租约内持续 | 保存该来源最新合法目标，不会单独 arm |
| `action` | 一次性 | 保存 AxisRequest 或 ClearFault，输出一次后消费 |
| `emergency_stop` | 一次性独立通道 | 不会被同源后续普通 action 覆盖 |
| `last_sequence` | 来源生命周期 | Release、超时和 fault 后仍保留，阻止旧帧复活 |

`ClosedLoopControl` 只有和**同一来源**的新鲜 setpoint 同时存在时才会形成可交付决策；
其它来源的目标不能被继承。非闭环 AxisRequest 会清除旧 setpoint，避免标定、辨识或停机
请求意外携带运行目标。

## 3. 来源策略

`CommandSourcePolicy` 是受信任配置，不从命令帧读取：

```text
source_id
priority
permissions
lease_ms
command_timeout_ms
```

- 数值更大的 `priority` 优先；
- 已持有租约的来源阻挡同级和低级来源，高级来源可立即抢占；
- 无 owner 时同优先级由较小 `source_id` 确定性胜出；
- `source_id` 只表示身份，不能编码优先级；
- `permissions` 分别授权 Release、AxisRequest、Setpoint、ClearFault、EmergencyStop；
- 未配置来源或未授权命令 fail-closed，且不推进防重放水位；
- `0 < lease_ms <= command_timeout_ms < 2^31`。

实际 source、优先级和权限值要到 P3 的版本化 `AppConfig` 才能批准；P1.2 没有写死
CAN、Shell 或上位机的产品优先级。

## 4. sequence 和时间

### 4.1 sequence

sequence 是每个 source 的全局 32 位串行数：

```text
delta = new.wrapping_sub(last)
delta == 0          -> duplicate
delta == 0x80000000 -> ambiguous / out of order
delta < 0x80000000  -> newer
其它                -> replay / out of order
```

Release、lease 到期、命令到期、EStop、外部 fault 和 ClearFault 都不会清除水位。来源进程重启
后不能擅自从零重新取得所有权；后续如需要 session/epoch reset，必须另立契约并只允许在
Disabled、无 owner 条件下执行。

单条 `submit()` 严格按到达顺序执行防重放。管理任务在同一拍已经收集到有界批次时，应使用
`submit_batch()`；它按同源回绕 sequence 排序后提交，并以调用者输入顺序返回结果。因此
Setpoint/AxisRequest 的同拍结果不依赖队列遍历顺序，且支持 `0xffffffff -> 0` 回绕。

### 4.2 timestamp、validity 和 lease

- `created_at_ms` / `valid_until_ms` 属于设备单调毫秒时钟域；主机时间必须由输入适配器转换；
- 有效窗必须满足 `0 < valid_until-created_at < 2^31`；
- `valid_until_ms` 是排他上界，`now == valid_until` 已过期；
- 未来时间戳、零窗、半周窗、过期和超过来源 timeout 均拒绝；
- owner 实际有效期取命令新鲜度与策略 lease 中先到者；lease 截止同样是排他的；
- 超时清除全部旧候选、保留 sequence 水位、输出一次明确 `CommandTimeout`，下一拍不会自动
  降级到等待中的旧来源。

## 5. 同拍安全优先级

当前纯逻辑冻结为：

```text
外部硬件/驱动 fault
  > EmergencyStop
  > 已锁存 EStop
  > active command/lease timeout
  > ClearFault
  > 高优先级来源抢占
  > 当前 owner
  > 无 owner 时的确定性来源选择
```

具体语义：

- 外部 fault 与 ClearFault 同拍时 fault 胜，并清除全部旧 payload；
- EStop 使用独立通道，不能被普通 mailbox action 覆盖；
- EStop 锁存后只允许交付 ClearFault；
- ClearFault 和 EStop/fault 都清除旧控制内容，恢复后必须重新下发 setpoint 和启动请求；
- Release 只释放发送来源；若另一个来源仍有**新鲜**命令，可在随后 poll 中按策略接管；
- `Safe(NoCommand/FaultActive/EmergencyStopLatched/CommandTimeout)` 都表示下游不得打开输出。

`fault_active=false` 只表示调用者已确认底层活动故障消失，不等于自动允许 ClearFault；目标端
接入时还必须由安全管理器检查 PWM 已关、Break/driver 已恢复和产品前置条件。

## 6. 已覆盖测试

Rust 单元测试覆盖：

- 空策略、重复 source、零/半周 duration 和 lease/timeout 配置；
- sequence 重复、倒序、半周歧义和 `u32` 回绕；
- timestamp 未来、零窗、排他截止、跨回绕和 timeout；
- 同拍批次正序/反序与 sequence 回绕；
- 双来源优先级、同级确定性、租约保持、高级抢占和 Release；
- Setpoint/AxisRequest 分槽、请求一次性消费、跨来源不继承；
- 权限拒绝不推进防重放水位；
- EStop 不被覆盖、fault/ClearFault 同拍、超时后不自动恢复旧命令；
- 产品命令的非法 `AxisRequest + feedback_mode` 在 Rust 与 FFI 两层拒绝。

这些是 S1 纯逻辑证据。交叉构建只能证明 `no_std` 可编译；在目标管理任务、真实协议和安全
状态机接入以前，不得宣称命令仲裁已在板端工作。

## 7. 后续接入门

1. P3 由版本化 `AppConfig` 提供 source policy，并为配置做 CRC、双副本和回滚；
2. 输入适配器完成鉴权、主机时间到设备时间转换和有界 mailbox；
3. 低频管理任务调用仲裁器，ISR 只读已批准的不可变快照；
4. 下游 Axis 状态机再次检查配置、fault、母线、反馈质量和输出条件；
5. 增加 C ABI/协议前先冻结线程所有权、队列容量、溢出策略和事件记录；
6. 目标接入后补 deadline、队列满、断线、并发来源和 fault 注入的 S4～S6 证据。

P2.4～P2.8将UART/USB/CAN/CAN-FD/PX4 DroneCAN/Cyphal/MAVLink管理/CANopen、PWM/DShot/Analog/
Step-Dir和EtherCAT全部按上述同一来源契约接入；它们只能生成`ProductCommand`，不能拥有第二套
仲裁器或直接操作Axis/FOC。编译期和运行期选择、资源冲突及各接口完成门见
[可选外部控制与通信架构](可选外部控制与通信架构.md)。

可复用实现时保持关闭，不能自写兼容栈。PX4实时CAN命令优先DroneCAN、其次Cyphal，MAVLink
只进入管理来源而不直接获得Axis owner。详见

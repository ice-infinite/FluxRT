# FluxRT 产品公共契约 V1

## 1. 结论与边界

P1.1 已冻结第一版产品层公共语言，供目标固件、Rust PC 仿真、MATLAB/Simulink、后续
配置系统和上位机共同使用。源码真值为：

- Rust：`rust/crates/foc-control/src/contract.rs`；
- C：`foc/include/foc_product_contract.h`；
- FFI：`foc/include/foc_rust_bridge.h` 与 `rust/crates/foc-rt-bridge/src/lib.rs`。

本契约描述的是 `Device/Axis` 的外部行为，不是当前 12 kHz ISR 的内部数据结构：

| 层次 | 当前对象 | 作用 |
|---|---|---|
| 产品层 | `AxisState`、`ProductCommand`、反馈/遥测/故障快照 | 面向命令仲裁、仿真、配置和未来协议 |
| 控制器层 | `foc_state_t`、Rust `Controller` | 当前控制状态机的内部实现 |
| 快环输入层 | `foc_realtime_input_t` V19 | ADC/平台到 12 kHz 控制调用的逐拍输入 |

三者不可互相改名或强制共用。P1.1 只新增产品契约和纯校验器，不把它接入命令路径、ISR、
PWM 或功率级，因此现有启动目标、控制参数和默认 `closed_loop=0` 均未改变。

## 2. 版本与兼容规则

| 项 | 冻结值 |
|---|---:|
| 产品契约版本 | `0x00010000` |
| 命令结构版本 | `1` |
| 反馈快照版本 | `1` |
| 遥测快照版本 | `1` |
| 故障快照版本 | `1` |
| 全局 C/Rust bridge ABI | V20 / `0x00140000` |
| 既有逐拍输入子契约 | V19 / 88 B / version `1`，未改变 |

兼容规则：

1. 所有跨语言枚举均以 `uint32_t` / `#[repr(u32)]` 传输；
2. 所有结构只包含定宽标量，不含指针、C `bool`、Rust 引用、切片或需析构对象；
3. 接收方必须检查 `struct_size` 和结构自身 `version`，不能只检查全局 ABI；
4. 未知版本、枚举、flag、非有限浮点数和非法组合全部拒绝，不能猜测或降级；
5. V1 只支持 `axis_id=0`。字段已预留 `axis_id`，但非零轴在能力发布前必须拒绝；
6. 改字段含义、顺序、宽度或函数签名必须提升全局 bridge ABI；破坏产品语义兼容时还要
   提升产品契约版本；
7. 目标启动会同时比较 bridge ABI 和产品契约版本，任一不匹配都保持 PWM 关闭并停机；
8. 未使用字段必须为规范零值，防止旧值在模式切换后被误解释。

`simulink/init_foc_params.m` 中的 `firmwareAbi=0x00080000` 仍是旧 MATLAB 参数镜像的历史
标识，不等于本产品契约。P1.3 会把两套仿真迁移到共同 identity/schema；P1.1 不在没有
schema 迁移的情况下只改一个字符串来制造虚假兼容。

## 3. 状态和模式冻结值

### 3.1 AxisState

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | `Uninitialized` | 尚未完成软件和硬件初始化 |
| 1 | `Disabled` | 初始化完成，输出关闭 |
| 2 | `Calibration` | 正在执行授权的标定 |
| 3 | `Startup` | 对齐、开环升速或反馈接管 |
| 4 | `ClosedLoop` | 闭环运行 |
| 5 | `Stopping` | 有序停止中 |
| 6 | `FaultLatched` | 故障已锁存，必须显式清除且前置条件通过 |

`AxisState` 只表达实际生命周期，不表达目标值，也不是命令。

### 3.2 AxisRequest

| 值 | 名称 |
|---:|---|
| 0 | `None` |
| 1 | `Disabled` |
| 2 | `CurrentOffsetCalibration` |
| 3 | `MotorIdentification` |
| 4 | `EncoderIndexSearch` |
| 5 | `EncoderOffsetCalibration` |
| 6 | `HallCalibration` |
| 7 | `Homing` |
| 8 | `OpenLoopTest` |
| 9 | `ClosedLoopControl` |

请求与实际状态分离。例如请求 `ClosedLoopControl` 不代表已经进入 `ClosedLoop`；状态机仍要
检查配置、故障、反馈质量、母线和功率级条件。

### 3.3 ControlMode

| 值 | 名称 | 主目标单位 |
|---:|---|---|
| 0 | `Inactive` | 无目标，仅用于非 Setpoint 命令 |
| 1 | `Voltage` | `V`，d/q 电压 |
| 2 | `Duty` | `[-1, 1]`，有符号归一化占空比 |
| 3 | `Current` | `A`，d/q 电流 |
| 4 | `Torque` | `N*m` |
| 5 | `Velocity` | `rad/s` |
| 6 | `Position` | `rad` |

V1 明确增加 `Inactive` 和 `Current`：`Inactive` 避免用某个有效控制模式冒充“无控制”；
`Current` 避免把安培目标假装成牛米目标。`Torque` 后续必须经过电机参数/转矩常数换算，
不能与 `Iq[A]` 混用。

### 3.4 InputMode

| 值 | 名称 | 允许的 ControlMode |
|---:|---|---|
| 0 | `Inactive` | 仅 `Inactive` |
| 1 | `Passthrough` | 任一有效控制模式 |
| 2 | `TorqueRamp` | 仅 `Torque` |
| 3 | `VelocityRamp` | 仅 `Velocity` |
| 4 | `PositionFilter` | 仅 `Position` |
| 5 | `TrapezoidalTrajectory` | 仅 `Position` |
| 6 | `ExternalSynchronized` | 任一有效控制模式 |

### 3.5 FeedbackMode

| 值 | 名称 |
|---:|---|
| 0 | `Sensorless` |
| 1 | `Hall` |
| 2 | `IncrementalEncoder` |
| 3 | `AbsoluteEncoder` |
| 4 | `Resolver` |
| 5 | `Fused` |

枚举表示产品意图或当前选择，不代表对应驱动已经存在。后续 capabilities 必须单独声明板卡
真正支持哪些反馈源。

## 4. ProductCommand

`foc_product_command_t` / Rust `ProductCommand` 固定为 104 B、4 B 对齐。命令类型为：

| 值 | 命令 | 规则 |
|---:|---|---|
| 0 | `Release` | 放弃控制；模式、请求、flags 和物理字段全为零 |
| 1 | `AxisRequest` | 仅 `axis_request` 可非零；目标和 limit 全为零 |
| 2 | `Setpoint` | `axis_request=None`；控制/输入模式组合必须合法 |
| 3 | `ClearFault` | 只表达清除请求；不能夹带目标 |
| 4 | `EmergencyStop` | 只表达急停；不能夹带目标 |

命令头还包含 `source_id`、`sequence`、`created_at_ms` 和 `valid_until_ms`。时间是 32 位单调
毫秒计数，允许回绕；P1.2 负责 lease、时效、乱序和来源优先级。本轮校验器只验证结构、
枚举、有限值、模式组合和规范字段，不提前实现仲裁语义。

限制 flag：bit0=`current_limit_a`，bit1=`torque_limit_nm`，bit2=`velocity_limit_rad_s`。
启用的限制必须严格大于零且适用于当前模式；未启用的限制字段必须为零。所有浮点数必须
有限，`NaN`/`Inf` 一律拒绝。

| 限制 | 允许的 ControlMode |
|---|---|
| `current_limit_a` | Current / Torque / Velocity / Position |
| `torque_limit_nm` | Torque / Velocity / Position |
| `velocity_limit_rad_s` | Velocity / Position |

电流限制可以叠加到所有依赖电流/转矩内环的模式；即使外层目标是速度或位置，也不能失去
安培级安全边界。Voltage/Duty 调试模式仍只依赖底层硬件保护，不接受这些产品软限制。

### 4.1 既有 524 rpm 启动的等价表达

现有路径没有被替换，但其意图可由两条产品命令无损表达：

1. `Setpoint + Velocity + Passthrough + Sensorless`，并令
   `velocity_ref_rad_s = 524 * 2*pi/60 = 54.873... rad/s`；
2. 单独发送 `AxisRequest + ClosedLoopControl`。

目标与启动请求分成两条命令，避免“写目标即自动 arm”。Rust 和 C Host 测试均锁定了
524 rpm 的 SI 往返，不改变旧目标值。

## 5. 三种只读快照

### 5.1 FeedbackSnapshot（68 B）

包含采样序号/时间/年龄、主/备用反馈源、方向、极对数 revision、机械位置/多圈位置/机械
速度、电角度/电角速度。`valid_flags` 对每个物理量逐项声明有效性，`quality_flags` 独立表达
已标定、找到 Index、方向有效、stale 和 degraded。

“数值为零”不等于“有效零值”；消费者必须同时检查 valid/quality。

### 5.2 TelemetrySnapshot（120 B）

遥测显式分离 `reference`、`measured`、`estimated` 和控制器实际 `used` 值，禁止把估算值
改名为测量真值。`valid_flags` 分别覆盖位置、速度、转矩、dq 电流、电压命令、母线和温度；
当前没有独立测量能力的通道必须清除对应位。

### 5.3 FaultSnapshot（72 B）

包含首次/最近发生时间、次数、锁存/活动故障集合、主故障、故障时状态/模式和母线、电流、
速度、温度证据。故障位冻结为急停、driver、Break、过流、母线欠压/过压、ADC、deadline、
反馈无效、观察器启动/运行丢失、输出拒绝、过温、命令超时和配置无效。`primary_fault`
必须为零或上述单一 bit，具体优先级由后续故障聚合器定义。

## 6. C/Rust ABI 布局

| 结构 | 大小/对齐 | 关键 offset |
|---|---|---|
| `ProductCommand` | 104 / 4 B | flags 48，duty 52，current 64，velocity 76，末字段 100 |
| `ProductFeedbackSnapshot` | 68 / 4 B | active mode 32，首个物理量 48 |
| `ProductTelemetrySnapshot` | 120 / 4 B | valid flags 44，首个物理量 48，Vbus 112 |
| `ProductFaultSnapshot` | 72 / 4 B | latched flags 28，primary 36，首个证据 56 |

C `_Static_assert` 与 Rust `size_of/align_of/offset_of` 测试共同锁定布局。启动还调用
`foc_rust_product_contract_version()` 做目标镜像自检。`foc_rust_validate_product_command()`
是无状态、无硬件副作用的纯校验入口；它当前由 Rust FFI 测试覆盖，等 P1.2 命令入口消费
后才会保留在最终 ELF 的可达路径中。

## 7. 后续实现必须遵守的边界

- P1.2 只消费本命令结构实现 mailbox/仲裁/lease，不重定义模式和单位；
- P1.3 两套仿真共享 schema/identity，并迁移旧 MATLAB ABI 元数据，不复制 Rust 控制实现；
- P3 配置系统引用这些枚举，但配置 schema version 独立演进；
- P4 才把各反馈驱动映射为统一反馈快照，并建立质量门和回退；
- P4.2 才实现 Torque/Velocity/Position 与各 InputMode 的完整状态机；
- 正式设备协议只序列化公共语义，不允许直接透传 Rust 内存或当前 ISR 私有结构；
- 新模式在实现和能力声明完成前保持“不支持”，不能自动回退到相近模式。

## 8. 本阶段证据边界

P1.1 已达到 S1（Host/单元/静态检查）和 S2（四档交叉构建）。它证明契约在 C/Rust 两侧
可编译、布局一致、非法组合可拒绝、旧速度启动可表达；不证明命令仲裁、模式执行、协议、
烧录、实机控制或产品安全已经完成。

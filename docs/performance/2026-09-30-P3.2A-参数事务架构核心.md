# P3.2A 参数事务架构核心

## 1. 目标

先完成不绑定具体电机的配置事务骨架，让后续 `Rs/Ld/Lq/磁链/PI/观察器` 调参只改变
受控配置数据，不改变架构、ISR或Flash原子性。

## 2. 实现

- 新增 `foc-control::config_transaction`，保持 `no_std`、无堆、无锁、无硬件依赖；
- 单写者token拒绝陈旧客户端；
- 六组定宽patch只修改pending，设备端重新计算真实group diff；
- `validate`只接受完整合法bundle，空事务和改回原值被拒绝；
- `prepare/confirm volatile apply`把实际执行器隔离在事务核心外；
- 应用等级固定为管理策略、Axis重建和平台重建三类；
- apply、rollback-after-apply和commit均要求Disabled、输出关闭、无活动故障；
- commit沿用P3.1双槽写计划，只有解码、sequence、approval、目标slot和内容全部回读一致才确认；
- 回读失败保留当前已应用的volatile active并进入`StorageFault`，避免虚构外部控制器已
  回滚；必须重启/重新扫描双槽或由后续执行器显式回滚后才能继续。

## 3. 本阶段没有做

- 未加入C ABI、RT-Thread参数线程、Shell或设备协议；
- 未连接实际运行控制器、平台寄存器或目标Flash；
- 未修改当前电机参数、PI、观测器、PWM频率或安全阈值；
- 未烧录、未转动电机，不能作为实机或掉电恢复证据。

## 4. 验证门

Host测试覆盖：正常apply+commit、坏参数、陈旧token、运行/输出/故障门、volatile rollback、
apply取消、坏Flash回读锁定和no-op事务拒绝。完整工作区、交叉构建和容量结果以同日
[工程操作日志](../工程操作日志.md)为准。

本轮实际结果：

- `test.ps1`：Python 147+37、Rust 75+81+31+36、C Host 20项全部通过；
- 524 rpm闭环PC仿真：`final_rpm=534.52`、`peak_phase_current_a=0.122`；
- Clippy `-D warnings`、CPU/CORDIC两种M4F Rust交叉构建通过；
- Diagnostic/Calibration/Identification/Production四档目标构建通过，ROM分别为
  110,604 / 102,964 / 115,812 / 101,688 B；
- 未烧录、未访问串口、未运行电机，因此证据止于S2。

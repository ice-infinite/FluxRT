# 阶段 1.3：可移植 CPU 快速数学候选 A/B

## 1. 结论

本轮实现了不依赖 CORDIC、DSP 或芯片寄存器的 Rust `f32` 快速 `sin/cos` 与
`atan2` 候选，并完成 Host 密集误差回归、同镜像停机 DWT 分项、PC 闭环仿真、实机完整
ISR A/B 和默认固件恢复。

- Host 密集扫描锁定最大允许误差：`sin <= 4e-6`、`cos <= 2.6e-5`、
  `atan2 <= 13 urad`；
- 板上 16 向量实测最大分量误差为 `24,855 ppb`，最大角误差为 `12 urad`；
- 通过 C ABI 的停机分项中，CPU-fast `sin/cos` 比 CORDIC 慢，而 `atan2` 略快；
- 实时路径中的 Rust 多项式可被内联，三轮 5 秒最坏完整 ISR 从 CORDIC 的
  `7,975` 降到 `7,771 cycles`，节省 `204 cycles`（2.56%）；
- 六轮实机均为 0 timing invalid、0 deadline miss、0 control error、0 Rust fault；
- PC bring-up 闭环仿真的速度、电流和观测器指标与软件基线基本一致；
- 测试结束已恢复普通 Diagnostic，CPU-fast benchmark/candidate 均关闭。

**决策：保留候选，不升为 G431 默认。** 当前实机测试仍是 `closed_loop=0`，没有编码器
或外部测速真值；快速 `atan2` 已参与观测器计算，但观测器没有接管控制角。因此本轮能证明
数值包络、开环安全短测与 WCET 收益，不能证明无感闭环角度质量不退化。STM32G431 继续默认
使用有界轮询 CORDIC + FPU；CPU-fast 作为无 CORDIC 国产 MCU 的可移植基线和后续闭环候选。

## 2. 实现与边界

| 层 | 实现 | 边界 |
|---|---|---|
| `foc-algorithm` | `fast_sin_cos()`、`fast_atan2_angle_0_to_2pi()` | 纯 `no_std f32` 多项式，无 HAL/FFI/全局状态 |
| `foc-control` | `FastApproxMath: ControlMath` | 与 `CpuMath`/平台后端使用同一控制契约 |
| `foc-rt-bridge` | feature 选择、两个停机诊断导出 | 实时候选可在 target/PC 显式启用；非法输入清零并返回失败 |
| C 平台 | DWT 同镜像基准记录 | 不实现算法，只计时并与 CORDIC 对拍 |
| Kconfig/CMake | benchmark 与 candidate 两级开关 | 默认 `n`；Production 忽略残留开关 |

新增开关：

- `FOC_MATH_CPU_FAST_APPROX_BENCHMARK`：把 Rust 快速近似放入停机基准；
- `FOC_MATH_CPU_FAST_APPROX_CANDIDATE`：Diagnostic 实时 `sin/cos`/`atan2` 改用快速近似；
- magnitude 不变，G431 继续使用 FPU `VSQRT.F32`。

新增两个诊断 C ABI 符号，因此 ABI 由 `0x00070000` 提升到 `0x00080000`，C/Rust、Host
测试和 MATLAB/Simulink 元数据同步更新。运行时配置结构未改，config version 仍为 4。

## 3. 数值方法与 Host 证据

`sin/cos` 先把角度缩到 `[-pi/2, pi/2]`，再计算 9 阶正弦和 8 阶余弦多项式；`atan2`
先把比值限制在 `[0,1]`，计算第一八分区奇多项式，再恢复象限。零矢量返回 0，NaN/Inf
返回 NaN；诊断 ABI 会把非有限输入转成“返回 0 + 出参清零”。

Host 测试扫描范围：

| 运算 | 扫描 | 回归阈值 |
|---|---:|---:|
| `sin/cos` | `[-2pi, 2pi]`，32,769 点 | `sin 4e-6`、`cos 2.6e-5` |
| `atan2` | 单位圆 65,537 点 | `13 urad` |

阈值是当前系数的回归包络，不表示它与 `libm` 或 CORDIC 等价。未来修改系数必须重新密集
扫描、PC 仿真和目标 WCET，不能只看少量轴线向量。

## 4. 同镜像停机分项

专项镜像打开 CORDIC benchmark 与 CPU-fast benchmark，实时仍走 CORDIC，执行
`foc_math_bench 64`。每类运算 16 向量 × 64 次，共 1,024 次：

| 后端/运算 | raw min/avg/max cycles | 最大误差 | 失败 |
|---|---:|---:|---:|
| CORDIC poll `sin/cos` | 385/393/423 | 1,013 ppb | 0 |
| CORDIC poll `atan2` | 458/475/499 | 1 urad | 0 |
| CORDIC fixed-6-NOP `sin/cos` | 374/383/397 | 1,013 ppb | 0 |
| CORDIC fixed-6-NOP `atan2` | 433/455/474 | 1 urad | 0 |
| CPU-fast `sin/cos` | 521/544/555 | 24,855 ppb | 0 |
| CPU-fast `atan2` | 425/426/444 | 12 urad | 0 |

四个非法输入全部按契约拒绝，`health=PASS`。CPU-fast 分项经过
`C -> Rust extern C -> FastApproxMath` 的 noinline 诊断边界，因此该数字不能直接推导实时
路径；实时路径在 Rust 内部可以内联，这也是完整 ISR 结果与分项直觉不同的原因。

## 5. PC 闭环仿真

显式启用 `foc-rt-bridge/fast-math-candidate` 后，理想反馈仿真和走固件 ABI 的 bring-up
仿真均 PASS。bring-up 关键对比：

| 指标 | 软件基线 | CPU-fast |
|---|---:|---:|
| final true speed | 577.28 rpm | 577.28 rpm |
| final observer speed | 587.76 rpm | 587.76 rpm |
| transient speed RMSE | 5.178 rpm | 5.179 rpm |
| steady speed std | 7.9465 rpm | 7.9482 rpm |
| steady observer RMSE | 13.442 rpm | 13.442 rpm |
| steady Iq / Id RMSE | 0.000380 / 0.000094 A | 0.000380 / 0.000094 A |
| final state / samples | 5 / 189 | 5 / 189 |

该结果只证明同一 PC plant 下候选未破坏闭环回归；plant 和观测器使用同一参数，不能替代
带独立编码器真值的实机闭环验证。

## 6. 实机完整 ISR A/B

条件：NUCLEO-G431RB + X-NUCLEO-IHM16M1 + GBM2804H-100T，板端约
12.28～12.30 V，电源上限 2 A，软件 trip 1.15 A，电机空载自由旋转；582 rpm、
`closed_loop=0`、trace off，每种后端三轮、每轮约 5 秒。

| 实时后端 | 三轮完整 ISR WCET | 最坏 control | miss/error/fault |
|---|---:|---:|---:|
| CORDIC poll + FPU | 7,965 / 7,975 / 7,965 | 7,107 | 0/0/0 |
| CPU-fast + FPU | 7,771 / 7,751 / 7,751 | 6,893 | 0/0/0 |

按最坏值，CPU-fast 节省 `204 cycles`（2.56%），control 段节省 `214 cycles`（3.01%）。
候选仍有 `4,729 cycles` 软件截止余量。该 A/B 使用两份只相差实时选择 feature 的专项
镜像；两份镜像都保留同一套 CORDIC/固定延迟/CPU-fast 停机基准。

## 8. 证据边界与下一步

专项/Production 目标构建）、S4（下载/verify/reset/串口）和受限 S5（六轮专项 + 一轮默认

阶段 2：先在 PC/Simulink 建立 `24 kHz PWM + 12 kHz 控制` 的调度、保持/延迟模型和验收
数据，再决定是否修改 TIM1/ADC 实机触发。CPU-fast 只有通过实机闭环角度真值 A/B 后才可
讨论升为默认。

# A22.2 / A24.4 平台锁门与 PC 完整相电压链

## 1. 结论

本轮完成两项纯软件门：

- A22.2：STM32G431 名义相电压模型进入纯 C 质量核心，但始终标记为
  `UNCALIBRATED`，不能成为观察器实测电压；
- A24.4：PC 上建立
  `plant端电压 → 传感器非理想 → 质量/来源选择 → V19 → target bridge + shadow SMO/PLL`
  的确定性链路。

默认目标固件仍使用 `CommandModel`。`Measured` 在目标 bridge 继续返回
`NotConfigured` 并清零输出；Hybrid 故障时解析为 `CommandModel`，不会把坏测量值送入观察器。
本轮达到 S1/S2/S3，不是逐板标定、目标 ISR、WCET 或实机闭环证据。

## 2. A22.2：未标定平台适配器

新增：

- `foc/include/foc_phase_voltage_platform_adapter.h`
- `foc/platform/stm32g431/foc_phase_voltage_platform_adapter.c`
- `tests/host/test_foc_phase_voltage_platform_adapter.c`

适配器只做名义换算、诊断和 A22 质量调用，不依赖寄存器、HAL、RTOS 或 ISR。版本 1
只接受 ST 名义/诊断模型，不设置 `CALIBRATED`，且 `observer_eligible` 恒为 0：

| 请求 | A22.2 实际选择 |
|---|---|
| CommandModel | CommandModel |
| Measured | Unavailable |
| Hybrid | CommandModel fallback |

复审时发现初稿会在 A22 返回后追加 `STALE` reason，并修补 state/selection，造成逐拍输出与
`last_reason_mask`、reason counters 不一致。现已删除所有后处理修补：A22 result、status 和
计数保持单一事实源。名义样本的序号跳变/超龄只写适配器自己的
`STALE_OBSERVED/stale_sample_count`，不伪装成已标定质量判定。

输入 flags 冻结为原始码和命令参考必须同时存在；缺任一位、未知位、错误版本/尺寸、非法
模式均 fail-closed。divider-off、原始码越界和所有适配器计数饱和也已有 Host 覆盖。

## 3. A24.4：PC 完整链

`rust/crates/foc-sim/src/phase_voltage_path.rs` 使用同一份
`duty × Vbus - dead-time/device loss` 三路单极桥臂端电压：

1. 原始单极端电压进入相电压传感器，避免负的去共模相电压被 ADC 模型错误裁为 0；
2. 同一份端电压去共模并 Clarke 后进入 PMSM plant；
3. 传感器输出经过 A22 等价的故障/恢复投影和明确的 source selection；
4. V19 输入进入真实 target bridge，锁定当前 Measured 关闭边界；
5. PC-only shadow SMO/PLL 只消费解析后的来源，用于比较来源切换，不改变目标控制路径。

覆盖 CommandModel、Measured、Hybrid 的 baseline、dropout、stale、三拍恢复，并验证 Hybrid
fallback 事件数、来源电压变化和确定性。完整 A22 开路/三相残差检测仍由 C Host 测试负责，
PC harness 不复制第二套全部 C 状态机。

`phase_voltage_sensor.rs` 同时修复 NaN/Inf 故障拍不推进 sequence 的问题；现在故障拍也用
wrapping 序号，后续有效样本可以确定恢复。V19 bridge 既有测试覆盖
`control=0, phase=UINT32_MAX, age=1` 的回绕等式。

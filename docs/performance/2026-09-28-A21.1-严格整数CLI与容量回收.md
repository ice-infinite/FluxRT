# A21.1 严格整数 CLI 与容量回收

## 1. 结论

A21.1 已完成软件侧实现与验收。`applications/main.c` 中 36 个 libc 数字转换调用
（29 个 `strtof`、1 个 `strtol`、4 个 `strtoul`、2 个 `atoi`）已全部替换为无分配、
全 token 校验的十进制整数解析器。Diagnostic + `z` 的 ROM 从 129,952 B 降到
106,416 B，净回收 23,536 B；Flash 余量从 1,120 B 增加到 24,656 B。

这解决的是容量和 CLI 输入确定性，不是运行时实时性验收。本轮没有烧录、没有接串口、
没有启动功率级或电机；V19 + `z` 的完整 ISR WCET 仍须在下一次获得 powered Diagnostic
授权后重新测量。

## 2. 实现边界

新增：

- `applications/foc_shell_parse.h`
- `applications/foc_shell_parse.c`
- `tests/host/test_foc_shell_parse.c`

修改：

- `applications/main.c`：`foc_start`、`foc_math_bench`、`foc_trace` 和 `foc_cfg` 统一使用
  严格解析接口；
- `tests/host/CMakeLists.txt`：增加独立严格告警 Host 测试
  `foc_shell_strict_decimal_parser`。

解析器不依赖 RT-Thread、HAL、locale、堆或 libc 数字转换。它属于 `applications/` 的
Shell/管理输入边界，不进入 FOC ISR，也不改变 Rust ABI、控制算法、电机参数、保护阈值或
构建档能力。

## 3. 固定语法

| 类型 | 接受 | 拒绝 |
|---|---|---|
| 有符号十进制 | `0`、`0012`、`+582`、`-582`、完整 `i32` 边界 | 空值、单独符号、空白、小数、指数、十六进制、NaN/Inf、单位后缀、尾随字符、溢出 |
| 无符号十进制 | `0`、`00042`、完整 `u32` 边界 | `+`/`-` 符号及上述全部非法形式 |
| 单位缩放 | 先完整解析 `i32`，再除以显式正分母 | 分母为 0、部分 token 或非法 token |

解析失败时输出参数保持不变。该规则把源码原注释“Shell 一律用整数输入”变成可测试契约；
过去 `strtof("1.5rpm", ...)` 或 `strtol("582x", ...)` 可能接受前缀，现在会整体拒绝。

## 4. 命令单位保持

| Shell 字段/命令 | 输入整数单位 | 内部结果 |
|---|---|---|
| `foc_start`、`startup`、`minspeed`、`runminspeed` | rpm | rpm 浮点值；允许负数表示反转 |
| `pll_kp`、`pll_ki` | 原配置单位 | 除数 1，保持整数输入语义 |
| `accel` | rpm/s | rpm/s 浮点值 |
| `current`、`aligncurrent`、`trip` | mA | A，除以 1000 |
| `align`、`ramp`、`acquire`、`transition`、`loss` | ms | s，除以 1000 |
| `slide`、`minbemf` | mV | V，除以 1000 |
| `boundary` | mA | A，除以 1000 |
| `runphase`、`acqphase` | mrad | rad，除以 1000 |
| `parkdelay`、`revparkdelay` | 0.001 tick | tick，除以 1000 |
| `util`、`filter`、`pll_acq`、`variance`、`preload`、`support` | permille | 比例，除以 1000 |
| `islew` | mA/s | A/s，除以 1000 |
| `closedloop`、`observe`、`invstage`、`obsdiv`、`confirm` | 无符号整数 | 保持原范围门与 Rust/platform 二次校验 |
| `foc_math_bench repeats`、`foc_trace ... rate` | 无符号整数 | 保持原上下限检查 |
| `observer` | `smo`/`bemf`/`st` 字符串 | 不经过数字解析器 |

负数是否最终有效仍由既有 Rust/platform 配置验证决定。例如反转转速和有符号角度延迟可保留，
本来只允许非负的电流、时间和比例不会因解析器而放宽。

## 5. S1 验证

独立解析器测试覆盖：

- `INT32_MIN/MAX`、`UINT32_MAX` 和相邻溢出值；
- 正负号、前导零和负零；
- 空指针、空 token、空白、小数、指数、十六进制、NaN/Inf、后缀和组合符号；
- `1150 / 1000 = 1.15`、负缩放、分母为 0；
- 所有失败路径不修改输出。

Host 目标使用 GCC `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror`
（MSVC 对应 `/W4 /WX`）。全量 `test.ps1` 结果：

| 测试族 | 结果 |
|---|---:|
| Python profile/simulation | 34/34 PASS |
| Rust `foc-algorithm` | 75/75 PASS |
| Rust `foc-control` | 38/38 PASS |
| Rust `foc-rt-bridge` | 26/26 PASS |
| Rust `foc-sim` | 30/30 PASS |
| Host C/CTest | 18/18 PASS |
| Rustfmt / Clippy / Cortex-M4F CPU 与 CORDIC 静态库 | PASS |

PC 闭环仍输出 `FOC_SIM_PASS`。这些是 S1/S3 软件证据，不代表板端运行通过。

## 6. S2 四档容量结果

四档均用 `build.ps1 -Regenerate -Profile <档位>` 重建，Diagnostic 默认 `z`，其余为 `s`。

| 指标 | Diagnostic + `z` | Calibration + `s` | Identification + `s` | Production + `s` |
|---|---:|---:|---:|---:|
| 修改前 ROM | 129,952 B | 100,840 B | 113,576 B | 98,932 B |
| 修改后 ROM | 106,416 B | 100,840 B | 113,576 B | 99,084 B |
| ROM 变化 | **-23,536 B** | 0 B | 0 B | +152 B |
| 修改后 Flash 余量 | 24,656 B | 30,232 B | 17,496 B | 31,988 B |
| 修改前 RAM | 23,136 B | 13,080 B | 15,552 B | 8,960 B |
| 修改后 RAM | 22,512 B | 13,080 B | 15,552 B | 8,960 B |
| `text/data/bss` | 105260/1156/21356 | 99684/1156/11924 | 112420/1156/14396 | 97928/1156/7804 |

Calibration/Identification 已在编译期裁掉普通 arm/在线调参路径，因此新解析器被链接垃圾回收，
尺寸不变。Production 只保留有符号解析和单位缩放，增加 152 B；这是以严格完整-token语义
替代原单个 `strtol` 路径的明确成本。Diagnostic 三个解析函数实际链接总计约 218 B。

最终 BIN SHA-256：

| 档位 | SHA-256 |
|---|---|
| Diagnostic | `F8C83A9D0635065AF0BD79B3CEA9143FFFAFB891F89FE1A2FDD32A967A0B1B70` |
| Calibration | `73A8F29E9C8C77BAB10E3A6F1823834B960545C8E9223CA96BA4628B97C5879F` |
| Identification | `E5F51DD59E62FCF8B6FD080291E495768AC25F7CBEFACE9EB5B3158EC8EC574B` |
| Production | `ECD7CB1FC25AF70B4E92DE4FDCCB36E42383B04055E60CBE595C322015A53222` |

`arm-none-eabi-nm -S --size-sort` 对四个最终 ELF 均未发现 `_strtod_l`、`strtof`、
`__gethex`、`_vfiprintf_r` 或 mprec 实际符号。map 的 archive cross-reference/discarded
sections 仍可能显示 newlib 成员名，不能把这些候选/丢弃记录误报为最终链接内容。

## 7. 保留边界与下一门

- 没有裁掉 trace、相电压 capture、保护、deadline 或运行诊断；
- 没有改 PWM/ADC、FOC 频率、PI、SMO/PLL、Rev-Up、相电压来源和审批状态；
- 没有烧录，因此板上仍是此前的 Identification S5.2 镜像；
- A21 仍为“进行中”：A21.1 容量门完成，目标板 V19 + `z` 完整 ISR WCET、ADC→ISR/CCR
  延迟、漏拍和 deadline 门尚未完成；
- A22 运行期接入仍须等待 A19 逐板标定和 A20 动态相序/采样窗，不能因 Flash 余量增加而
  提前开放 Measured/Hybrid。

# A7｜24 kHz PWM + 12 kHz 控制多速率仿真设计门

> 后续静态核对 TIM1 后发现：CCR1..3 preload 只在 RCR 分频后的 UEV 装载，
> 因此本报告使用的“12/12 kHz 零延迟、24/12 kHz 一载波拍延迟”不是目标硬件
> 可实现时序。A7 保留为历史设计筛选记录；目标时序与修正结果以 A8 为准。

## 结论

`24 kHz PWM + 12 kHz 控制 + 1 个 PWM 拍输出延迟` 已在 Rust PC 仿真与
MATLAB/Simulink 中按同一时间语义实现，并通过闭环、故障和计数检查；**尚未修改
TIM1/ADC、没有生成新的实机固件、没有烧录或驱动电机**。

候选方案能维持闭环，但没有自动改善控制质量：两套模型的稳态转速波动基本持平，
Iq/Id 跟踪误差都比 12/12 kHz 基线更大。因此本轮只批准进入“目标硬件定时设计”，
不批准把 24/12 kHz 设为默认，也不能据此宣称刺耳声音已经解决。

## 实现边界

```text
每个 PWM 边界（12 kHz 或 24 kHz）
  ├─ 让到期的占空命令生效
  ├─ 每 N 个 PWM 拍执行一次完整控制（N = fpwm / fcontrol）
  ├─ 未执行控制时保持上一份占空
  └─ 用 fpwm 的周期推进平均值逆变器和 PMSM plant
```

- `rust/crates/foc-sim/src/scheduler.rs`：整数分频、占空保持和整 PWM 拍延迟；拒绝
  非整数频率关系，以及“延迟不小于一个控制周期”的单队列不支持配置。
- `foc-sim` 两个入口：默认仍为 12/12 kHz、0 额外延迟；CLI 可显式设置
  `--pwm-hz`、`--control-hz`、`--actuation-delay-pwm-ticks`。
- Host-only 死区补偿新增独立 `pwm_period_s`；PI、Rev-Up、SMO/PLL 仍使用 12 kHz
  控制周期，死区损失和补偿使用真实 PWM 周期。
- Simulink：模型固定步长改为 `pwmTs`，ControllerCore 明确为 `controlTs`，PMSM plant
  为 `pwmTs`；`DutyActuationDelay` 表达输出延迟，plant trace 以零阶保持对齐到控制拍。
- 固件 C ABI 保持 `0x00080000`，目标端默认配置和板上镜像均未改变。

## 下一设计门

下一步只做目标硬件方案设计与静态检查，仍不直接运行电机：

1. 选择路线图方案 A：TIM1 24 kHz，ADC/完整控制每两个载波周期 12 kHz；
2. 明确定义 ADC 注入触发落在哪一个半周期、CCR preload 在哪一个 Update Event 生效；
3. 用定时图证明采样到占空生效延迟与本模型的 1 个 PWM 拍一致；
4. 平台层分别报告 `pwm_frequency_hz` 和 `control_frequency_hz`，停机配置时校验 2:1；
5. 先做交叉构建和示波器 GPIO/ADC/PWM 时序验证，再决定是否进行 2 A 限流空载短测；
6. 实机必须单独测声音、相电流波形、deadline、Fault 和温升。平均值模型不能预测
   开关纹波、结构共振或可听噪声。

当前默认继续保持 12/12 kHz 和 `closed_loop_enable=0`。

# P5.5 H2-5 采集证据绑定与 run 草稿软件门

## 1. 结论

H2-5 的下一项纯软件门已完成 S1：公共时钟采集器现在把 `combined-lines.csv` 与
`dengfoc-angle.csv` 的 SHA-256 写入 `capture.summary.json`；run 草稿生成器再把采集摘要、
合并原始行、角度 CSV、转换后 trace 和单次分析 JSON 全部绑定到同一个 matrix run。

任意一个文件被替换、采集器发送过命令、两个来源没有共享单调时钟、没有 `FLSI_RAW`、没有
AS5600样本、角度时间窗没有覆盖G431输出窗口或分析固件身份不一致，草稿或matrix聚合都会
fail-closed。

该工具只生成 `evidence-bound-unapproved` 草稿，并固定：

```text
parameter_approval=not-granted
target_capability_approval=not-granted
```

## 2. 入口

```powershell
python .\tools\foc_lsi_h2_run_draft.py `
  --project-root . `
  --run-id h2-angle-01 `
  --motor-id <真实电机ID> `
  --firmware-sha256 <真实固件SHA256> `
  --capture-dir .\profiles\identification\captures\h2-angle-01 `
  --trace-csv .\profiles\identification\captures\h2-angle-01\trace.csv `
  --analysis-json .\profiles\identification\reports\h2-angle-01.json `
  --angle-axis 0 `
  --window-padding-s 0.25 `
  --output .\profiles\identification\sessions\h2-angle-01.run-draft.json
```

输出中的 `matrix_run` 可由后续人工评审流程加入总 manifest。生成器不会创建电机阈值、批准
HFI 参数或修改产品 profile，避免在 H2-4 尚未实测时把响应/噪声阈值写死。

## 3. 合同收紧

`fluxrt-lsi-h2-matrix-v1` 的每个 run 现在额外要求：

- `capture_summary_path/sha256`；
- `combined_lines_path/sha256`。

聚合器还会从采集摘要反查 `combined-lines.csv` 和 `dengfoc-angle.csv` 的内部哈希，形成双向
绑定。这样即使外层 run 的哈希被重新计算，替换后的文件仍与冻结采集摘要不一致，不能进入
矩阵。

run 草稿合同位于 `profiles/schema/fluxrt-lsi-h2-run-draft-v1.schema.json`。

## 4. 证据边界

- 本轮只完成工具、合同和合成测试，没有真实 H2 run；
- `window-padding-s` 只是把静态AS5600窗口包住G431缓存输出窗口，不是动态采样时延补偿；
- `FLSI_RAW`串口时刻依旧不是控制拍时刻，H3动态闭环必须另建确定性时间映射；
- H2-3c、H2-4、真实多角度矩阵和H2-6审批仍未完成。

# P5.5 H2-5 多 run 证据聚合软件门

## 1. 结论

H2-5 的多角度/重复性离线聚合器已经完成 S1。它把每个 run 的 G431 trace、单次分析结果和
DengFOC AS5600 静态时间窗绑定为一个不可静默替换的证据项，并且在形成矩阵前逐项拒绝：

- `motor_id` 或固件 SHA 不一致；
- trace、分析 JSON 或角度 CSV 的 SHA-256 不一致；
- G431 trace 控制拍不连续、含硬件故障/软件 trip 或达到矩阵电流门；
- 单次分析没有通过 bounded hardware execution，或错误声称已经批准参数；
- AS5600 时间窗样本不足、序号不连续、`valid!=1`、失败计数非零或转子静止跨度超限；
- 正/负脉冲响应不对称或响应没有显著高于 bias 噪声。

聚合器即使收齐所有角度，也只输出 `screening-complete`，并固定输出：

```text
parameter_approval=not-granted
target_capability_approval=not-granted
```

因此它不能越过 H2-6 审批，也不会访问串口、烧录、arm 或启动 PWM。

## 2. 证据结构

每个 manifest 冻结一个电机和一份固件：

```text
fluxrt-lsi-h2-matrix manifest
├─ motor_id / pole_pairs / firmware_sha256
├─ requirements
│  ├─ minimum_runs / electrical angle bins
│  ├─ AS5600 minimum samples / maximum span counts
│  ├─ maximum phase current
│  └─ positive-negative asymmetry / response-noise gates
└─ runs[]
   ├─ trace CSV path + SHA-256
   ├─ one-shot analysis JSON path + SHA-256
   ├─ capture summary / combined serial lines path + SHA-256
   ├─ AS5600 CSV path + SHA-256
   ├─ common-host angle window start/end
   └─ repeated motor_id + firmware SHA-256
```

JSON 字段合同保存在
`profiles/schema/fluxrt-lsi-h2-matrix-v1.schema.json`；执行器为
`tools/foc_lsi_h2_matrix.py`。

## 3. 时间窗与角度规则

AS5600 CSV 沿用 `tools/dengfoc_angle_capture.py` 的格式。聚合器只取
`angle_window_start_s <= host_time_s <= angle_window_end_s` 且 Axis 匹配的记录，并要求：

1. 至少 `minimum_angle_samples` 个样本；推荐首轮设为 3 或更高；
2. 所有样本 `valid=1`，`read_failures=0`；
3. sequence 每点严格递增，允许 `u32` 回绕；
4. 使用 AS5600 的 4096 count 圆周距离计算静态跨度，推荐最大 2 count；
5. 机械角使用圆均值，乘极对数后映射到电角度 bin，避免 `0/2pi` 附近普通平均出错。

时间字段必须来自同一个主机单调时钟。聚合器只验证已经封装好的时间窗；配套只读协调器
`tools/foc_dual_serial_capture.py` 已完成S1，可以用同一次`time.monotonic_ns()`起点记录两个
COM口。它不发送命令，且只能用于静态H2角度窗口；不能仅凭人工抄写两个不同程序的相对秒数
把 `angle_index_valid` 置为 1，也不能把缓存后输出的G431 trace串口时间当作动态采样时刻。

## 4. 多 run 判据

聚合器从 trace 重新计算，而不是只相信分析 JSON：

- 三相峰值电流；达到门值即拒绝；
- 正/负脉冲内部相邻拍的平均 `|delta Iu|`；
- 正负响应不对称率；
- bias 段 `Iu` 标准差；
- 较弱一侧响应与 bias 噪声的比值；
- 单次拟合 L、RMSE 和最大残差（来自已验证哈希的单次分析 JSON）。

推荐首轮 manifest 使用 6 个电角度 bin、至少 6 个独立 run。具体不对称率和响应/噪声门必须
在 H2-4 首拍取得真实噪声与响应后审批，不在代码中写死。合成测试已证明：6 个不同 bin 可以
把状态推进为 `screening-complete`，但批准位仍保持关闭。

## 5. 使用方式

```powershell
python .\tools\foc_lsi_h2_matrix.py `
  .\profiles\identification\sessions\h2-5-matrix.json `
  --project-root . `
  --json-output .\profiles\identification\reports\h2-5-matrix.json `
  --csv-output .\profiles\identification\reports\h2-5-matrix.csv
```

当前仓库没有伪造一份可运行的真实 manifest，因为 H2-3c/H2-4 尚未完成，也没有新的
G431+AS5600同步采样。待真实文件产生后必须填入实际路径与 SHA，不能用全零占位哈希。

## 6. 验证与剩余项

本轮新增 6 项 Profile 测试，覆盖：

- schema 的身份、哈希和时间窗字段；
- 单 run 只能处于 `collecting`；
- 6 个分散电角度 bin 得到 `screening-complete` 但仍不批准；
- 文件篡改、角度移动/失败、motor 身份错误和达到电流门均 fail-closed。

# P5.3 Advanced Lab 无功率目标探针

## 1. 本轮结论

P5.3 的目标侧软件准备已经达到 S2，但**尚未达到板端 S4**：

- Advanced Lab 现在有独立的无功率目标入口，能在真实 ADC ISR 中执行与正式路径相同的
  Advanced supervisor、预计算 Park、电流环 policy、逆 Park 与调制组合；
- 探针只替换无法在断电静止状态成立的观测器角度、速度和测试参考，不伪造控制器状态，
  也不改写正式 powered 入口；
- 每拍在 Rust 调用前、控制后和 CCR preload 写入后检查 Gate、MOE、CC1～3、Break、
  driver fault、功率安全状态和 `fault_epoch`；任一异常立即失败并锁存故障；
- `foc_advanced_wcet` 支持 Basic、MTPA、弱磁、MTPV、解耦、DPWM、过调制和全组合八种模式；
- PC 参考器使用相同输入运行 36,000 拍，生成仅包含离散策略决策的 FNV-1a 签名；
- Advanced Lab / Diagnostic / Rust `s` 已成功链接，ROM 124,664 B、RAM 23,376 B；
- 源码和生成配置已恢复默认 Basic Drive，默认镜像不含探针或 Advanced 入口符号。

本轮没有连接、烧录或运行开发板，没有给功率级加电，也没有转动电机。因此当前数据不能证明
STM32G431 的真实 WCET、寄存器抢占顺序、控制效果或实机安全性。

## 2. 实现分层

| 层 | 文件 | 职责 |
|---|---|---|
| Rust 固定 ABI | `rust/crates/foc-rt-bridge/src/advanced_abi.rs` | 44 B、版本化、有限值校验的 synthetic control frame |
| Rust 实时入口 | `rust/crates/foc-rt-bridge/src/lib.rs` | 复用正式 advanced/current-loop 组合，只替换可信控制帧与测试参考 |
| 硬件中立安全门 | `foc/include/foc_advanced_probe.h`、`foc/runtime/foc_advanced_probe.c` | 状态机、逐拍计数、safe-off、fault epoch、完成/失败语义 |
| STM32G431 平台 | `foc/platform/stm32g431/foc_platform_stm32g431.c` | ADC ISR 执行、真实寄存器快照、inactive CCR preload、DWT 时序和签名 |
| 平台控制面 | `foc/include/foc_platform_advanced_candidate.h` | stopped-state start/status/finish；不暴露 ISR-owned Rust context |
| Shell | `applications/main.c` | `foc_advanced_wcet [ticks] [mode]`，事务结束恢复 Advanced disabled |
| PC 对拍参考 | `rust/crates/foc-rt-bridge/examples/advanced_probe_reference.rs` | 同输入/同模式生成离散决策签名，不要求浮点 duty 位完全一致 |
| Host 守卫 | `tests/host/test_foc_advanced_probe.c` | 正常完成、安全位、fault epoch、控制失败 fail-closed |

## 3. 模式与输出

| mode | 功能 |
|---:|---|
| 0 | Basic 基线；Advanced feature mask 为 0 |
| 1 | MTPA |
| 2 | Field Weakening |
| 3 | MTPV |
| 4 | dq decoupling/feed-forward |
| 5 | DPWM；仅本次探针事务临时声明重构 capability |
| 6 | Overmodulation；仅本次探针事务临时声明最小脉宽 capability |
| 7 | 当前目标支持的六项全开；不包含仍无目标请求通道的 HFI/Flying Start |

默认命令运行 36,000 拍，即 12 kHz 下 3 s：

```text
foc_advanced_wcet
foc_advanced_wcet 36000 0
...
foc_advanced_wcet 36000 7
```

输出格式：

```text
FADV,m=<mode>,f=<configured>,s=<state>,r=<result>,n=<done>/<requested>,
     sig=<signature>/<samples>,a=<active>,st=<status>,rg=<region>,mod=<mode>,
     wcet=<full ISR cycles>,ctrl=<control cycles>,miss=<deadline misses>
FADV,end,<0=pass>,<finish status>
```

成功门必须同时满足：`s=2`、`r=1`、`n=requested/requested`、签名样本数等于请求拍数、
`miss=0`、没有 basic fallback/fault，并且 `FADV,end,0,0`。模式 0 的 status/active 为 0 是
预期行为。

## 4. PC 参考签名

命令：

```powershell
cd rust
cargo run -p foc-rt-bridge --example advanced_probe_reference --features advanced-foc -- 36000
```

固定输入为 `Vbus=12.3 V`、`Iq*=0.6 A`、电角 `0.35 rad`、机械速度 `150 rad/s`、
上一拍 `Vq=7.3 V` 和三相电流 `0.10/-0.04/-0.06 A`。36,000 拍结果：

| mode | signature | 末拍 active | status | region | modulation |
|---:|---:|---:|---:|---:|---:|
| 0 | `7ec15fc5` | `00` | `00000000` | 0 | 0 |
| 1 | `e8c062c5` | `01` | `00000001` | 1 | 0 |
| 2 | `9fb4c285` | `02` | `00000001` | 2 | 0 |
| 3 | `7ccd02c5` | `04` | `00000001` | 3 | 0 |
| 4 | `399968c5` | `08` | `00000001` | 0 | 0 |
| 5 | `0ae6a005` | `10` | `00000001` | 0 | 1 |
| 6 | `82b70145` | `20` | `00000001` | 0 | 3 |
| 7 | `4a884a05` | `2c` | `00000001` | 3 | 3 |

签名只覆盖 `active_features/region/modulation_mode/status_flags`，避免把 CPU math 与 CORDIC
浮点末位差异误判为控制策略差异。板端签名若不同，必须先定位哪一拍跨过了离散阈值，不能直接
豁免；只有板端八种模式都与该表一致，才能关闭“逐拍策略对拍”子门。

## 5. S1/S2 证据

统一 `test.ps1` 通过：Profile Python 153、Simulation Python 47、Rust workspace 355、
Clippy 0 warning、三组 ARM archive、Host C 52/52及PC闭环仿真全部通过。新增覆盖包括：

- Rust no-power ABI 保持真实 controller startup 状态，并对非法 synthetic 输入清零输出；
- C guard 精确完成 requested ticks，拒绝 Gate/MOE/CCER/fault epoch/控制失败；
- C/Rust 的 44 B probe input ABI 尺寸和版本一致。

Advanced Lab 目标构建：

| 项目 | 值 |
|---|---:|
| 产品组合 / 主构建档 / Rust | Advanced Lab / Diagnostic / `s` |
| ROM | 124,664 / 131,072 B |
| RAM | 23,376 / 32,768 B |
| 运行堆余量 | 9,392 B；高于 9 KiB 硬门 176 B |
| text/data/bss | 123,508 / 1,156 / 22,220 B |
| BIN SHA-256 | `47FDC6A072C21CBAE51FBC44D59FB0933C95559E021FFE5FFE30C61986AAB04D` |
| HEX SHA-256 | `9F352D082C322AD2A6BC67AD39AFAB7425ED2343164B9D52131F305B091B2E77` |

首次链接曾因只剩 8,928 B 堆而被 9 KiB 链接门拒绝。没有放宽门；改为让 Shell 的一次性

新增任何常驻状态都必须重新审计，不能把本次“刚过门”解释成容量宽裕。

## 7. 下一门

P5.3 仍为“进行中”。下一步只做无功率板端 S4：

1. 保持电机主电源断开，确认 Vbus 接近 0、Gate/MOE/CC1～3关闭、无 fault；
2. 烧录本报告 Advanced Lab 哈希对应的镜像并逐一运行 mode 0～7；
3. 每项核对签名、完整 ISR WCET、control WCET和 deadline miss；
4. 任何模式超 12,750 cycles 或签名不符都停止，不进入 powered；
5. 完成后恢复并重烧 Basic Drive，确认 `foc_advanced_wcet` 不存在。

只有上述 S4 完成后，才能讨论 P5.4 的低功率/实机功能验证；S2 构建通过不能授权电机上电。

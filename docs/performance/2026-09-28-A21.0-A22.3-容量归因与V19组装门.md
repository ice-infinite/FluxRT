# A21.0 / A22.3：Diagnostic 容量归因与 V19 组装门

## 1. 本轮结论

- A22.3 已完成纯软件组装层：把 A22.2 平台适配器快照与旧反馈组装为 ABI V19
  `foc_realtime_input_t`，但不接入目标 ISR。
- adapter v1 的 ST 名义换算仍只是诊断量；组装层不会设置
  `FOC_REALTIME_VALID_PHASE_VOLTAGES`，不会把三相毫伏值送进 Rust 观察器。
- `Measured` 仍关闭；`Hybrid` 在名义模型下只能明确回退到 `CommandModel`。
- A21.0 已定位 Diagnostic Flash 的主要膨胀源：不是 Rust，而是 Shell 调参中的
  `strtof()` 拉入 newlib 浮点字符串解析链。
- 本轮只取得 S0～S2 软件/构建证据，没有烧录、串口、PWM 或电机实机操作。

## 2. A22.3 数据流与边界

```text
legacy feedback + control sequence + actual dt + hardware faults
                              |
A22.2 adapter output ---------+--> A22.3 validate/assemble --> V19 snapshot
                                                               |
                                                               +-- 当前未接 ISR
```

新增文件：

- `foc/include/foc_phase_voltage_realtime_input.h`
- `foc/runtime/foc_phase_voltage_realtime_input.c`
- `tests/host/test_foc_phase_voltage_realtime_input.c`

组装器只负责验证、显式映射和快照物化，不拥有 ADC、HAL、RTOS、ISR、观察器或配置状态。
请求模式与实际选择分别运输，禁止依赖枚举数值碰巧相同进行直拷。

### 2.1 接受条件

输入必须同时满足：

1. request、adapter output、quality 的尺寸和版本正确；
2. `actual_dt_s`、三相电流、母线电压等基础反馈有限，且母线电压大于零；
3. 硬件故障、adapter flags、quality reason、phase mask 没有未知位；
4. `quality.requested_mode` 与 request 一致；
5. `quality.sample_sequence == adapter.phase_sequence`；
6. 使用 `uint32_t` 回绕运算满足
   `control_sequence - phase_sequence == phase_voltage_age_ticks`；
7. 请求、实际选择、fallback/unavailable 三者自洽；
8. adapter v1 不含逐板标定证据，因此不得出现 `BOARD_CALIBRATED`、
   `observer_eligible`、`measured_eligible` 或实际选择 `Measured`；
9. 模型和质量必须满足联合不变量：
   - `ST_IHM16M1_NOMINAL` 只能是
     `UNCONFIGURED/UNCONFIGURED` 或 `UNCALIBRATED/UNCALIBRATED`；
   - `NONE` 只能是
     `UNCONFIGURED/UNCONFIGURED` 或 `INVALID_SAMPLE/INVALID_SAMPLE`。

任何条件失败时，返回失败并保持整个 88 B V19 输出为零。

### 2.2 交叉复核发现并关闭的旁路

首版已经拒绝 forged Measured，但只分别检查了 model 和 quality，没有检查二者的联合关系，
调用者可伪造 `ST_NOMINAL + VALID` 或 `NONE + VALID`。它不会直接打开 Measured，却会把
“名义/无模型”错误表述为质量有效，违反 adapter v1 永不产生 calibrated evidence 的契约。

最终实现增加联合不变量校验，并加入以下拒绝用例：

- nominal + `VALID` + reason 0；
- nominal + `VALID` + `RECOVERY_HYSTERESIS`；
- none + `VALID` + reason 0。

所有用例同时检查失败后的 88 B 输出全零。

### 2.3 兼容性与回绕门

- 覆盖同拍、普通 age、`0 - UINT32_MAX == 1`、`1 - UINT32_MAX == 2`；
- age 或 sample sequence 不一致立即拒绝；
- 128 组 faults=0 的 Command/Hybrid-fallback 快照，与
  `foc_realtime_input_from_legacy()` 的基础字段逐拍相等；
- 组装层只叠加 provenance/quality/reason/selection/sequence 元数据，三相电压有效位和值仍关闭。

## 3. A21.0 Diagnostic Flash 归因

### 3.1 四档对比

| 档位 | ROM | RAM | 与 Production ROM 差值 |
|---|---:|---:|---:|
| Diagnostic + `z` | 129,952 B | 23,136 B | +31,020 B |
| Calibration + `s` | 100,840 B | 13,080 B | +1,908 B |
| Identification + `s` | 113,576 B | 15,552 B | +14,644 B |
| Production + `s` | 98,932 B | 8,960 B | 0 B |

Diagnostic 只剩 1,120 B Flash。Rust 静态库在 Diagnostic 与 Production 之间只差约
58 B，不能把当前容量压力归因于“Rust 本身占空间”。

### 3.2 主要膨胀链

`applications/main.c` 的 `foc_cfg` 参数注释宣称使用整数单位以避免浮点文本解析，实际仍有
28 处 `strtof()`；非 Production 的 `foc_start` 另有一处，共29处。它使 Diagnostic 链入约
22,624 B 的 newlib `libc.a` 内容，而 Production 约为 1,701 B、Calibration 约为
2,445 B。

主要符号包括：

| 符号 | 近似大小 |
|---|---:|
| `_vfiprintf_r` | 4,680 B |
| `_strtod_l` | 4,616 B |
| `__gethex` | 1,520 B |
| `mprec` 相关对象合计 | 2,988 B |

这条依赖还会继续带入十进制/十六进制浮点、任意精度辅助和格式化代码。下一步 A21.1 应把
Shell 参数改为**严格整数解析 + 显式单位缩放**，保留全部安全范围检查、`foc_cfg`、trace、
capture 和运行时验证。保守预计可回收约 18～20 KiB ROM，必须用实际 map/size 复核。

该修改会收紧 CLI：旧实现意外接受的小数、NaN/Inf、十六进制或尾随垃圾应变为明确拒绝，
所以必须先冻结每个命令的整数单位和严格解析测试，不能只机械替换函数名。

### 3.3 暂不优先裁剪的内容

| 模块 | 估算 ROM | 估算 RAM | 决策 |
|---|---:|---:|---|
| Diagnostic trace | 3.6～4.5 KiB | 约 8.98 KiB | 保留；是板端相关性与 WCET 证据入口 |
| phase capture | 1.5～2.2 KiB | 约 4.12 KiB | 保留；Calibration 也需要 |
| Rust 控制库差异 | 约 58 B | 不构成主因 | 不为容量问题裁算法 |

链接 map 把约 13,268 B 的合并字符串池归到 `board.c`，这是 GNU ld 合并 section 的归属
显示，不代表 `board.c` 真实新增了同等逻辑。后续归因必须结合 archive/member/symbol，不能
只看单个输出 section 的表面归属。

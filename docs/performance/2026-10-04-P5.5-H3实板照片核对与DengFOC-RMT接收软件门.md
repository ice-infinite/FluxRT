# P5.5-H3 实板照片核对与 DengFOC RMT 接收软件门

## 1. 结论

四张实板照片纠正了首轮资源方案：NUCLEO-G431RB在X-NUCLEO-IHM16M1叠板状态下仍能
接触Morpho排针，PB6/PB7可继续作为发送/回采候选；DengFOC V0.4没有可见GPIO4通用排针，
所以不能按旧候选直接接线。当前DengFOC首选改为**只在Axis1关闭时复用第二路传感器插座
SDA1/GPIO23**。

本轮同时完成独立`dengfoc_usb_time_sync_rx`诊断目标的S1/S2、USB-only S4和双板身份链S4：RMT接收完整身份帧，GPIO
上升沿ISR锁存与AS5600相同的`esp_timer` 1 MHz时间域，完整codec验证后才提交同步事件。
实板已烧录并确认RMT与M0 AS5600均可启动；PB6/CN10-17→IO23和公共GND已在无主电下
完成单帧及连续10帧验证，累计11帧、失败0。没有主电、PWM、driver enable或电机运行，
也尚未取得G431连续全局边沿时间戳，因此属于身份链S4，不属于动态时间映射完成或功率S5。

## 3. 软件分层

| 层 | 实现 | 责任 |
|---|---|---|
| 公共codec | `foc/runtime/foc_time_sync_wire.c` | 20字节身份、CRC、161个codec symbol |
| 板级资源仲裁 | `foc_time_sync_dengfoc_input_resource_valid()` | Axis0必须保留；拒绝PWM/ADC/GPIO12；只允许复用已关闭Axis的I2C脚 |
| 目标绑定 | `targets/esp32_dengfoc/src/time_sync_main.cpp` | GPIO23、RMT、SOF tick、M0 AS5600、串口证据 |
| 默认目标 | 其它PlatformIO环境 | 不编译`time_sync_main.cpp`，不启用同步输入 |

RMT接收端暴露了一个物理层细节：若帧以低电平结束，最后一个data-low会与无限idle合并。
因此平台发送端必须在161个codec symbol后追加10 us高电平结束保护脉冲；接收端严格要求
162个实际symbol，并单独验证保护脉冲。保护脉冲不进入公共20字节包和CRC。

实板首版在`rmt_receive()`返回`ESP_ERR_INVALID_ARG`：经典ESP32的RX毛刺过滤器按80 MHz源
时钟计算，5 us阈值约400个时钟，超过硬件字段范围。诊断目标改用1 us；它仍远小于协议
最短10 us保护高脉冲和20 us数据脉冲。修正后`rmt=1,ready=1`。同时避开该Arduino运行库
`Serial.printf("%llu")`对后续变参的污染，64位tick改由`Serial.print(unsigned long long)`输出。

两板初次接线又暴露两个目标边界。PB6若在CC1启用前切AF，会被IO23所在旧SDA网络上拉，
形成约3 us伪SOF；发送完成若先关闭CC1，保护低电平也会在约3 us后被上拉截断。G431改为
启动成功后才切AF，并在最终下降沿先把PB6接管成GPIO低，再停TIM4。经典ESP32在持续低电平
触发RMT idle threshold时，把最后保护symbol记录为`high=10 us, low=0`，其中0是硬件end marker；
接收端仅在总数162、last-part、guard高宽有效且公共codec/CRC全部通过时接受该目标语义。

## 4. 验证

| 等级 | 检查 | 结果 |
|---|---|---|
| S0 | 照片、当前V0.4源码、ST官方原理图/数据手册及公开DengFOC接线资料交叉核对 | GPIO4降级为逻辑候选；PB6/CN10-17与SDA1/GPIO23成为当前物理候选 |
| S0 | 用户实物插座丝印回报 | `VCC/GND/IO23/IO5/IO21`；当前同步只使用GND与IO23，VCC/IO5/IO21悬空 |
| S1 | `foc_as5600_dengfoc_profile_and_normalization` | PASS；GPIO23仅在Axis1关闭时允许，Axis1开启及PWM/ADC/GPIO12冲突均拒绝 |
| S2 | `platformio run -e dengfoc_usb_time_sync_rx` | PASS；最终Flash 166,587 B，RAM 17,984 B；BIN 166,944 B，SHA-256 `D89CDAB9...2DAB` |
| S4 | COM14明确端口烧录、Hash verify、RTS复位 | PASS；ESP32-D0WD-V3 rev3.1，40 MHz晶振，8 MB Flash |
| S4 | USB-only启动/RMT/AS5600 4 s净窗口采集 | PASS；`resource/encoder/adapter/decoder/rmt/ready=1`；`SYNC_READY`后1,859条完整真值，`valid=1,read_failures=0`；3条状态均0 frame-fail/overflow，driver disabled |
| S4身份链 | PB6/CN10-17→IO23单帧与10帧重复性 | PASS；identity/CRC逐帧匹配，累计11帧、`frame_fail=0`、`truth_fail=0`、`overflow=0` |
| S4动态映射/S5 | G431全局边沿tick、跨时钟残差和电机 | 未执行；当前G431每帧TIM4重置值不能充当全局参考时间；没有12.3 V主电 |

## 5. 后续门

1. G431 TIM4/DMA发送端与DengFOC RMT接收端已完成双板无主电身份链S4；
2. 当前接线只使用公共GND与PB6/CN10-17→IO23；VCC/IO5/IO21悬空；
3. 下一步为G431补连续全局同域边沿tick，优先PB7输入捕获或经验证的硬件锁存；
4. 取得多锚点的双端tick、漏帧、漂移和残差后，才生成H3动态时间映射证据；
5. 本门不授权HFI、PWM、GPIO12拉高或电机运行。

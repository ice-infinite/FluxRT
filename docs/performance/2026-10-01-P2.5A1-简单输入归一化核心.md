# P2.5A1 简单外部输入归一化核心

## 1. 本批结论

P2.5A1 已完成 PWM 脉宽、模拟量和 Step/Dir 的**纯计算核心、固定 C ABI、默认关闭构建门和
Host Fake 输入测试**。本批没有实现 STM32G431 的 Timer/ADC/GPIO 物理采集，也没有把外部
输入接到 `MotorService` 执行链；生成的命令只包含 setpoint，绝不自动 arm。

DShot 没有自行实现。它继续等待许可证清晰、可独立升级的官方或标准维护上游；没有合适
上游时保持关闭。

## 2. 数据链和职责

```text
Timer capture / ADC / Step counter（后续平台驱动）
                    │ raw value + timestamp
                    v
foc-input（Rust no_std纯逻辑）
  校验 → 归一化[-1, 1] → deadband → SI命令映射
                    │ 固定C ABI
                    v
foc_simple_input_adapter（C应用适配）
  InputSample + SETPOINT-only ProductCommand
                    │ 后续P2.5A2
                    v
InputService → CommandService → CommandArbiter → MotorService安全门
```

各层边界：

- `foc-input` 不依赖 RT-Thread、HAL、寄存器或堆；
- `input_abi.rs` 只负责 `#[repr(C)]` 布局、指针/版本/范围检查和错误码；
- `foc_simple_input_adapter` 只生成目标中立输入和 setpoint，不生成 Axis 启停请求；
- C adapter 在任何失败返回前先清零输出 candidate，不能残留上一条可执行命令；
- 物理采集、资源占用和故障健康属于后续平台层；
- arm、状态切换、软限位和最终执行仍只属于 `MotorService`/安全事务。

## 3. 已实现能力

| 能力 | 当前行为 |
|---|---|
| PWM pulse | 支持非对称 min/neutral/max、deadband、反向、越界拒绝 |
| Analog | 与 PWM 共用有界中心量模型，可表达 ADC/电压标定后的物理输入 |
| 命令映射 | `[-1,1]` 映射为 Torque/Velocity/Position 的非对称 SI 限值 |
| Step/Dir | 由累计计数、整步/细分、传动比、方向和零点计算位置 rad |
| 非法输入 | NaN/Inf、坏布局、坏配置、越界或空指针均 fail-closed |
| 安全语义 | 只生成 `SETPOINT`；`axis_request=NONE`、`input_mode=PASSTHROUGH` |
| 编译选择 | PWM、Analog、Step/Dir 三个 Kconfig 均 `default n` |
| DShot | 未实现；等待官方上游选择门 |

当前 ABI V1 布局：centered config 40 B、step/dir config 40 B、输出 28 B。C 头文件使用
静态断言锁定尺寸和 offset。

## 4. 主要落点

| 路径 | 责任 |
|---|---|
| `rust/crates/foc-input/` | no_std 归一化、命令映射和 Step/Dir 换算 |
| `rust/crates/foc-rt-bridge/src/input_abi.rs` | 输入 ABI V1 与 fail-closed 边界 |
| `foc/include/foc_input_bridge.h` | C 固定布局、状态码和函数声明 |
| `applications/foc_simple_input_adapter.*` | C 输入样本到 setpoint-only `ProductCommand` |
| `board/Kconfig`、`custom.cmake` | 三项独立默认关闭 feature 与目标 Rust feature |
| `tests/host/test_foc_input_bridge_layout.c` | C/Rust ABI 布局检查 |
| `tests/host/test_foc_simple_input_adapter.c` | Fake PWM/Analog/Step-Dir、timeout和安全语义 |

同时修复了一个目标构建可见性问题：`foc_external_io.c` 和
`foc_external_io_management.c` 现在都包含 `foc_build_profile.h`。该头在目标侧引入生成的
`rtconfig.h`，使 Kconfig capability 真正进入翻译单元；Host 测试仍可以直接注入宏。修复前，
feature-on 构建会错误地把 capability 编译为 0，并被链接器裁掉输入自检。

## 6. 仍未完成与下一步

P2.5A1 不能被解读为“PWM/模拟量/Step-Dir 已可接线使用”。仍缺：

1. P2.5A2：把三类标定/映射参数纳入版本化配置，设计 V4 迁移且旧记录必须迁移为全关闭；
2. P2.5A2：由唯一低频 owner 把适配结果提交到 `InputService`/`CommandService`，仍不接物理驱动；
3. P2.5A3：STM32G431 Timer capture、ADC 和 Step/Dir GPIO/计数平台驱动及资源事实；
4. P2.5A4：断线、抖动、越界、计数回绕、资源冲突和目标时序/ISR预算；
5. DShot：重新刷新官方候选、许可证和更新边界；没有合格上游则继续延期；
6. 最后才在独立安全门下做无功率输入注入和板端验证，不自动进入 powered 电机测试。

当前下一步是 P2.5A2。配置 schema 不能为了赶进度随意加字段：必须一次冻结三类输入的
标定、SI限值、失效策略和兼容迁移，并保持默认关闭、固定内存和可回滚。

# P4.2E1B 无功率 motion 目标执行门

## 1. 结论

P4.2E1B 已完成软件、Host、目标交叉构建和真实板端无功率门，证据等级达到 S4：

- Diagnostic candidate 现在有一个真实活调用点，能够在 ADC ISR 中执行与目标相同的
  dispatcher、Rust combined realtime、平台输出检查和 CCR preload 提交路径；
- 该入口不能 arm，运行前、combined 后和提交后都会核验 Gate、MOE、CCER、功率安全状态、
  driver fault、Break 与 `fault_epoch`；
- 六个一次性故障点覆盖 configure、combined 和 commit 边界；任一命中都进入 FAILED，
  不能继续提交输出；
- 模式 0/1 分别测量相同平台路径下的基线和强制 motion 参考路径，可用于估算 motion 增量；
- 默认四档仍不编译该入口，默认 Diagnostic map 中没有 motion candidate 符号；
- NUCLEO-G431RB 上 mode 0/1 各完成 1,200 拍，motion 最坏完整 ISR 为
  `12,157 / 12,750 cycles`，`deadline miss=0`；
- 1～6 号注入均在真实 ADC ISR/寄存器路径 fail-closed，最终三相 duty 为 0；
- 板上最后已经恢复为默认关闭候选的 Diagnostic 固件。

本阶段始终断开电机主电源，没有 arm、没有打开 Gate/MOE/CC1～3，也没有让电机转动。
因此它证明的是目标执行、实时预算和无功率关断边界，不证明 powered 闭环控制质量。

## 2. 实现落点

| 层 | 文件 | 职责 |
|---|---|---|
| 硬件中立安全门 | `foc/include/foc_motion_probe.h`、`foc/runtime/foc_motion_probe.c` | 固定状态机、寄存器快照、安全关闭判定、tick计数、fault epoch与一次性注入 |
| Rust combined | `rust/crates/foc-rt-bridge/src/lib.rs`、`motion_abi.rs` | 正常入口保持原启动语义；no-power入口仅为测量强制执行motion参考，再继续旧快环 |
| STM32G431平台 | `foc/platform/stm32g431/foc_platform_stm32g431.c` | 读取真实Gate/MOE/CCER/Break/driver状态，在ADC ISR中执行、测时并做提交前后复核 |
| 目标控制面 | `foc/include/foc_platform_motion_candidate.h` | 只暴露配置、发布、停止、故障、probe和关闭；不暴露ISR-owned Rust context |
| Diagnostic Shell | `applications/main.c` | 提供`foc_motion_wcet`和`foc_motion_inject`，不提供powered start |
| Host验证 | `tests/host/test_foc_motion_probe.c` | 覆盖正常完成、全部安全输出位、fault epoch、combined失败、提交后检查和one-shot语义 |

`foc_platform_control_start()` 在 candidate route 存在时固定拒绝，因此 probe 已配置、命令已发布
也不能通过普通 `foc_start` 上电。probe 只写 TIM1 CCR preload，既不生成 update event，也不打开
Gate、MOE或CC1/2/3。

## 3. 两种测量模式

```text
mode 0: ADC ISR + dispatcher + 普通combined入口 + 平台检查/提交
mode 1: 先按真实生命周期预热12拍，再由no-power combined仅推进motion影子，
        保持正常startup状态与Id/Iq；平台检查/提交仍逐拍执行
```

两次运行应使用相同固件、tick数和停止状态。`ctrl(mode1) - ctrl(mode0)`可作为 motion 增量的
直接估计。`wcet`是各次运行不同采样拍的最大值，二者相减只能作为保守参考，不能当作严格的
同拍差分。

Shell输出格式：

```text
FMWCET,m=<mode>,s=<state>,r=<result>,n=<executed>/<requested>,
       c=<no-power commits>,inj=<count>,wcet=<full ISR>,
       ctrl=<control section>,miss=<deadline misses>
```

正常完成必须同时满足：`s=3`、`r=1`、`n=requested/requested`、`c=requested`、`miss=0`。

mode 1 的诊断入口不会把 Alignment 人为改成 ClosedLoop，也不会把测试 motion Id/Iq 注入正常
启动控制器；正式 powered combined 入口没有这项诊断隔离。motion 外环到期拍固定保持上一份
已验证 PWM，新 Id/Iq 从下一拍生效，因此每 12 拍有一拍 83.3 us 的确定性参考延迟，换取
外环与逆 Park/SVPWM 不在同拍叠加。

## 4. 故障注入矩阵

| 编号 | 注入点 | 预期 |
|---:|---|---|
| 1 | configure发布route之前 | 配置拒绝，route不能可达 |
| 2 | configure发布route之后 | 二次安全检查发现epoch变化并撤销route |
| 3 | combined之前 | 当拍不调用Rust、不提交CCR，进入FAILED |
| 4 | combined执行期间 | 模拟高优先级Break；Rust返回后、commit前由epoch门拒绝 |
| 5 | commit之前 | 不写CCR，进入FAILED |
| 6 | commit之后 | 提交后复核发现变化，立即安全关断并进入FAILED |

每个编号都是one-shot。每一项必须在独立清故障/恢复后执行；不能在sticky fault未清时把下一项
失败误判成对应注入点通过。

## 6. S4板端证据

### 6.1 条件与镜像

- 板卡：NUCLEO-G431RB / STM32G431RBT6，ST-LINK V3J9M3，探针
  `00400027544B500120343637`，COM6 115200；
- 供电：仅开发板 USB/3.3 V，电机主电源断开；母线 ADC 为 0～26 mV 噪声；
- candidate：第5.2节哈希，STM32CubeProgrammer v2.19.0 download/verify/reset PASS；
- 测试全程 `foc_stop`，不调用 powered start。

### 6.2 正常路径

| 模式 | 结果 | 完整ISR WCET | control WCET | deadline miss |
|---:|---|---:|---:|---:|
| 0 | `s=3,r=1,n=1200/1200,c=1200` | 11,275 | 10,708 | 0 |
| 1 | `s=3,r=1,n=1200/1200,c=1200` | 12,157 | 11,590 | 0 |

两次独立运行的最坏值差为882 cycles，只能作为隔离增量估计。mode 1 距12,750 cycles还剩
593 cycles，即4.65%；已过硬截止线，但余量仍偏紧，后续不能在该时隙无审计地继续加功能。

### 6.3 故障注入

| 点 | 板端结果 | 最终安全状态 |
|---:|---|---|
| 1 | `FMWCET,start,4` | fault锁存，`duty=0/0/0` |
| 2 | `FMWCET,start,4` | fault锁存，`duty=0/0/0` |
| 3 | `s=4,r=5,n=0,c=0,inj=1` | fault锁存，`duty=0/0/0` |
| 4 | `s=4,r=4,n=0,c=0,inj=1` | fault锁存，`duty=0/0/0` |
| 5 | `s=4,r=5,n=0,c=0,inj=1` | fault锁存，`duty=0/0/0` |
| 6 | `s=4,r=4,n=0,c=0,inj=1` | fault锁存，`duty=0/0/0` |

每项前都做独立硬件复位并重新确认 disabled、fault=0、duty=0和母线低于100 mV，避免用
上一项sticky fault伪造下一项结果。点4/6的`r=4`代表寄存器safe-off复核拒绝，点3/5的
`r=5`代表fault epoch变化拒绝；两类都属于预期fail-closed。

### 6.4 测试中发现并关闭的问题

1. command写入0.8 A却漏设`CURRENT_LIMIT`位，Rust按契约拒绝；已补有效位。
2. 物理0 V不能用于SVPWM归一化；probe仅给算法注入已验证的标称母线，真实ADC/安全门仍读0 V，
   且计算结果从不提交到有功输出。
3. 64项trace挤占候选堆，Finsh线程创建失败；candidate专用trace缩为16项，普通Diagnostic仍64项。
4. 首次force motion暴露1 KiB异常主栈溢出：`CFSR=0x8200`、`BFAR=0xFFFFFFDC`，PC落在
   RT-Thread defunct链回收；SWD同时确认MOE=0、CCR1/2/3=0、Gate=0。candidate专用主栈改为
   4 KiB，普通构建仍1 KiB，HardFault消失。
5. 重复配置校验/多层状态复制和同拍外环+电流环导致超期；保留每拍命令/反馈门与外层整事务影子，
   内层走已验证实时路径，并用1/12固定PWM保持槽把外环输出延后一拍，最终达到第6.2节结果。

### 6.5 默认固件恢复

最终默认Diagnostic已烧录、verify/reset PASS。串口确认：`FSTAT,disabled`、`FOC st=0`、
`rf=0`、`duty=0/0/0`、`FFAULT=0`、Vbus=0 mV；调用`foc_motion_wcet`返回
`command not found`，证明板上候选入口已移除。

## 7. 未关闭风险与下一阶段

- 4.65%是通过而非宽裕；正式powered闭环还必须重新测 observer + motion + current-loop 的真实峰值；
- no-power入口刻意隔离motion，不证明Torque/Velocity/Position的控制质量或切换无扰；
- 主电源断开，未验证真实转矩、电流、速度、编码器/Hall或传感器less反馈精度；
- 电机磁链口径仍有约6.91倍歧义，必须用物理反电势测量审批，不能用本门替代；
- candidate容量仍接近Flash上限，不应直接演化成产品常驻镜像。

下一阶段是P4.2E2逐模式低功率验证方案评审与仿真准备；重新接通电机电源前必须重新确认
限流、空载/机械状态、急停手段和参数审批，不能因E1B通过而自动进入powered。

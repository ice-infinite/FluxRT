# P4.2E1 单写者 dispatcher 与 combined realtime

## 1. 结论

P4.2E1 已完成**软件结构与目标静态接线**，但尚未完成板端无功率 WCET：

- 管理线程只发布固定快照和一次性 STOP/FAULT 请求；ADC ISR 是 Rust motion 状态的唯一写者；
- motion planner、cascade 与原有 FOC 快环通过一次 `foc_rust_realtime_step_with_motion()` 完成，
  不再使用 C 侧双 FFI 拼接；
- Break、`fault_epoch`、占空比校验和最终 CCR commit 门保持在 C 平台层；
- Kconfig 默认仍为 `n`，运行路由 BSS 初值为 0，Production 不携带 motion Rust feature；
- Diagnostic candidate `s` 已成功链接，ROM 119,780 B、RAM 23,520 B；
- 当前没有 boot/Shell/management 活调用点，configure/publish 控制面会被链接回收，所以还不能
  启用 motion、测真实 combined WCET 或运行电机。

证据等级为 S1/S2；没有烧录、上电、PWM 输出或电机运行。

## 2. 已落位的职责

| 层 | 文件 | 职责 |
|---|---|---|
| C 交接 | `foc_motion_dispatcher.c/.h` | 单 task 发布、双槽快照、ADC IRQ 临界提交、one-shot STOP/FAULT |
| C 平台 | `foc_platform_motion_candidate.h`、`foc_platform_stm32g431.c` | stopped-state 配置、ISR 单调用、C 安全关断与最终 commit |
| Rust ABI | `motion_abi.rs`、`lib.rs` | 136 B request、64 B output、时间/序列/位置新鲜度、事务提交 |
| Rust 控制 | `controller.rs`、`motion.rs`、`motion_cascade.rs` | 当拍反馈、分频外环、保持 Id/Iq、一次三角函数事务、原电流 PI/SVPWM |
| 验证 | `test_foc_motion_dispatcher.c` 与 Rust tests | 无撕裂、回绕、非法发布不推进、urgent 优先、combined 顺序和回滚 |

combined 顺序固定为：硬件故障镜像 → 输入/时间门 → 当拍反馈/observer → motion 分频执行或
保持上次 Id/Iq → current PI/SVPWM → C 侧输出范围与 `fault_epoch` 复核 → CCR commit。

## 3. 并发与失败语义

- `active_slot` 和 urgent 字段是 volatile 单字；task 只写 inactive slot，屏蔽 ADC1_2 IRQ 后
  只提交索引。Break IRQ 不被屏蔽。
- FAULT 强于 STOP；两者被 ISR 消费后即清。consume 之后任何异常或 FFI 未执行都必须故障关断。
- route 已选择却没有命令时不再回退旧速度环，而是清零输出并锁 motion fault。
- `control_start` 在 route 开启但首条命令尚未发布时拒绝 arm。
- STOP 正常关断且不增加 realtime error；FAULT 和 combined 错误进入 sticky fault。
- 任意平台故障都会立即撤销 motion route 和 command-ready，避免 motion 已 disable 但 API 仍报告
  enabled。

这些结论依赖单核、单 task publisher、单 ADC ISR consumer，以及临界回调确实屏蔽 ADC1_2
并提供 compiler/hardware ordering。

## 4. 配置一致性门

configure 现在必须同时提供 active `foc_config_bundle_t`、已配置的
`foc_runtime_config_t`、相同的非零 bundle revision 和外环分频。平台在进入 Rust 前核对：

- ABI/结构尺寸与 revision；
- 实际 PWM/control 频率；
- pole pairs、Rs、Ld/Lq、磁链、连续电流；
- Id/Iq PI Kp/Ki 与 12 kHz `ts`。

这是一道精确 enable gate，不做容差匹配。任何独立舍入或旧副本必须先由配置事务统一，不能把
两套参数分别交给 motion 与基础 FOC。

configure 还记录初始 `fault_epoch`，提交 route 时二次检查 disabled/fault-free；Break/fault
路径本身也会撤销 route，因此配置过程中发生故障不会留下可运行的 motion 所有权。

## 5. 容量问题与修复

首次保活真实 combined consumer 后，问题才暴露：

| 构建 | ROM | 结果 |
|---|---:|---|
| candidate `s`，初版 | 144,076 B | 超 128 KiB 13,004 B |
| candidate `z`，初版 | 141,132 B | 超 10,060 B |
| candidate `z`，去除浮点格式化链 | 117,276 B | 链接通过；这是最终安全加固前的容量对照 |
| candidate `s`，最终安全加固 | 119,780 B | 链接通过，ROM 91.38%，余 11,292 B |

反汇编证明唯一的 `f32 Debug` 引用来自动态 `f32::clamp()` 的非法上下界 panic 分支。它把
`flt2dec/format_shortest/format_exact` 一整套浮点格式化链带入固件。motion 热路径改用配置已
验证前提下的无 panic `clamp_symmetric()`；NaN 仍保留并由既有 finite-output 门拒绝。最终 ELF
中上述浮点格式化符号为 0。

combined 入口反汇编栈帧为 368 B：20 B 首次 push + 16 B 高寄存器保存 + 332 B 局部区。该值
是静态反汇编证据，不包含上层 ISR 其它局部量和嵌套中断栈，不能冒充整条中断栈上界。

  fmt/Clippy/M4F CPU/CORDIC、C Host 26/26 全部 PASS；

  urgent one-shot、零 fault detail 和位置时间戳；

  `7C7369AC2C060468E342497FBFB2D67EA7466CBBCF4E188F775B01A888466C69`；

  默认 ELF 无 motion 符号。

## 7. 尚未完成与下一步

P4.2E1 不能标记为完整完成，剩余子阶段定义为 **P4.2E1B 无功率目标执行门**：

1. 增加 Diagnostic-only、不能 arm 的配置/发布测量入口，使 control plane 在 candidate 镜像中
   被真实保活；不得直接复用普通 `foc_start`；
2. 加寄存器模型/目标故障注入：configure 各点、combined 前/中/commit 前插入 Break；
3. 验证 route-on + NO_COMMAND、过期/未来/倒序命令和陈旧 position 均不提交 CCR；
4. 测 isolated motion delta 和 command+feedback+motion+FOC+验证+commit 完整 ISR WCET；
5. 只有完整 ISR 小于 12,750 cycles 且保留阶段余量，才讨论 P4.2E2 Torque→Velocity→Position
   的逐模式受限实机门。

# P5.5-H1：DengFOC功率执行器无主电软件门

## 1. 目标

在不接12 V、不烧录、不运行电机的条件下，为DengFOC ESP32平台补齐PWM、ADC和驱动使能的
隔离执行器骨架。该阶段只证明软件结构和目标编译，不授权GPIO12拉高或任何功率输出。

## 2. 架构落点

硬件无关安全事务位于：

- `foc/platform/esp32_dengfoc/foc_dengfoc_power_stage.h`
- `foc/platform/esp32_dengfoc/foc_dengfoc_power_stage.c`

Arduino薄绑定位于：

- `targets/esp32_dengfoc/src/dengfoc_arduino_power_port.h`
- `targets/esp32_dengfoc/src/dengfoc_arduino_power_port.cpp`

状态顺序固定为：

```text
RESET -> SAFE_DISABLED -> PWM_READY -> ARMED
                    \                 |
                     -> FAULT_LATCHED <-
```

执行器具备以下约束：

- 初始化首先关闭GPIO12；初始化不配置LEDC；
- PWM准备必须在driver disabled下完成，并先写三相0 count再读回；
- ADC引脚、PWM引脚、30 kHz/8 bit参数均来自板级profile；
- `allow_actuation=0`时，`arm`不能调用driver enable；
- arm要求PWM读回为0、fault epoch匹配且驱动仍关闭；
- duty必须在0～255内，序号必须逐拍递增，每次写后读回；
- duty越界、序号/epoch错误或任何回调失败都先关GPIO12、清零PWM并锁存故障；
- 普通`shutdown`不能清除`FAULT_LATCHED`，只能显式`clear_fault`恢复到安全态。

目标诊断程序将policy和Arduino端二次许可都固定为禁止：

```text
powerPolicy.allow_actuation = 0
runtimeActuationPermitted = false
```

同时具备两道门的目的，是防止将来只改一处配置就意外开放GPIO12。

## 4. 证据边界

- 最终镜像已在用户确认USB-only后完成烧录和串口回读；全程没有接通12 V、没有调用
  `prepare`、没有配置真实LEDC，也没有输出PWM；
- Arduino薄绑定已能配置普通LEDC 30 kHz/8 bit，但还没有证明三路载波相位、ADC采样触发点或
  电流采样与PWM中心同步；
- `ledcRead()`只证明外设配置读回，不是示波器波形、栅极状态或相端电压真值；
- 当前没有已知电流源，电流A/count和极性仍只使用参考工程名义值；
- 该软件门不能升级H2，也不能称为DengFOC功率平台已完成。

## 5. USB-only默认关闭S4

用户确认只接USB、12 V断开后，最终镜像已烧录到COM13对应的ESP32-D0WD-V3 rev3.1。
独立硬复位启动回读：

```text
driver_enable_gpio=12,disabled=1
power_stage_init=1,state=1,allow_actuation=0,pwm_configured=0
axis0_init=1
axis0_adc_zero=1
```

ADC 1000点A/B均值1859.304/1859.829 count，名义噪声3.429/3.737 mA。随后12 s共239帧
角度遥测全部有效，I2C失败0、FATAL 0。该结果关闭默认安全启动与持续关断S4，但仍未配置
LEDC，也没有波形或功率证据。

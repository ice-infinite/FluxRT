# A17 相电压只读采样与 12 kHz 固定窗

## 1. 结论

A17 已把 X-NUCLEO-IHM16M1 的三路 BEMF 网络接入 STM32G431 Diagnostic 固件，形成
一个**只记录 ADC 原始码、不会进入控制律**的 256 拍固定窗。板上完成了无功率采集：
256/256 样本连续、控制步数为 0、输出保持关闭，结束后 `IO_BEMF` 恢复禁用。

这一步只证明信号链、ADC 序列、固定缓冲和安全互斥可工作。它没有证明 ADC 原始码已
换算成电机端电压，也没有执行电压阶跃、RL 辨识、闭环运行或相序动态验证。

## 2. 硬件依据

- [X-NUCLEO-IHM16M1 官方原理图](https://www.st.com/resource/en/schematic_pack/x-nucleo-ihm16m1_schematic.pdf)
  给出 `BEMF1/2/3` 的 10 kΩ/2.2 kΩ 分压与保护网络，并把 U/V/W BEMF 映射到
  PC0/PC3/PC1；PC9 是 `IO_BEMF` 控制端。
- [STM32G431RB 官方数据手册](https://www.st.com/resource/en/datasheet/stm32g431rb.pdf)
  给出 PC0/PC1/PC3 的 `ADC12_IN6/IN7/IN9` 复用。
- 本地 ST MCSDK 6.4.1 参考工程 `P-IHM03-Potentiometer` 的 FOC `.ioc` 没有启用这三路
  BEMF ADC。因此本工程沿用其电流采样方案，但相电压采集是 FluxRT 独立增加的诊断能力。

当前 Diagnostic 注入序列为：

| ADC | Rank | 信号 | 引脚/通道 |
|---|---:|---|---|
| ADC1 | 1 | U 相电流 | 原有通道 |
| ADC1 | 2 | U 相 BEMF | PC0 / IN6 |
| ADC1 | 3 | V 相 BEMF | PC3 / IN9 |
| ADC1 | 4 | W 相 BEMF | PC1 / IN7 |
| ADC2 | 1 | V 相电流 | 原有通道 |

电流的硬件采样触发时刻没有改变，但 Diagnostic ISR 要等 ADC1 后续三个转换完成才收到
JEOS，因此运行态 WCET 和采样到控制计算的延迟必须在有功率测试前重新测量。Production
仍保留原来的一 rank 电流采样路径。

## 3. 代码职责

| 层 | 文件 | 职责 |
|---|---|---|
| 通用固定缓冲 | `foc/include/foc_phase_voltage_capture.h`、`foc/runtime/foc_phase_voltage_capture.c` | 256 个固定样本；ISR 单写，停止后线程读取；不分配、不覆盖 |
| STM32G431 平台 | `foc/platform/stm32g431/foc_platform_stm32g431.c` | GPIO/ADC 注入序列、PC9 使能、ISR 原始码入窗、启停互斥 |
| 平台接口 | `foc/include/foc_platform.h` | Diagnostic-only start/stop/status/pop 契约和能力位 |
| 应用 | `applications/main.c` | `foc_phase_capture` Shell 命令，只做管理和 CSV 文本导出 |
| PC 采集 | `simulation/capture_phase_voltage_window.py` | 强制停机、采集、连续性校验、CSV/日志落盘、finally 再停机 |

每个样本 16 B，容量 256，共 4096 B；12 kHz 下窗口长约 21.33 ms。母线字段是慢速监控
ADC 的最近值，不与三相注入采样严格同步，所以命名为 `bus_last_raw`。

安全约束：

1. 只有 Diagnostic 构建实例化缓冲和命令；Production 返回未配置且不占这 4 KiB RAM；
2. 只有功率级未 arm、控制步数不运行且同步监控已启动时才能 arm；
3. 采集处于 armed 状态时，`foc_platform_control_start()` 拒绝启动电机；
4. PC9 默认拉高禁用，开始短窗时拉低，完成、停止或异常退出时恢复拉高；
5. 原始码没有 `valid`/校准结论，不能送入 Rust 观察器或标记
   `actual_phase_voltage_measured=true`。

## 4. 使用方式

板端命令：

```text
foc_phase_capture start
foc_phase_capture status
foc_phase_capture dump
foc_phase_capture stop
```

推荐由脚本执行，脚本会在前后都发送 `foc_stop`：

```powershell
python simulation/capture_phase_voltage_window.py `
  --port COM6 `
  --output profiles/identification/evidence/<session-id>/phase_voltage_raw.csv
```

不要在电机运行时手工开启，不要把 `FPV` 原始码直接乘一个理论分压比后用于控制。

## 7. A16 追溯修正

A17 构建覆盖了 `cmake-build/fluxrt.bin`，暴露出 A16 session 曾把历史固件哈希指向可变
构建路径。现有目录找不到 SHA-256 为 `175CD0D3...9A5FC9` 的旧 BIN，因此没有伪造归档：

- A16 保留当时记录的固件哈希；
- `firmware_image_path` 改为 `null`；
- 分析报告增加 `firmware_image_archived=false` 和“旧固件不可重新校验”阻断项；
- 后续 session 必须把固件复制到不可变 evidence 目录再写哈希，不能引用构建输出目录。

这不会改变 A16 的 `screening-only` 结论，反而使 revision 2 的拒绝理由更完整。

## 8. 下一步门槛

下一步不是立刻把原始值送入闭环，而是依次完成：

1. 静态多点标定三路 ADC 偏置、增益和分压网络，记录板卡与温度；
2. 用示波器同时观察相端、分压端、ADC 触发和 PWM，确定可用采样窗；
3. 在不开启闭环的受限工况下采动态短窗，确认 U/V/W 相序、饱和和开路判据；
4. 测量新增三次 ADC 转换后的完整 ISR WCET；
5. 只有校准、有效性和回退测试通过后，才扩展快速输入 ABI 并研究
   `CommandModel/Measured/Hybrid`；
6. 独立角度/速度真值仍是磁链与观察器验收的前置条件。

# CM4.2 接管支撑与速度 PI 预装解耦

## 1. 结论

CM4.2 已完成启动超调的第一轮受限整改：

- 根因不是单纯的强拖电流、角度渐变时长或 Iq 限速，而是一个配置字段同时控制
  “维持无感可观测性的接管转矩”和“速度 PI 积分预装”；
- ABI V15/config V9 将两者拆成 `handoff_torque_support_ratio` 与
  `speed_pi_preload_ratio`，Production 默认仍为 `0/0`，审批位仍为 0；
- 最终 Diagnostic 候选保持 0.28 A 接管支撑（`0.8 A × 0.35`），只把速度 PI
  预装降为 `0.15 × 0.28 A ≈ 0.042 A`；
- 候选完成 3/3 次 10 s 冷启动和 1 次 30 s 闭环，均为 0 error / 0 deadline miss /
  0 fault；30 s 实机观察器峰值为 722 rpm，旧 CM4.1 为 894 rpm；
- PC 真值峰值从 840.4 rpm 降为 710.5 rpm，过冲从 44.4% 降为 22.1%。

这是约 12.3 V、2 A 限流、单板单电机、空载正转的 S5 证据。实机没有编码器或
独立测速仪，722 rpm 是观察器估计，不是转速真值。

## 2. 为什么必须拆开

旧字段 `speed_pi_preload_ratio=0.35` 同时产生：

```text
接管电流终点 = 0.8 A × 0.35 = 0.28 A
速度 PI 预装 = 0.28 A × 0.35 ≈ 0.098 A
```

实机消融表明：

| 候选 | 结果 | 结论 |
|---|---|---|
| 支撑降为 0.16 A | 获取失败或接管后 BEMF 塌陷 | 不能用减小支撑来换低过冲 |
| 确认门 10→5 ms | 短暂接管后 BEMF 0.059 V、持续失锁停机 | 不能放宽可靠性门绕过 |
| 支撑约 0.24～0.26 A | 2/3 或首轮失败 | 低于 0.28 A 的重复性不足 |
| 角度渐变 50→10 ms | 首轮接管后失锁 | 角度融合仍需要 50 ms |
| PI preload=0，支撑仍 0.28 A | 首轮峰值 658 rpm，但第二轮掉到约 409 rpm 后失锁 | PI 完全从零也缺少重复性 |
| 支撑 0.28 A，PI preload=0.15 | 3/3 冷启动 + 30 s PASS | 当前最小稳健候选 |

因此“支撑”和“PI 预装”必须是两个独立旋钮，不能再用同一个比例碰运气。

## 3. 实现与安全边界

| 层 | 修改 |
|---|---|
| `foc-control/startup.rs` | 角度融合与电流下降不再强制同进度；已有 Iq slew 可让电流提前到终点，但不晚于角度融合结束 |
| `foc-rt-bridge` | 新增独立 `handoff_torque_support_ratio`；`speed_pi_preload_ratio` 只预装 PI；ABI V15/config V9，配置 288 B |
| C ABI/Application | 同步结构尺寸、CRC 与 `foc_cfg support/preload`；运行中仍拒绝改参 |
| `foc-sim` | PC CLI 分成 `--handoff-support-ratio` 与 `--speed-preload-ratio`；新增对齐/升速/强拖电流入口 |
| 采集脚本 | 同步两个独立参数和现有停机态 `foc_cfg current` |
| Production profile | revision 2，runtime CRC `54F9828D`，record CRC `97850826`；approvals 仍为 0 |

Diagnostic 固件 ROM 130,600/131,072 B（99.64%），RAM 23,104/32,768 B（70.51%）。
Flash 只剩 472 B，后续诊断能力不能继续无界加入该构建档。

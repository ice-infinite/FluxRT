# EXP-B3 S4.5：C 执行契约静态门

## 1. 结论

S4.5 已把同步 raw、板级标定、Rust 注入计划、CCR 量化和下一控制拍账本组合成一个
Identification-only 的 C 执行契约，并通过 Host、全回归、四档目标构建和链接隔离。
固定窗到达 256 点时，目标 ISR 现在也会立即走 C 快速关断，不再只有 contract/storage
错误才关断。

本门仍然**没有**把 `WRITE_PRELOAD` 决策接到 TIM1 CCR，没有状态机运行会话、栅极/MOE
使能或 `foc_lsi_start`。启动期只用真实板级换算常量执行一组 BIAS→OFF 合成对账，自检
全程不写寄存器。因此结论只到 S1/S2；本轮未烧录、未上主电源、未运行电机，S5 仍禁止。

板上固件没有变化，仍是 S4.3 Identification：BIN
`4BA420C62DEB09B6DD90EE88849AAD4744F548DD5475D4142AA0BEEC5979B4D9`。

## 2. 分层和单拍顺序

```text
应用状态机输出（数值映射由 Host _Static_assert 锁定）
  OFF / BIAS / +PULSE / -PULSE
                    + capture ready/full/error + hardware fault/trip
                                      │
同步 raw：U/V ADC、Vbus ADC、当前 CCR1/2/3、ARR、flags
                                      │
                                      ▼
foc_lsi_executor_step()              C runtime，无 HAL/寄存器
  1. 任意 fault/error 先返回 SAFE
  2. 校验 raw 量程、ADC valid、compare<=period
  3. 若有上一拍计划，先对 control_tick + CCR + pulse flags
  4. raw→A/V（板级 offset、counts/A、V/count）
  5. 调用 foc_rust_lsi_plan()
  6. 复核 status/finite/duty/source/expected tick
  7. duty→CCR 四舍五入并建立下一拍 ledger
                                      │
                                      ▼
  SAFE 或 WRITE_PRELOAD(compare U/V/W)
  （仍是未施加决策；尚无 TIM1 writer/start）
```

平台保持唯一寄存器所有者。executor 只返回决策记录，不能开栅极，也不能证明 TIM1
preload shadow 已在物理 update event 后生效。

## 3. 新增契约

- `foc_lsi_executor_config_t`（48 B）：12 kHz、ARR、ADC 上限、1 tick 延迟、U/V offset、
  counts/A、V/count 和 3%～97% 平台 duty 窗；
- `foc_lsi_executor_command_t`（44 B）：四种状态请求、capture ready/full/error、硬件 fault、
  软件 trip 和 bias/扰动请求；
- `foc_lsi_executor_t`：保存板级/算法配置和**至多一项**待核对 ledger；
- `foc_lsi_executor_output_t`：只返回 `SAFE` 或 `WRITE_PRELOAD`，同时保存换算后的 A/V、
  Rust plan、CCR 和 ledger 结果。

下一拍对账同时要求：

1. `control_tick == expected_active_control_tick`；
2. U/V/W compare 与上一拍量化值逐项一致；
3. `DRIVE_ACTIVE` 已置位；
4. `+PULSE/-PULSE` flag 与上一拍请求极性一致，BIAS 不得带 pulse flag。

任一不一致返回 `HARDWARE_FAULT + SAFE` 并清除 pending ledger，不沿用旧占空比。

## 4. Fail-closed 矩阵

| 条件 | executor 结果 | 调用方义务 |
|---|---|---|
| 合法 active + raw/capture/plan 全通过 | `WRITE_PRELOAD` | 仍须在写寄存器前复核硬件；当前没有调用者 |
| 合法 OFF | `SAFE_REQUESTED` | 保持/执行快速关断 |
| capture 未就绪 | `NOT_CONFIGURED + SAFE` | 不得写 CCR |
| 256 点窗满 | `DISABLED + SAFE` | 同拍快速关断；目标 ISR 已实现 |
| capture error、raw fault bit、break/trip 镜像 | `HARDWARE_FAULT + SAFE` | 同拍快速关断并锁存原因 |
| ADC/compare/period 非法 | `HARDWARE_FAULT + SAFE` | 同上 |
| tick/CCR/极性账本不一致 | `HARDWARE_FAULT + SAFE` | 同上；不能用请求值冒充应用值 |
| 未知枚举、NaN、版本/尺寸、Rust 非 OK/越界输出 | 非 OK + `SAFE` | 拒绝本拍 |

固定窗正常完成不设置 `LSI_CAPTURE_ERROR`，但仍立即关断；contract/storage 失败既关断又
锁存错误位。这样“正常停止”和“证据损坏”可以区分，同时二者都不会继续输出。

## 5. 验证证据

### S1/S3

- 最终 `test.ps1`：profile 140、simulation 7、Rust `75+38+21+17`、PC 闭环、fmt、
  Clippy、CPU/CORDIC target 和 C Host **13/13** 全通过；
- 新 Host 用例覆盖 raw→A/V、duty→CCR、BIAS→OFF 成功账本、pulse flag 缺失、窗口满、
  capture error、raw fault bit、compare>period、capture 未就绪、planner 越界和非法频率；
- 应用状态枚举到 ABI 枚举继续逐项 `_Static_assert`，Shell 不能提交任意 duty。

## 6. 未完成与下一门

2. 平台在每次 `WRITE_PRELOAD` 前最终复核并写 TIM1 CCR1/2/3；
3. Identification 独立 arm token、MOE/CCER/栅极的唯一安全开启路径；
4. powered 状态下 active/shadow compare 与 ADC 采样相位的板端证明；
5. 新路径完整 ISR WCET、0.2 A 电流包络和任意退出复位。

下一步定义为 **S4.6 私有会话协调器与物理 preload sink 的静态安全门**：先做独立代码
复核、fake-register Host 测试和 S2，仍不暴露 Shell start。只有这条实际寄存器链和无功率
S4 复核都通过，才单独设计一次性确认的 `foc_lsi_start` 并向用户请求 0.2 A S5 授权。

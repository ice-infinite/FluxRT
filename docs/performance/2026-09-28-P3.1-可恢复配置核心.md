# P3.1 可恢复配置核心验证报告

## 1. 范围与结论

本轮在 `foc-control` 新增 Host/目标均可编译但尚未接入目标运行路径的配置核心：六组
`ConfigBundle`、512 B A/B 槽、双 CRC、最后提交标记、candidate/approved/active、
V0→V1迁移、自动与显式回滚、factory fallback 和最终 arm identity/calibration 门。

产品契约仍为 V1，bridge ABI 仍为 V20，V19 快环输入、12/12 kHz、现有运行配置和默认
闭环状态均未修改。完整语义见[可恢复配置核心 V1](../可恢复配置核心V1.md)。

## 2. 核心安全性质

| 性质 | 实现 |
|---|---|
| 半份记录不可用 | `CMIT` 固定在槽末尾且最后写，缺任一字节即拒绝 |
| 记录完整性 | payload CRC + 覆盖header/payload的record CRC |
| 保留已知良好版本 | approved 总写另一槽，commit前继续选择旧active |
| candidate隔离 | candidate可恢复/查看，但启动只选择approved |
| 自动回退 | 最新approved坏CRC时选择另一槽旧approved |
| 显式回滚 | 旧approved以新sequence重写，重启后继续生效 |
| 版本兼容 | V0在RAM迁移并标记需重存；未知schema/storage拒绝 |
| 身份与标定 | header/payload ID一致；arm再匹配实板/电机和反馈标定 |
| 序号回绕 | u32半区间比较；相同/半区间歧义拒绝猜测 |

## 4. 证据边界

- 纯配置逻辑不拥有 Flash、RTOS、ISR、C ABI、active runtime 或 GUI；
- 未烧录、未连接串口、未使能 PWM、未运行电机；
- Host 掉电枚举不是目标 Flash 擦写粒度、供电跌落或磨损寿命实测；
- P3.2 负责事务状态机，后续平台阶段才允许在 Safe/Disabled 下接 Flash 适配器；
- factory/reference/candidate 均不自动获得电机参数审批，A26限制保持不变。
- 本轮达到S1/S2；没有新增S3仿真契约场景，也没有执行S4～S6硬件验证。

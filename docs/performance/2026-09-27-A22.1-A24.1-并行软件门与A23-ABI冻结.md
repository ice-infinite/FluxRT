# A22.1 / A24.1 并行软件门与 A23 ABI 冻结

## 1. 结论

本轮把不依赖硬件且写入区互不冲突的工作拆成三路同时执行，并由主线统一集成：

- A22.1：完成相电压质量状态、恢复滞回及来源回退的纯 C 核心；
- A23：完成版本化物理量输入 ABI 的只读审计和布局冻结，尚未修改 V18；
- A24.1：完成 13 个相电压非理想/故障场景的确定性 PC 矩阵。

定向测试、全套 `test.ps1` 和四构建档重新生成/交叉构建均通过。没有连接串口、烧录、
使能功率级或运行电机；默认观察器仍只允许 `CommandModel`。

## 2. A22.1 质量与回退契约

新增 `foc_phase_voltage_quality.h/.c`，它不访问 HAL、RTOS、ADC 或 PWM，只接收已整理的
样本和命令侧参考。状态覆盖：

```text
UNCONFIGURED / UNCALIBRATED / VALID / STALE / OPEN_SUSPECT
LOW_SATURATION / HIGH_SATURATION / THREE_PHASE_INCONSISTENT / INVALID_SAMPLE
```

来源请求和实际选择被明确分开：

| 请求模式 | 数据健康 | 实际选择 |
|---|---:|---|
| CommandModel | 任意 | CommandModel |
| Measured | 是 | Measured |
| Measured | 否 | Unavailable，调用方必须 fail-closed |
| Hybrid | 是 | Measured |
| Hybrid | 否/恢复滞回中 | CommandModel |

实现记录逐原因计数、fallback/unavailable 样本和事件数、恢复次数；样本年龄超限或序号不连续
判为 stale。饱和、开路、不一致与恢复均有进入/释放或连续确认门。三相一致性使用
`U-V / V-W / W-U` 线电压残差，因此共同模偏置不会被误报为三相不一致。

这些阈值只是 Host 契约输入，不是已批准的板级阈值。模块已参与四档目标编译，但没有实例化
状态，也没有接入目标 ISR 或 Rust 观察器。

## 3. A24.1 故障场景矩阵

`analyze_phase_voltage_fault_scenarios.py` 固化 13 个场景：baseline、offset、gain、
quantization、delay、stale、dropout、low/high saturation、open suspicion、三相不一致、
unconfigured、uncalibrated。

输出使用严格 JSON，明确标记：

- host-only；
- 阈值不是 production-approved；
- Hybrid 的速度/工况准入门在本矩阵中被假设为已满足；
- 正常非理想样本保留 Measured 候选；所有坏数据按上表确定性回退或不可用。

A24 JSON 为了保留场景名称使用 `dropout`；进入 A22/C ABI 时它规范化为
`INVALID_SAMPLE + INVALID_SAMPLE reason`，不新增第四种运行期含义。

证据文件：

`profiles/identification/evidence/phase-voltage-20260927/a24_fault_scenario_matrix.json`

本阶段只是来源选择和故障语义，不等于完整 Rust plant 仿真或 MATLAB 独立公式对拍，因此
A24 仍是进行中。

## 4. A23 版本化快速输入冻结

审计结论是不能原地扩展 20 B、无版本字段的 `foc_feedback_t`。它继续服务旧的
`foc_rust_fast_step()`；实时入口下一步新增完整 `foc_realtime_input_t`，并把 ABI V18 提升
到 V19。config V11 暂不变化，因为目标运行配置仍不开放 Measured/Hybrid。

冻结的 V1 布局如下：

```c
typedef struct
{
    uint32_t struct_size;                       /* 0  */
    uint32_t version;                           /* 4  */
    uint32_t control_sequence;                  /* 8  */
    uint32_t valid_flags;                       /* 12 */
    uint32_t hardware_fault_flags;              /* 16 */
    uint32_t phase_voltage_sequence;            /* 20 */
    uint32_t phase_voltage_age_ticks;           /* 24 */
    uint32_t phase_voltage_provenance;           /* 28 */
    uint32_t phase_voltage_quality_state;        /* 32 */
    uint32_t phase_voltage_reason_mask;          /* 36 */
    uint32_t observer_voltage_selection;         /* 40 */
    uint32_t phase_voltage_fallback_event_count; /* 44 */
    float actual_dt_s;                          /* 48 */
    float phase_current_a;                      /* 52 */
    float phase_current_b;                      /* 56 */
    float phase_current_c;                      /* 60 */
    float dc_bus_voltage;                       /* 64 */
    float phase_voltage_a_v;                    /* 68 */
    float phase_voltage_b_v;                    /* 72 */
    float phase_voltage_c_v;                    /* 76 */
    float electrical_angle_rad;                 /* 80 */
    float sensor_temperature_c;                 /* 84 */
} foc_realtime_input_t;                         /* size=88, align=4 */
```

`valid_flags` 冻结为：三相电流、Vbus、三相相电压、外部电角度、温度五个整体有效位。未知位
拒绝；相电压不能按单相零散进入观察器。provenance 沿用 `NONE=0 / ST nominal=1 /
BOARD_CALIBRATED=2`，只有逐板标定来源和 A22 有效状态同时成立，才允许 Measured。

A22 内部阈值、raw、开路/恢复内部计数和逐原因数组不跨 ABI；跨 ABI 只传稳定状态、原因位、
实际选择、序号、年龄和 fallback 事件数。硬件故障使用独立稳定镜像，不直接暴露会继续增长的
平台诊断位域。

迁移顺序：先新增 V19 快照和 legacy→CommandModel 初始化辅助函数，证明默认路径与 V18
逐拍一致；再接 A22 输出；最后在 A19/A20/A21 硬件门完成后才开放 Measured/Hybrid。

## 5. 验证

| 等级 | 命令/对象 | 结果 |
|---|---|---|
| S1 | A22 独立 GCC，`-Wconversion -Wsign-conversion -Werror` | PASS |
| S1 | `python -m unittest discover -s tests/simulation -p test_*.py` | 31/31 PASS |
| S1/S2 | `test.ps1` | profile 140、simulation 31、Rust 75+38+21+17、C Host 15/15 PASS |
| S2 | 四档 `build.ps1 -Regenerate -RustOptLevel s` | 全部 PASS，新质量源均在 compile DB |
| S4～S6 | 烧录、实机、故障注入、独立真值 | 未执行 |

目标固件体积保持：Diagnostic 130,912 B、Calibration 100,328 B、Identification
113,104 B、Production 98,420 B。质量模块尚无目标调用者，因此被链接垃圾回收；这不能用来
估计未来接入 ISR 后的 ROM、RAM 或 WCET。

第一次四档检查误用了 `-BuildOnly`；它不会在 `SConscript` 修改后重新生成 CMake 源清单。
主线通过 compile DB 发现四档都没列出新源，随后改用 `-Regenerate` 完整重建并确认新源实际
参与编译。前一次结果不作为本阶段交叉构建证据。

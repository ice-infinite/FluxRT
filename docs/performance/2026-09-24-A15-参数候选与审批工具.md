## 1. 结论

A15 把 A14 的手写常量变成了可复核候选流程，但没有改变固件参数和审批状态：

- revision 1 的全部 60 个 ABI 字段已经保存为 JSON；
- Python 标准库工具按 C ABI 顺序编码 `u32/f32`，复算得到 runtime CRC
  `0x8C7A8DF4` 和 record CRC `0xD9F996C3`；
- 审批必须绑定同一 runtime CRC，并具备工程内证据文件、类别和 SHA-256；
- 闭环审批依赖参数审批，审批状态必须与 `closed_loop_enable` 完全一致；
- 生成物默认不进入构建，工具不能自动改源码或自动批准；
- 当前仍是 `approval_flags=0`、`closed_loop_enable=0`。

## 3. 关键安全门

工具拒绝以下情况：

- 字段缺失、多余、类型错误、非有限浮点或 ABI 版本/尺寸不匹配；
- 参数变化后仍使用旧 runtime CRC 或 record CRC；
- 未审批但携带 reviewer、审批时间、绑定 CRC 或证据；
- 审批 CRC 与当前 runtime 配置不一致；
- 证据缺少规定类别、文件不存在、SHA-256 不一致或路径逃出工程；
- 闭环越级审批，或 `closed_loop_enable` 与审批不一致；
- 已跟踪 `.inc` 与候选重新生成的内容不一致。

CRC 仍不防恶意修改；若有人同时修改候选、证据和哈希，工具无法提供数字签名级身份。

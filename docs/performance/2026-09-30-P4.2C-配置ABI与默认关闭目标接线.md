# P4.2C 配置、ABI与默认关闭目标接线

## 1. 结论

P4.2C软件架构门完成：P4.2A参考规划器和P4.2B级联控制器现在共享一条正式的
`ConfigBundle -> MotionRuntimeConfig`映射，并通过独立V1 motion ABI和目标中立C适配器暴露。
配置、启用、逐拍执行明确分离；新能力仍默认关闭，没有接入现有ADC ISR或电流环消费者。

本阶段达到S1/S2，不包含板端WCET、烧录、上电或电机运行。

## 2. 配置与迁移

配置schema由V1升级到V2，payload由316 B增至340 B；512 B双槽、header、CRC和最后commit
协议不变。`AxisConfig`新增：

- `motion_control_enabled`；
- `torque_ramp_rate_nm_s`；
- `velocity_ramp_rate_rad_s2`；
- `position_filter_bandwidth_rad_s`；
- `trajectory_acceleration_rad_s2`；
- `trajectory_deceleration_rad_s2`。

关闭配置要求五个参数全为零；启用配置要求全部有限且大于零，并要求有效Position P和
Velocity PI。V0/V1记录都可读，迁移后的六个字段固定为关闭/零，防止固件升级后自动启用。
motion字段的配置事务仍属于Axis组，apply class为`AxisRestart`。

唯一运行配置映射为：

```text
dt = 1 / control_frequency_hz
Imax = min(motor.continuous_current_a, inverter.maximum_phase_current_a)
Kt = 1.5 * pole_pairs * flux_linkage_v_s
Tmax = Kt * Imax
```

`Kt`明确是基础SPMSM路径。MTPA/IPMSM凸极转矩不得无版本地塞入该公式。

## 3. ABI与C适配

配置管理ABI由V1升级为V2：`foc_config_axis_t`为68 B，`foc_config_bundle_t`为348 B；实时
bridge V20和V19逐拍输入未改。新的motion子ABI保持独立版本：

- `foc_rust_motion_init/configure/enable/disable`属于管理面；
- `foc_rust_motion_step`接收既有104 B `foc_product_command_t`、32 B motion反馈，输出64 B；
- planner和cascade在本地副本上运行，只有两者都成功才提交完整上下文；
- 任一错误都保留旧状态并返回Inactive、`Id=Iq=0`安全输出；
- C适配器初始化只配置、不使能；换配置和使能都要求Axis Disabled、输出关闭、无活动故障。

## 4. 默认关闭和目标边界

- Cargo `motion-control`默认关闭；
- Kconfig `FOC_MOTION_CONTROL_CANDIDATE`默认`n`；
- 仅Diagnostic候选把Rust feature传给Cargo；
- 非Diagnostic即使遗留Kconfig开关也不传Rust feature，C侧只编译无Rust引用的关闭桩；
- 本阶段没有注册RT-Thread线程/Shell，没有静态motion owner，没有改ISR，也没有把输出送到
  既有CurrentLoop。

临时Diagnostic候选构建中，Rust archive导出全部8个`foc_rust_motion_*`符号，C adapter成功
交叉编译；因尚无应用层owner，链接器只保留ABI查询片段并GC未调用的init/configure/step，
这是当前默认关闭边界，不是运行期可用证明。

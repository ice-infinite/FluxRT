# P5.5 H2-4 首拍软件包络门

## 1. 结论

H2-4 的软件前置包络已经落实到实际执行链，不再只存在于文档：Identification 应用状态机、
Rust 注入计划器配置和 STM32G431 目标启动前检查共同限制首拍候选为：

| 项目 | 上限/配置 |
|---|---:|
| DC bias 电流请求 | `0.20 A` |
| 扰动电压绝对值 | `0.10 V` |
| 软件电流跳闸 | `0.25 A`，达到边界即失败关闭 |
| 母线窗口 | `7.0～18.0 V` |
| 最大主动窗口 | `600`控制拍（50 ms） |
| 总超时 | `6000`控制拍（500 ms） |

本门只达到S1/S2：没有烧录新镜像、没有接主电源、没有arm、没有PWM输出，也没有电机动作。
H2-3c仍因缺少可调限流电源延期，`HARDWARE_FAST_SHUTDOWN`能力仍为0；因此本结果不授权
H2-4实机首拍。

## 2. 执行链

```text
Identification management H2 envelope
  0.20 A bias / 0.10 V perturbation / 0.25 A trip
                 │  only-tighten mapping
                 v
Rust foc-control LSI planner ABI
                 │  request and measured-current checks
                 v
C executor + next-tick ledger + private preload sink
                 │  target start-time equality check
                 v
STM32G431 TIM1 platform owner
```

- `applications/foc_lsi_management.*`拥有H2 commissioning参数，不把它当Production参数；
- only-tighten映射拒绝比H2更宽的sequence，也拒绝底层Rust包络比请求更窄时静默钳位；
- Rust计划器在`|Iphase| >= 0.25 A`时返回fault，在`|Vperturb| > 0.10 V`时拒绝请求；
- C状态机同样把“达到电流门”定义为`>=`，避免刚好等于阈值时继续一拍；
- G431启动前再次要求executor中实际保存的bias、扰动、trip和母线窗口逐项等于应用sequence；
- 任一不一致返回`FOC_STATUS_NOT_CONFIGURED`，不会尝试打开功率输出。

Rust内部仍保留EXP-B3通用上限`0.4 V / 1.15 A`，但它不是G431 H2镜像的生效值。目标平台
必须先把通用配置收紧到本H2包络，收紧失败即启动自检失败。这样后续其它辨识实验可以使用
各自独立审批包络，而不会通过修改一个全局默认值意外放宽H2。

## 4. 剩余门

1. 取得可设置`5.0 V / 0.20 A`的可调限流电源，完成H2-3c STSPIN830自产生UVLO fault；
2. H2-3c通过后仍需重新评审接线、电机锁定、12.3 V/2 A限流和急停条件；
3. 烧录时必须记录本报告中的候选哈希或重新构建后的新哈希，不能把旧镜像当成已收紧版本；
4. 首拍只执行一次；任何电流门、Break、deadline、采样序号或硬件状态异常均自动关闭，
   不提高阈值、不自动重试；
5. H2-5重复性、角度索引和Rust/MATLAB误差表仍需要真实采集数据。

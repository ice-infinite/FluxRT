# P2.5A2 输入配置与服务接线

## 1. 结论

P2.5A2 已完成软件门：PWM pulse、Analog、Step/Dir 的标定和 SI 映射参数进入同一份
`ExternalIoConfig` 持久化事务；C/Rust 配置 ABI 升级为 V4；旧 V3 记录迁移时保留
transport/link 配置，但由于没有输入标定字段，所有 simple input 必须关闭。应用组合根现已把
`InputService` 与唯一 `CommandService -> Rust CommandArbiter` 路径接通。

本批没有物理 Timer/ADC/GPIO 驱动，没有连接 MotorService，没有自动 Axis 请求，没有烧录，
也没有电机或功率级操作。目标板 capability 仍为 0，默认 Kconfig 仍关闭。

## 2. 持久化结构

`ExternalIoConfig` 从 V1/296 B 升为 V2/384 B，新增 88 B `SimpleInputConfig`：

| 分组 | 大小 | 字段 |
|---|---:|---|
| header | 8 B | `struct_size`、`version` |
| PWM | 24 B | raw min/neutral/max、deadband、正负 SI 限值 |
| Analog | 24 B | raw min/neutral/max、deadband、正负 SI 限值 |
| Step/Dir | 32 B | full steps/rev、microsteps、gear ratio、direction、zero count/position、最大 step rate |

控制模式、source、priority、permissions、lease、command timeout 和 failure action 继续使用既有
`ExternalInputConfig`。只有启用的输入才要求有效标定；Step/Dir 只能映射到 Position。

## 3. Schema V4 与迁移

| schema | payload | commit offset | 迁移规则 |
|---|---:|---:|---|
| V0 | 284 B | 508 | motion 与 External I/O 默认关闭 |
| V1 | 316 B | 508 | motion 与 External I/O 默认关闭 |
| V2 | 340 B | 508 | 保留 motion，External I/O 默认关闭 |
| V3 | 636 B | 764 | 保留 transport/link；simple input 全关闭并补 V2 配置头 |
| V4 | 724 B | 764 | 当前完整配置 |

768 B 槽中 header 为 40 B、末尾 commit 为 4 B，因此最大 payload 正好是 724 B。V4 已无
保留空间；下一次增加持久化字段前必须扩大槽、拆分版本化存储或重构编码，不能继续在当前
payload 后追加。

## 4. 服务数据流

```text
未来物理采集(A3)
  -> foc-input Rust 归一化
  -> foc_simple_input_adapter（InputSample + SETPOINT-only ProductCommand）
  -> foc_external_io_management_submit_simple_input
       -> InputService.publish
       -> CommandService.submit
       -> Rust CommandArbiter
  -X-> MotorService / Axis request / PWM register
```

管理层支持注入 capability 的初始化入口，供 Host/HIL 和后续板级端口复用。配置应用先在
`InputService` 副本上校验，再配置 CommandService，成功后才替换 active input state。poll
会更新输入 timeout/expired 状态并继续调用原有只读 command owner。A4 才实现 failure action
到 Release/ControlledStop/Hold 的完整状态机。

## 5. 验证证据

| 等级 | 验证 | 结果 |
|---|---|---|
| S1 | 统一回归Rust全feature tests | 75 + 133 + 8 + 55 + 39 全部通过 |
| S1 | Rustfmt、workspace Clippy `-D warnings` | 通过 |
| S1 | C Host CTest | 41/41 通过 |
| S1 | V3 迁移、V4掉电写入点、坏标定、Step/Dir模式、service submit/timeout | 通过 |
| S2 | Cortex-M4F `external-inputs` release | 通过 |
| S2 | 三输入 feature-on 目标构建 | ROM 126,484 B，RAM 28,104 B，BIN `42917922...DB816` |
| S2 | 恢复默认关闭目标构建 | ROM 111,548 B，RAM 22,472 B，BIN `24D51F7...DA029`；相关符号 0 |
| S3～S6 | 仿真、烧录、板端输入、功率与电机 | 未执行 |

feature-on 构建只证明源文件、ABI 和目标链接可以组合，不证明输入引脚或运行时功能可用。
未被实际调用的提交函数可被链接器回收；A3 物理 driver 接入后必须重新做 map 和活调用检查。
统一回归首轮发现motion feature测试的手工bundle漏填新增`external_io`字段；补为规范默认值后
全套回归通过，说明定向默认feature测试不能替代组合feature门。

# P5.5 H2-5 公共时钟双串口采集软件门

## 1. 结论

已完成 G431 与 DengFOC 的只读双串口协调采集器 S1。两个 reader 在串口均打开后，共享同一
次 `time.monotonic_ns()` 起点；每条完整串口行记录主机单调时间、来源和来源内序号。工具没有
串口写入路径，不发送 arm、start、PWM 或参数命令。

该结果让 H2-3c 暂时延期时仍能继续完善证据链，但不改变任何硬件能力位，也不把尚未执行的
真实采集写成通过。

## 2. 入口与产物

入口：`tools/foc_dual_serial_capture.py`

```powershell
python .\tools\foc_dual_serial_capture.py `
  --g431-port COMx --g431-baud 115200 `
  --dengfoc-port COMy --dengfoc-baud 115200 `
  --duration 15 `
  --output .\tmp\h2-common-clock-capture
```

输出目录包含：

- `combined-lines.csv`：两个来源按公共主机时间排序的原始完整行；
- `dengfoc-angle.csv`：沿用 H2 matrix 可读取的 AS5600 CSV 字段；
- `capture.summary.json`：端口、波特率、公共时钟、行数、解析样本数和错误。

采集器还把前两个CSV的SHA-256反向写入摘要，后续run草稿和matrix聚合器会再次核验，防止
文件被替换后只重算外层哈希。

JSON 合同为 `profiles/schema/fluxrt-dual-serial-capture-v1.schema.json`。摘要始终固定：

```text
read_only=true
commands_sent=0
parameter_approval=not-granted
target_capability_approval=not-granted
```

任一 reader 出错时状态为 `capture-failed`，不允许静默产出成功证据。

## 3. 证据边界

本工具只解决 H2 静态锁转子场景的公共主机时间关联。G431 的 `FLSI_RAW` 是缓存后输出，
串口时间不是控制拍的真实采样时刻；因此摘要明确固定
`dynamic_alignment_valid=false`。静态 H2 中转子应保持不动，可以用采集前后持续的 AS5600
窗口证明角度没有变化；进入 H3 动态闭环前必须使用 MCU 同步采样、触发线或其他确定性时钟
映射，不能复用本工具声称动态相位对齐。

本轮没有打开真实串口、烧录、发送命令、使能功率级或转动电机。

## 4. 自动验证

Profile 单元测试覆盖：

- 相同 COM 口、无效时长拒绝；
- 双来源只读采集和正常关闭；
- 单一公共 `monotonic_ns` 起点及 H2 静态窗口标记；
- AS5600 输出兼容 H2 matrix 输入；
- reader 错误 fail-closed；
- 源码不存在串口 `.write()`、LSI start 或 capture arm 命令。

# P5.5-H3 同步边沿事件 ABI 与双平台采集适配软件门

## 1. 结论

本轮完成了 H3 动态真值链的目标中立同步边沿事件 ABI、固定容量 SPSC 采集核心，以及
STM32G431 和 DengFOC/ESP32 两个薄适配器。Host 回归、G431 Identification 交叉构建和
DengFOC 默认只读角度目标构建均通过。

这仍是 **S1/S2 软件门**，不是物理同步证据。当前没有选择 GPIO、没有安装边沿 ISR、没有
烧录，也没有把任何 sensorless 平台能力位置 1。

## 2. 为什么不能只记录“第几个脉冲”

若两块 MCU 都从 0 开始给收到的脉冲计数，其中一端漏掉一个周期后，后续本地计数仍可能
形成看似连续、实际错位的一一配对。对于周期同步脉冲，这种错位甚至可能被仿射拟合的截距
吸收，产生危险的假通过。

因此 `foc_time_sync_edge_identity_t` 强制携带：

- 非零 `session_id`；
- `edge_sequence`；
- 非零 `edge_tag`；
- `RISING_EDGE | IDENTITY_VERIFIED` 两个标志。

`IDENTITY_VERIFIED` 不是公共层自己授予的能力。后续板级实现必须用能识别边沿身份的外部
机制产生该输入；普通 GPIO 周期脉冲加本地计数不能直接设置它。身份、会话或序号不一致时，
本次采集立即锁为 `FAILED`，不能继续生成 H3 批准证据。

## 3. 固定布局与存储语义

| 对象 | 固定内容 |
|---|---|
| `foc_time_sync_edge_identity_t` | 24 B，版本、session、sequence、tag、flags |
| `foc_time_sync_event_t` | 40 B，身份字段、来源、本地 64 bit tick 的高低字、G431控制拍、flags |
| `foc_time_sync_status_t` | 48 B，状态、失败原因、下一序号、记录/未读/溢出/拒绝/端口错误计数 |
| `foc_time_sync_capture_t` | 16 槽固定容量；无堆分配；ISR 单生产者、线程单消费者 |

生产者先写完整事件，再以 release 语义发布 `write_count`；消费者以 acquire 语义读取并在
复制后发布 `read_count`。队列满时不覆盖最旧事件，而是增加 `overflow_count` 并锁存
`QUEUE_FULL`。运行中的 capture 不能被静默重新 arm；必须先停止或进入失败态，再显式建立
新 session。

## 4. 平台职责

公共层 `foc/runtime/foc_time_sync.c` 不包含 HAL、寄存器、GPIO、Arduino 或 ESP-IDF 类型。

- STM32G431 薄适配器要求平台同时提供本地自由运行 tick 和当前 12 kHz 控制拍；
- DengFOC 薄适配器只提供本地 tick，事件的 `control_tick` 固定为
  `FOC_TIME_SYNC_NO_CONTROL_TICK`；
- AS5600 角度仍是独立真值流，不在边沿 ISR 内做 I2C 读取；
- 两端平台都只接收已经验证的边沿身份，不能自行把普通中断标成可信锚点。

## 5. 故障语义

以下条件均 fail closed：

1. ABI 尺寸或版本错误；
2. 缺少已验证身份标志、tag/session 为 0 或出现未知 flag；
3. session、sequence 或 source 不匹配；
4. 本地 tick 或 G431 控制拍读取失败；
5. 固定队列已满；
6. capture 正在运行时再次 arm。

失败后的旧事件仍可由消费者导出，便于诊断；但状态保持 `FAILED`，不得被离线工具解释成
完整有效 run。

## 7. 尚未授予的能力与下一步

当前只完成“公共事件格式和采集容器”。以下仍未完成：

- 两板可用 GPIO/定时器输入捕获资源核对；
- 可检测漏边沿的物理身份编码或旁路身份绑定方案；
- 两端真实 ISR 时间戳与固定容量事件导出；
- 事件导出文件与 `foc_h3_time_map.py` manifest/hash 的闭环绑定；
- 目标板 S4 同步残差、漂移和回绕测量。

下一步先做**只读原理图/引脚/定时器资源核对和身份传输设计**。在方案能证明漏边沿不会静默
错配之前，不安装 GPIO，不烧录，不把 UART 到达时间当同步锚点，也不进入 H3 powered 测试。

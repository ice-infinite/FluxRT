# P2.6A FluxRT Native 帧核心

日期：2026-10-01
证据等级：S0协议契约 + S1 Rust/Python/C Host + S2 Cortex-M4F交叉构建
硬件状态：未烧录、未连接新transport、未运行电机

## 1. 结论

FluxRT Native 的第一层已经形成可复用、固定内存的Rust `no_std`核心：V1固定头、消息编号、
节点/Axis寻址、CRC-32C、严格校验、最大256 B payload和有界字节流重同步均已实现。C侧只有
292 B message/316 B decoder ABI，不复制协议算法；Kconfig默认关闭，选中codec也不产生板级
UART/USB/CAN capability，不提交命令、不接MotorService。

实现中曾短暂形成C版codec；审查现有架构后发现它违背“纯协议逻辑归Rust、C只做transport”
的既定职责，因此在本批次结束前完全移除，最终工程只有Rust单一协议实现和C ABI。

## 4. 边界和下一步

- 当前只完成frame envelope，不宣称发现/状态/参数/命令payload已经可互操作；
- 既有64 B transport packet不能直接承载280 B逻辑帧，P2.6B/C必须定义流适配和CAN分片；
- `ProductCommand`只锁定104 B规范payload长度，禁止直接透传C/Rust struct；
- 下一步P2.6B先冻结只读Identity/Capabilities/Status及CommandResult payload，再实现Fake
  Native service；仍不接物理驱动、不烧录。

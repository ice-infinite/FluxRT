## 1. 结论

核心约 9,800 cycles 的归属（4 拍，稳定值）：

| 分段 | cycles | 占 core | 占 12,750 预算 |
|---|---:|---:|---:|
| **尾部事务**（参考选择、指令处理、遥测快照、输出构造） | **约 4,119** | **41.9%** | 32.3% |
| **显式电流环段**（`mark_startup` → 返回） | **约 4,296** | 43.7% | 33.7% |
| 启动时序 sequencer | 826 | 8.4% | 6.5% |
| 观测器块 | 340 | 3.5% | 2.7% |
| 状态门 + Clarke | 255 | 2.6% | 2.0% |
| **合计** | **9,836** | 100% | — |

**单拍总账**（tick 1）：`total 17,852 = control 17,335 + 前后 517`，其中 `chain 7,499`、`core 9,836`。

### 最反直觉的两项

1. **观测器只要 340 cycles。** 这是整个启动链里被讨论最多、调参最多的部分，却只占核心的 3.5%、整帧的 2.7%。**它不是瓶颈。**
2. **显式电流环与"其余尾部"各占约一半（4,296 与 4,119）。** 也就是说，**削减空间的一半不在电流环里，而在它周围的每拍事务中**。

### 对裁剪的含义

| 目标 | 量级 | 风险 |
|---|---:|---|
| 尾部事务（参考选择/遥测/输出构造） | ~4,100 | **待细分**——需再插桩才知道哪一块可省 |
| 显式电流环段 | ~4,300 | 真正的控制律，风险最高 |
| sequencer + 观测器 + 门 | ~1,420 | 合计仅 14%，且观测器已很便宜 |

**约 4,800 的缺口无法只靠链侧（上限约 2,000）补齐**（见 `2026-10-07-P5.5传感链内部归属.md`），而核心的 9,836 里真正属于"控制律"的只有约 4,300。**下一刀应落在尾部事务上，而不是控制律上。**

## 2. 测量方法

`foc_rust_realtime_step_core` 增加第 6 个可选参数：

```rust
#[cfg(feature = "sensorless-foc")] timing: Option<&mut CoreTiming>,
```

- **所有生产调用方传 `None`**，编译器因此完全消除全部标记（`if timing.is_some()` 在 `None` 下是死代码）；
- 只有复合探针路径传 `Some`；
- 三个边界：Clarke 之后、观测器块之后、`startup.update` 之后；
- 在**三个 `return`/尾部点**统一汇总（该 tick 只经过其中一个）。

结果经 `FocSensorlessRealtimeOutput` 的 4 个新字段导出（116 → 132 B），平台 RAM 缓冲扩为 14 列 × 128 拍，由 `foc_sensorless_wcet_decomp` 在 **ISR 外**输出。

**ISR 内无任何打印**（`AGENTS.md` 第 8 条）。

### 原始数据

```text
FSLS,m=3,p=3,r=5,n=128/36000,sig=25e26bc5/128,wcet=17898,ctrl=17380,miss=1
FSLD 字段序: idx,total,control,chain,separator,hfi,fusion,
             abi_prepare,abi_checks,abi_publish,abi_tail,
             core_gate,core_observer,core_startup,core_current_loop

tick 1: total=17852 control=17335 chain=7499 core=9836
        CORE gate=255 observer=340 startup=826 tail=4119   (合计 5540，显式电流环段 4296)
```

`gate`/`observer`/`startup`/`tail` 在 4 拍上**逐位恒定**，说明是确定性成本而非抖动。

**一处诚实的含糊**：`core_current_loop_cycles`（4,296）与 `tail`（4,119）是**同一段**（`mark_startup` → 返回）的两个读数，两者之差来自本项目实测的"调用边界 + 标记自身开销"（约 160～960 cycles，与链侧同源）。**因此该段的可信量级是"约 4,100～4,300"，不应引用单一读数。** 这也说明该段的内部构成仍未分辨——要区分"参考选择"与"电流环"，需要在该段内再插桩。

## 3. 边界与不确定

- 单一镜像、单次运行、单板、**空载**；主电源虽接通，控制器未武装、无输出，电流为静止噪声——**不代表带功率工况**；
- 4 拍样本（缓冲 128 拍，本次只导出 4 拍）；`gate/observer/startup/tail` 恒定，`chain` 有约 30 cycles 抖动；
- `core = control − chain` 仍是差值，吸收 Clarke、组合事务、限幅与计数器开销；
- **11 个标记**（链侧 3 + 核心 4 + ABI 4）自身的开销计入被测量区间；上一轮已测得 mode 1/2 的 WCET 因此上升约 5%；
- 未测：不同 feature 组合、带功率、其它转速。

## 4. 建议的下一步（按风险升序）

1. **细分尾部事务**（约 4,100）：在 `mark_startup` 与返回之间再插桩，区分"参考选择/指令处理"与"显式电流环（Park/逆Park/PI/限幅/SVPWM）"与"遥测与输出构造"。**这是当前最大的单一未知量，且大概率含可省的重复事务。**
2. **把 `input_valid` 的每拍常量校验移出热路径**（尺寸/版本/掩码改为配置期检查）。无契约风险，量级小但确定。
3. 链侧 fusion/HFI 解调的抽取（上限约 1,500～2,000），需重新整定。
4. **不建议**先动观测器与其门限——实测只占 3.5%。

## 6. 附注（2026-10-07 追加）：第 4 节的裁剪建议**已更正**

本文档第 4 节把 `core_current_loop_cycles`（约 4,300）读作"显式电流环段"，并据此建议"**下一刀应落在尾部事务，而不是控制律**"。

**该归属已被证伪**（见 `2026-10-07-P5.5尾部细分缺口已定位控制律不在current_reference内.md`）：

```rust
// lib.rs:3669
Self::SensorlessComposite(_) => false,   // force_reference() 在复合路径为 false
```

配合 `startup.phase != ClosedLoop`，`controller.current_reference` 的求值实际走 **else 分支（简单赋值）**，实测仅 **81 cycles**。真正的电流环预计算位于 **L4472 / L4606**，即 `mark_after_reference` **之后**。

**因此缺口的约 4,300～8,000 cycles 就在控制律路径上，而非"每拍事务"里。** 本文档第 3 节与 LOG-147 中"下一刀砍尾部事务"的建议**应予撤回**；观测器 340 cycles 的结论（第 1 节）不受影响。

# P4.1C 默认关闭反馈管理服务

## 范围

本轮在 `applications/` 增加单一管理 owner 可调用的反馈标定协调器，将 P4.1B1 的反馈 ABI
与 P3.2 配置事务串成一条默认关闭、可取消、可超时的管理链。它不创建 RT-Thread 线程，
不注册 Shell，不读取传感器寄存器，不进入 ISR，也不执行 volatile apply 或 Flash 写入。

实现入口：

- `applications/foc_feedback_management.h`：服务状态、证据、只读状态和调用契约；
- `applications/foc_feedback_management.c`：owner、timeout、取消/回滚、stage+validate、
  commit/readback revision 确认和失败锁存；
- `tests/host/test_foc_feedback_management.c`：Fake Rust ABI/Fake config 事务的应用层测试；
- `tests/host/CMakeLists.txt`：新增严格 warning-as-error CTest。

## 生命周期和安全边界

```text
Disabled -> Idle -> Collecting -> ReadyForReview -> Staged -> Idle
                         |              |             |
                         +----异常/超时/不可回滚-----> Failed
```

- 初始化后固定 `Disabled`，目标工程没有 `set_enabled(1)` 调用点；
- `owner_id` 非零且会话独占，非 owner 不能提交证据或取消；
- timeout 固定允许 1～600000 ms，并按 `u32` elapsed 处理回绕；
- 初始化、停用、取消、超时和失败均调用注入的 `force_safe`；
- 批准后只执行 config begin、Axis/Calibration stage、validate；
- 只有外部参数服务完成 apply、commit、readback，使 config 回到 `Idle` 且 active revision
  等于预期值，才允许 `finish_committed()`；
- CommitPrepared/StorageFault 不可由协调器猜测或强退，必须保持 Failed 和关断要求。

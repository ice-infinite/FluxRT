# P5.5-H1 DengFOC MCPWM 同步执行器软件门

## 1. 结论

在没有逻辑分析仪的条件下，本轮没有停在 LEDC 准备态，而是继续建立了一个独立、默认
关闭的 `dengfoc_usb_mcpwm_timing` 目标。它已在 DengFOC 的经典 ESP32-D0WD-V3 上完成
S1、S2 和 USB-only S4：

- M0 三相共用一个 MCPWM 定时器，采用 up-down 计数；软件读回频率为 29,985 Hz；
- 定时器 full 事件 ISR 在板端持续运行，应用每 100 ms 检查事件计数必须前进；
- GPIO12 始终处于驱动禁用电平，三相发生器被永久强制为低，非零 duty 写入必定拒绝；
- 公共功率状态机新增显式能力门，缺少任一电流闭环必需能力时不能 arm；
- 当前端口报告 `0x47`，即 duty 读回、中心对齐 PWM、三相同拍更新和 PWM 周期 ISR；
- 当前仍缺 `0x38`，即相位锁定电流采样、ADC overrun 检测和硬件快速关断。

因此，本轮把“中心对齐载波与快环时基”从待设计推进到板端运行，但没有把它误标为可用的
FOC 功率执行器。H2 低压锁转子注入仍不授权。

## 2. 为什么不等待逻辑分析仪

逻辑分析仪能够补充 GPIO32/GPIO33/GPIO25 的物理电平和边沿证据，但当前零 duty 固件没有
边沿，最多只能证明三路为低。对后续架构更关键的问题是：目标是否具备中心对齐载波、周期
ISR、ADC 同步和硬件关断能力。因此本轮先把每项能力变成机器可读位，并令 arm 对能力集合
执行 fail-closed；以后补仪器只增加物理证据，不会改变安全语义。

## 3. 分层实现

| 层 | 文件 | 责任 |
|---|---|---|
| 公共功率事务 | `foc/platform/esp32_dengfoc/foc_dengfoc_power_stage.*` | 定义能力位、读取平台能力、计算缺失集合、在 arm 前拒绝能力不足的平台 |
| Arduino LEDC 端口 | `targets/esp32_dengfoc/src/dengfoc_arduino_power_port.cpp` | 只报告真实具备的 duty 读回，不冒充中心对齐或 ADC 同步 |
| ESP-IDF MCPWM 端口 | `targets/esp32_dengfoc/src/dengfoc_mcpwm_power_port.*` | 单定时器、三 operator、up-down 计数、group-wide shadow flush、full ISR、永久强制低输出 |
| 目标选择门面 | `targets/esp32_dengfoc/src/dengfoc_target_power_port.h` | 由构建宏选择 LEDC 或 MCPWM，不把驱动类型泄漏到公共 C 状态机 |
| 诊断应用 | `targets/esp32_dengfoc/src/main.cpp` | 启动自检、arm 负例、周期 ISR 活性与禁用状态持续监督 |
| 构建入口 | `targets/esp32_dengfoc/platformio.ini`、`build.ps1`、`.vscode/tasks.json` | 独立 MCPWM timing 环境；不会改变默认 angle diagnostic |

快 ISR 只递增固定宽度计数器，不执行串口、I2C、浮点控制、动态分配或配置事务。慢速应用只
读取快照并执行健康检查。这遵循项目“ADC/PWM 事件进入快环，管理与遥测留在慢路径”的分层。

## 4. 能力合同

电流闭环最低能力集合为：

```text
CENTER_ALIGNED_PWM
COHERENT_THREE_PHASE_UPDATE
PHASE_LOCKED_CURRENT_SAMPLE
ADC_OVERRUN_DETECTION
HARDWARE_FAST_SHUTDOWN
```

诊断定时器可以在能力不完整时进入 `PWM_READY`，便于逐步验证；三路 compare 先分别写入
shadow register，只有全部成功后才调用经典 ESP32 MCPWM 的 group-wide shadow flush，以一次
硬件事件同步更新三个 operator，且不改变 timer 相位。但只要
`allow_actuation=1`，调用方就不能删减上述集合。`arm` 比较平台能力与要求集合，存在任何
缺失位就关断并进入 `FAULT_LATCHED`。这使“可以产生定时器事件”和“可以闭环驱动电机”成为
两个不可混淆的状态。

## 5. ESP32 能力边界

Espressif MCPWM 官方接口支持 up-down 计数、定时器事件回调和同步机制，因此经典 ESP32
可以提供中心对齐载波及周期 ISR。当前本机目标的 SoC capability 与公开驱动链没有提供可由
MCPWM 事件硬件触发的 ADC 采样通路；ADC 仍是独立的软件/连续采样路径。故本实现不声明
`PHASE_LOCKED_CURRENT_SAMPLE`，也不以软件定时读取冒充硬件同步。

参考：

- <https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/mcpwm.html>
- <https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/mcpwm/index.html>

新版文档中的 MCPWM→ADC ETM 触发只适用于具备相应 ETM 外设能力的目标。不能把其他 ESP32
变体的能力外推到本板 ESP32-D0WD-V3。

对`E:\File\PlatformIO\DengFOC\include`、`src`及当前FluxRT板级profile的核对只找到GPIO12
总使能、三相PWM、两路电流ADC和AS5600连接，没有独立driver fault/over-current输入。软件
把GPIO12拉低仍是重要的安全动作，但它依赖CPU和软件执行，不能据此声明
`HARDWARE_FAST_SHUTDOWN`。若实物原理图另有未被参考工程使用的故障网络，必须先取得原理图
和网络真值，再把它加入独立板级revision profile。

## 6. 验证结果

| 等级 | 场景 | 结果 |
|---|---|---|
| S1 | 公共功率事务 Host 负例与全量回归 | PASS；能力不足时 arm 故障锁存；调用方不能弱化最低能力；Host C 59/59 |
| S1 | Rust、Clippy、闭环仿真和工具回归 | PASS；Rust 383、Simulation Python 47、Profile 166，Clippy clean |
| S2 | `dengfoc_usb_mcpwm_timing` | PASS；RAM 16,600 B，Flash 172,107 B |
| S2 | 旧 `dengfoc_usb_pwm_prepare` 兼容构建 | PASS；RAM 16,600 B，Flash 171,007 B |
| S4 | COM13 烧录后独立硬复位 | PASS；新 MCPWM timing 启动标识、GPIO12 disabled、ADC 零点有效 |
| S4 | 同步功能版12 s连续观察 | PASS；219帧/218有效（首帧预热），`freq=29985×3`、`duty=0×3`、`arm_refused=1`、`caps=0x47`、`missing_runtime=0x38`、`coherent=1`、`FATAL=0` |
| S4 | 最终源码一致镜像6 s复核 | PASS；99帧、`FATAL=0`、`fail=0`，能力与同步计数不变 |

板上固件：

```text
targets/esp32_dengfoc/.pio/build/dengfoc_usb_mcpwm_timing/firmware.bin
SHA-256 4193461F937D121006EF037F05DF9CB60EDD392D6B7980A9B0BA22EB9DB3005C
```

PlatformIO 上传主流程为 SUCCESS。Windows GBK 控制台的进度输出线程仍发生块字符编码异常，
所以烧录结论来自之后的独立硬复位和应用日志，而不是仅依赖上传返回值。

三相同步的第一次实现尝试使用独立 MCPWM software-sync。目标构建通过，但板端
`mcpwm_soft_sync_activate()`返回`ESP_ERR_INVALID_STATE (0x103)`；公共事务立即fault latch，
GPIO12和三相输出保持关闭。没有绕过失败，而是改用经典ESP32已经提供的global shadow
flush。最终板端回读`update_step=0/update_err=0/coherent=1`。该失败与修正均保留在操作日志。

## 7. 仍未完成与下一步

1. 不在经典 ESP32 上用软件延时伪造 ADC 同步。应二选一：
   - 为当前芯片建立“异步采样、带时间戳和相位估计”的研究档，但保持不可用于正式电流环；
   - 选择具备 MCPWM/ETM/ADC 硬件触发链的 MCU/ESP32 变体或外部同步 ADC；
2. 建立 ADC 丢样/overrun 计数与失效同拍关断；
3. 核对板上驱动器硬件 fault/enable 通路，建立不依赖任务调度的快速关断；
4. 逻辑分析仪恢复后补三相低电平、中心对齐边沿、同拍更新和关断延迟的物理证据；
5. 上述 `0x38` 全部关闭后，才进入电流比例/极性、电角度零偏和 H2 审批。

当前板端仍是仅 USB、零 duty、禁止 arm 的诊断状态；本报告不证明 12 V 功率级、电机运行、
HFI 注入或全速域闭环。

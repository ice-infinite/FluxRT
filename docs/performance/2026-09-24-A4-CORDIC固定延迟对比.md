# 阶段 1.3：CORDIC 固定延迟读取候选 A/B

## 1. 结论

STM32G431 CORDIC 的“6 个 `NOP` + 单次 `RRDY` 检查”候选在当前板卡、170 MHz 时钟和
GNU Arm 15.3.1 工具链下通过了停机分项测试与低功率完整 ISR 测试，但**暂不替换默认的
有界轮询路径**。

严格完整 ISR A/B 使用同一套专项基准代码，仅切换实时 CORDIC 等待策略：

| 实时策略 | 三轮完整 ISR WCET | control | invalid/miss/error/fault |
|---|---:|---:|---:|
| 有界 `RRDY` 轮询 | 7,957 / 7,957 / 7,957 cycles | 7,099 | 0/0/0/0 |
| 6 NOP + 单次 `RRDY` 检查 | 7,888 / 7,888 / 7,888 cycles | 7,030 | 0/0/0/0 |

候选减少 69 cycles，即完整 ISR 的约 0.87%，或 12 kHz 软件截止 12,500 cycles 的约
0.55%。收益是真实可重复的，但还不足以抵消缺少实时回退计数、强制未就绪故障注入和
跨工具链/时钟证明的风险，所以 Kconfig 默认仍为关闭。

## 2. 候选实现与边界

候选只改变 C 平台层 `foc_cordic_wait_ready()` 的等待方式：

```text
当前默认：最多 64 次读取 CSR.RRDY，成功后读 RDATA，超时返回 0
专项候选：固定 6 个 NOP，只读一次 CSR.RRDY；未就绪返回 0
```

候选没有照搬 ST 生成代码的“直接读 `RDATA`”：单次检查失败时仍拒绝读取结果，并让
Rust `CpuMath` 在同一控制拍回退。因此它不会把旧结果当成新结果。CORDIC 寄存器、
`PRIMASK` 保存/恢复和固定延迟仍全部位于
`foc/platform/stm32g431/foc_math_accel_stm32g431.c`，没有进入 Rust 算法层。

配置门：

- `FOC_MATH_DIAGNOSTIC_BENCHMARK`：编译停机 A/B 向量和 Shell 命令；默认 `n`；
- `FOC_MATH_CORDIC_FIXED_DELAY_CANDIDATE`：让 Diagnostic 实时路径使用候选；依赖前一项，默认 `n`；
- Production 即使看到候选宏也强制使用轮询路径。

## 3. 停机分项 A/B

专项固件在同一个镜像中交错调用轮询参考和固定延迟候选。每轮为 16 个单位圆向量、
每向量重复 64 次；候选启用后的最终复测结果如下：

| 运算 | 策略 | 调用/成功/失败 | raw min/avg/max cycles | 最大误差 |
|---|---|---:|---:|---:|
| `sin/cos` | 轮询 | 1024/1024/0 | 349/392/424 | 1,013 ppb |
| `sin/cos` | 固定 6 NOP | 1024/1024/0 | 353/391/408 | 1,013 ppb |
| `atan2` | 轮询 | 1024/1024/0 | 452/475/498 | 1 µrad |
| `atan2` | 固定 6 NOP | 1024/1024/0 | 428/446/466 | 1 µrad |

候选关闭时另做三轮，每类策略累计 3,072 次调用均为零失败，误差与上表一致。A4 基准
通过不可内联包装器和函数指针让两种策略使用同一调用口径，因此它的绝对周期不能直接
与 A3 旧基准的 287/357 cycles 比较；本报告只使用同一 A4 镜像内的相对差值。

机器记录拆成两行：`FMATH` 是轮询参考，`FMATHF` 是固定延迟候选。最初把 39 个字段
放在一行，超过 RT-Thread 控制台缓冲后被截断；修正后两行均完整输出。人读统计未受影响。

## 4. 完整 ISR 严格 A/B

硬件和场景：NUCLEO-G431RB + X-NUCLEO-IHM16M1 + GBM2804H-100T，板端约
12.26～12.30 V，电源上限 2 A，软件 trip 1.15 A，空载自由旋转，默认开环 582 rpm，
trace 关闭，每轮 5 秒，每轮及最终均执行 `foc_stop`。

轮询专项固件：

- BIN 127,568 B；SHA-256 `24ACAC5914721CE3DBD142D7CB3F1F8AAD7979E2C4000ED689011651850BC16A`；
- 三轮样本数 66,034 / 66,028 / 66,112；三轮完整 ISR 均为 7,957 cycles。

固定延迟专项固件：

- BIN 127,520 B；SHA-256 `2BDC41CD147B2F69A7007646917D83C8B1FF24C637CDFD70EF495607D1A2F45E`；
- 三轮样本数 66,041 / 66,052 / 66,037；三轮完整 ISR 均为 7,888 cycles。

两类固件均通过 STM32CubeProgrammer 2.19.0 下载、verify、reset；每轮均为 0 invalid、
0 deadline miss、0 control error、0 Rust fault。这里只证明低压、限流、空载短时运行，
没有编码器角度真值、负载、温升或 CORDIC 故障注入。

## 6. 下一门槛

固定延迟候选若要升为默认，还必须补齐：

1. Diagnostic 可读的硬件调用成功、未就绪和 CPU 回退累计计数；
2. 可恢复的“强制单次未就绪”故障注入，证明不会读旧数据且不会越过截止；
3. 冷启动、重复上电和更长运行；
4. 工具链、系统时钟、Flash wait-state 或 MCU 改动后的重新验证。

在这些证据完成前，69 cycles 只记作可选优化收益，不改变默认生产路径。

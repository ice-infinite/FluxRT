# P5.5-H3 同步物理资源与边沿身份方案

## 1. 本轮结论

H3 的公共事件 ABI 已经存在，但不能把“周期 GPIO + 两端各自计数”当成可信同步：任一端
漏掉一个边沿后，后续事件会整体错位，而单纯的仿射拟合可能把这个错位吸收到截距中。
因此物理链必须同时传输边沿身份，并在完整帧校验通过后才能设置
`FOC_TIME_SYNC_EVENT_FLAG_IDENTITY_VERIFIED`。

源码、官方原理图和芯片资料的首轮核对后，用户又提供两块实板的正反面照片。本轮据此
修正候选：NUCLEO的Morpho排针已经确认可接近；DengFOC照片没有看到GPIO4通用排针，因此
不能继续把“源码未占用GPIO4”误写成“实板可接GPIO4”。

| 角色 | 首选候选 | 备选/辅助 | 当前判定 |
|---|---|---|---|
| STM32G431 发送 | `PB6 / TIM4_CH1`，NUCLEO `CN10-17` | `PB7 / TIM4_CH2`，NUCLEO `CN7-21`可作本地物理回采 | Morpho排针在叠板状态仍外露；与当前TIM1/TIM2/控制台/探针分离 |
| DengFOC ESP32 接收 | 未启用Axis1的`SDA1 / GPIO23 / RMT RX` | GPIO4只保留逻辑候选，不作为当前接线点 | 用户实物目视确认插座丝印；受控复位后PB6→IO23已完成5帧身份/时间锚点S4 |
| 连接 | G431 `PB6/CN10-17` -> DengFOC `SDA1/GPIO23`，外加公共GND | PB6 -> PB7/CN7-21本地回采已接并通过 | 单向3.3 V逻辑已完成无主电实接；VCC/IO5/IO21悬空 |

`PB6/CN10-17`与`SDA1/GPIO23`已经从“照片/源码/丝印候选”推进到无主电身份与初始时间链S4：
受控复位后5帧`session/sequence/tag/CRC`逐帧一致且失败0；连续DWT锚点拟合漂移约
21.116 ppm、最大残差3.312 us。后续PB7真实边沿run3进一步取得20/20锚点、绝对漂移
23.328 ppm和最大残差1.326 us。该结果仍不是动态角度同步或产品配置，也不得把任何
sensorless capability从0提升。

## 2. 当前资源占用核对

### 2.1 STM32G431 + X-NUCLEO-IHM16M1

当前源码已经使用：

- `TIM1_CH1/2/3` 的 `PA8/PA9/PA10`：三相 PWM；
- `TIM1_CH4`：ADC 同步触发窗口；`TIM1_BKIN2 / PA11`：保护；
- `TIM2`：Identification 多速率下的 ADC 触发分频，不能复用；
- `PB13/PB14/PB15`：三相 gate enable；`PB12`：外部 Break 自检刺激；
- `PC0/PC3/PC1`：BEMF U/V/W，`PC9`：BEMF 分压支路使能；
- `PA2/PA3`：LPUART1；`PA5`：可选 ISR 时序探针；
- ADC 网络还使用 `PA0/PA1/PA7/PB11/PC2/PC4`。

ST 官方 X-NUCLEO-IHM16M1 原理图列出的电流、VBUS、PWM、保护、使能、BEMF 和 Hall 网络
中没有发现 PB6/PB7；NUCLEO-G431RB 官方原理图把 PB6/PB7 引到 Morpho 连接器。STM32G431
数据手册又给出 PB6=`TIM4_CH1`、PB7=`TIM4_CH2`，而 TIM4 是独立的4通道16位定时器。
因此 `PB6/TIM4_CH1` 是当前冲突最少的发送候选，PB7可选作同一定时器的输入捕获回采。

官方依据：

- [X-NUCLEO-IHM16M1 schematic](https://www.st.com/resource/en/schematic_pack/x-nucleo-ihm16m1_schematic.pdf)
- [NUCLEO-G431RB schematic](https://www.st.com/resource/en/schematic_pack/mb1367-g431rb-c04_schematic.pdf)
- [STM32G431RB datasheet](https://www.st.com/resource/en/datasheet/stm32g431rb.pdf)

### 2.2 DengFOC ESP32

当前 `foc_dengfoc_v04_reference_profile` 使用：

- GPIO12：driver enable；
- M0：PWM 32/33/25，电流 ADC 39/36，I2C 19/18；
- M1：PWM 26/27/14，电流 ADC 35/34，I2C 23/5。

当前源码未使用GPIO4，但照片上没有看到对应通用排针，故不再把它作为首个物理接线点。
当前默认只启用M0；M1的I2C1映射为SDA23/SCL5。DengFOC公开V3项目把板端第二路插座称为
`SDA1/SCL1/3V3/GND`，这与当前V0.4参考源码的SDA23/SCL5相互印证，但旧版资料不能替代
V0.4原理图或连续性测量。

为避免把候选写死，`foc_time_sync_dengfoc_input_resource_valid()`只做逻辑冲突仲裁：

- Axis0必须启用，保留M0 AS5600真值；
- PWM、电流ADC和GPIO12在任何情况下都不可复用；
- I2C引脚只允许在对应Axis整体关闭时复用；
- 因此GPIO23在`axis_mask=0x01`时允许，在`axis_mask=0x03`时必须拒绝。

这项检查不证明电气连续性。实物丝印已经确认`VCC/GND/IO23/IO5/IO21`；首次接线仍必须
断开Axis1传感器，只接公共GND和IO23，VCC/IO5/IO21保持悬空。

官方依据：

- [ESP32 GPIO/IO MUX](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/io_mux.html)
- [Arduino-ESP32 RMT API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/rmt.html)
- [ESP-IDF Programming Guide for ESP32](https://docs.espressif.com/projects/esp-idf/en/v5.2.1/esp32/esp-idf-en-v5.2.1-esp32.pdf)
- [DengFOC V3公开项目的SDA0/SCL0与SDA1/SCL1接线说明](https://github.com/ToanTech/Lailuo_DengFOC#2-%E6%8E%A5%E7%BA%BF)

## 3. 边沿身份协议设计

### 3.1 不采用的方案

- 只发固定频率方波；
- 两端各自从零累加序号；
- 用串口接收时间代替物理边沿时间；
- 收到帧头就提前提交事件；
- 队列满时覆盖旧事件。

这些方案无法证明两端看到的是同一个物理事件，或会在丢边沿后静默错配。

### 3.2 固定脉宽帧

采用单线、自时钟、固定长度的脉宽帧。建议线协议字段为：

| 字段 | 字节 | 含义 |
|---|---:|---|
| magic | 2 | 固定同步字，排除随机脉冲 |
| version | 1 | 线协议版本 |
| length | 1 | 固定包长，拒绝结构歧义 |
| session | 4 | 每次采集会话随机/唯一身份 |
| sequence | 4 | 会话内严格递增事件序号 |
| tag | 4 | 由发送端生成的非零事件标签 |
| CRC32 | 4 | 覆盖前16字节 |

共20字节、160 bit。另加一个特殊 SOF symbol；每bit用“固定低电平间隔 + 短/长高电平”
编码，因此不会依赖两端同频时钟。ESP32 RMT完成整帧捕获，只有 symbol 数量、宽度、magic、
version、length和CRC全部通过后，才把SOF首个物理上升沿的本地tick与解码出的身份一起提交
给`foc_time_sync`。

RMT实际接收还需要一个**平台层结束保护脉冲**：161个codec symbol后追加10 us高脉冲，
使最后一个data-low获得明确结束边沿；保护脉冲后的低电平允许延伸到RMT idle阈值。保护
脉冲不进入20字节codec和CRC，接收端要求实际symbol总数严格为162，并单独验证保护脉冲。

### 3.3 发送与接收责任

```text
G431 TIM4/DMA                         ESP32 RMT RX + GPIO edge ISR
session/sequence/tag                 捕获完整161 symbols
        |                                      |
编码固定脉宽帧 -----------------------------> 校验时宽/长度/CRC
        |                                      |
记录首个发送compare tick              记录SOF首个上升沿tick
        |                                      |
提交CONTROL_REFERENCE事件             校验通过后提交TRUTH_SENSOR事件
```

- G431：TIM4负责波形，不进入TIM1控制快环；帧身份在启动DMA前冻结；发送完成或错误都必须
  有计数器，不得在ISR里动态分配。
- ESP32：RMT只采波形，GPIO首个上升沿ISR用`esp_timer_get_time()`锁存与AS5600相同的1 MHz
  时间域；解码器放在loop/task上下文；完整验证前不得发布事件。当前专用诊断目标只编译
  到S2，并已在双板无主电S4证明经典ESP32能严格解码受控复位后的5帧身份，失败0。
- 可选G431本地回采：PB7/TIM4_CH2捕获真实PB6边沿，用于区分“计划compare tick”和
  “引脚实际边沿”。没有回采时必须把该证据边界写进manifest。
- 公共层：继续只保存验证后的事件，不了解TIM4、DMA、RMT或GPIO。

## 4. 故障语义

以下任何情况整帧拒绝，不允许猜测或修补：

- 少/多symbol、非法高低脉宽、帧间idle不足；
- magic、version、length或CRC错误；
- session不匹配、sequence不连续、tag为0或重复；
- RMT溢出、DMA错误、事件队列满、本地tick读取失败；
- 收到新会话时旧会话仍处于armed状态。

拒绝后保留首个失败原因和计数，要求显式结束/重开会话。离线时间映射只接受两侧
`session/sequence/tag`完全一致且均带`IDENTITY_VERIFIED`的锚点。

## 5. 下一软件门和实机门

### 5.1 可立即继续的软件工作

1. 公共codec和Host故障矩阵已经完成；
2. DengFOC新增独立`dengfoc_usb_time_sync_rx`，仅在该目标中显式选择GPIO23；
3. 诊断目标保持GPIO12低、六路PWM输入态，只采M0 AS5600、RMT帧和SOF tick；
4. G431默认关闭的TIM4/DMA发送端和10 us结束保护脉冲已经完成S1/S2，Identification镜像只通过显式Shell命令运行；
5. 默认DengFOC目标、G431产品目标和全部能力位保持不变。

### 5.2 到此才需要用户操作

两端身份链S4已经通过；下一步继续USB-only动态时间门：

1. 已由用户实物目视确认插座丝印为`VCC/GND/IO23/IO5/IO21`；首次接线只用GND和IO23；
2. 当前已只接公共GND与PB6/CN10-17→IO23，VCC/IO5/IO21悬空；
3. 单帧和连续10帧均通过身份/CRC校验，累计11帧、失败0；
4. G431连续DWT/control同域tick、PB6→PB7实际边沿回采和自动证据包已完成；
5. 下一步在同一转子拓扑和新的带功率授权下取得动态query与角误差，之后才讨论H3动态真值能力。

本方案不授权HFI、低压注入、PWM输出或电机运行。

# P2.5A2D 外部 I/O 平台解耦

## 1. 结论

外部 I/O 公共管理层已不再直接依赖 STM32G431 板级头文件或板级函数。目标构建现在由
`foc_external_io_platform.h` 定义唯一平台 capability provider，STM32G431 实现在
`foc/platform/stm32g431/`，启动组合根取得 capability 后显式传给
`foc_external_io_management_init_with_capabilities()`。

本批只调整依赖方向，不增加 Timer/ADC/GPIO 驱动，不改变配置 ABI、控制公式、命令权限、
默认开关或硬件状态。

## 2. 依赖边界

```text
applications/main.c（目标组合根）
  -> foc_external_io_platform_capabilities()       公共平台端口
       -> foc/platform/<target>/...                 构建期唯一实现
  -> foc_external_io_management_init_with_capabilities()
       -> InputService -> CommandService -> Rust CommandArbiter
```

以下旧依赖已经删除：

```text
foc_external_io_management.h
  -X-> foc_external_io_board.h

foc_external_io_management.c
  -X-> foc_external_io_board_stm32g431_capabilities()
```

`foc/SConscript` 不再把 `foc/platform/stm32g431` 作为公共 include path 导出。平台源文件仍由
当前 STM32G431 目标构建选择，这是允许存在的组合层耦合；未来 MCU 必须提供同名公共端口
实现并由其目标构建选中，不能把 MCU 头文件重新带回 applications/runtime/Rust。

## 3. 测试防回归

新增 `foc_external_io_management_header_isolation_tests`，只向编译器提供：

- `applications/`；
- `foc/include/`。

它不提供 `foc/platform/stm32g431/` include path，也不链接任何平台源。公共 management
头文件以后如果再次包含板级头文件，该测试会在编译阶段直接失败。管理服务测试同样已经
移除 STM32G431 源和 include path，只使用 Fake capability 注入。

## 5. 后续边界

P2.5A3 实现物理采集时必须新增目标中立的 raw-capture 端口，再由
`foc/platform/stm32g431/foc_external_input_stm32g431.c` 实现。公共层只接收原始值、时间戳、
序号和健康状态，不允许出现 TIM/ADC/GPIO/HAL 类型。新板卡需要替换 capability/provider、
raw-capture driver 和构建选择；Rust 归一化、配置、服务、命令仲裁和协议 adapter 保持复用。

当前还不能宣称多 MCU 已实证：工程只有 STM32G431 provider，第二平台构建与 U10 多板完成门
仍未执行。本批证明的是公共 External I/O 管理层不依赖现有板级实现。

# A9｜24/12 kHz 无功率实机时序门

> **2026-09-24 A10 后续纠正：**本报告证明了原 Update 触发候选的频率和无功率寄存器，
> 没有证明三分流采样窗口。S5 电流数据已否决该触发方案；当前实现改为
> `TIM1 OC4REF -> TIM2 ITR0 二分频 -> TIM2 TRGO -> ADC`。本文只保留为历史证据，
> 修正方案和实机结果见
> [A10｜24/12 kHz 受限实机 A/B](2026-09-24-A10-24k12k受限实机AB.md)。

## 结论

24 kHz PWM / 12 kHz ADC 与控制候选已经在 NUCLEO-G431RB 上完成一次**无功率输出**
验证，证据达到 S4：固件成功烧录、校验、启动、串口通信，运行态 TIM1/ADC/GPIO
寄存器和 DWT 同步间隔与 A8 设计一致。

验证期间始终满足：

- `closed=0`，没有执行 `foc_start`；
- `steps=0`、`errors=0`、`duty=0/0/0`；
- TIM1 `CC1E/CC2E/CC3E=0`、`BDTR.MOE=0`；
- PB13/PB14/PB15 栅极使能输出为低；
- 电机没有转动，没有进行 S5 功率级验证。

验证结束后，`.config`、`rtconfig.h` 和板上固件均已恢复为默认 12/12 kHz，候选与
PA5 timing probe 关闭，并执行 `foc_stop`。因此本报告不是批准候选成为默认配置。

## 2. 运行态寄存器证据

普通 SWD 连接会让目标停在复位状态，第一次读到的全零寄存器已判为无效。随后先让
固件正常启动，再使用 CubeProgrammer `mode=HOTPLUG` 读取运行态寄存器：

| 对象 | 读值 | 解码与判断 |
|---|---:|---|
| TIM1 CR1 | `0x00000131` | `CEN=1`，`CMS=1`，中心对齐模式 1 正在运行 |
| TIM1 CR2 | `0x00000020` | `MMS=2`，TRGO 来源为 Update Event |
| TIM1 CCMR1 | `0x00006868` | CH1/CH2 PWM1，CCR preload 开启 |
| TIM1 CCMR2 | `0x00000068` | CH3 PWM1 preload 开启，CH4 未作为触发源 |
| TIM1 CCER | `0x00000000` | CH1～CH4 输出全部关闭 |
| TIM1 ARR | `0x00000DD5` | 3541 |
| TIM1 RCR | `0x00000003` | 每 4 个半周期产生一个控制 UEV |
| TIM1 CCR1～4 | 全 0 | 没有三相占空命令 |
| TIM1 BDTR | `0x03302C00` | `MOE=0`，主输出关闭 |
| ADC1 JSQR | `0x00000480` | `JEXTSEL=0`=TIM1_TRGO，`JEXTEN=1`=上升沿，rank1=ADC channel 2 |
| GPIOB ODR | `0x00000000` | PB13～15 栅极使能全部为低 |
| GPIOA MODER | `0xABAAF7AF` | PA5 mode=1，timing probe 为推挽输出 |

这证明固件常量确实落到运行态外设，而不只是反汇编中存在。它仍不能代替外部仪器对
UEV、ADC 采样沿、PA5 ISR 脉冲和 active CCR 边沿的同屏测量。

## 3. 目标触发频率实测

只在 `FOC_ISR_TIMING_PROBE=y` 时，ADC ISR 使用 DWT 记录相邻 ISR 入口间隔；该统计
同时保留 PA5 高低包络，不进入默认镜像。停机监测状态得到：

```text
FOC rates PWM/control=24000/12000Hz ratio=2 delay=2 PWM ticks ADC trigger=2.
FOC sync interval last/min/avg/max=14131/12953/14163/15746 cycles
  (716025 samples); monitor ISR=117/117/334 cycles.
```

理论 Update 间隔为：

```text
4 × ARR = 4 × 3541 = 14164 timer cycles
170 MHz / 14164 = 12002.26 Hz
```

累计平均以整数打印为 14,163 cycles，与 14,164-cycle 理论值相符。入口最小/最大值
不是 PWM 周期漂移，而是 ADC 中断入口受到 UART、SysTick 等更高/并发中断延迟影响；
长期平均保持不变。停机监测 ISR 包络最大 334 cycles，占一个控制间隔约 2.36%。

这里的 117～334 cycles 只覆盖“读 ADC、重构静态电流、更新诊断、清标志”的未 arm
路径，**不是完整 Rust FOC ISR WCET**。完整路径仍沿用此前约 7,975 cycles 的实机
上界，且必须在后续功率级候选运行时重新测量。

## 5. 为本门增加的诊断

`foc_platform_diagnostics_t` 增加：

- `sync_interval_last/min/max_cycles`；
- `sync_interval_sum_cycles` 与 `sync_interval_sample_count`；
- `monitor_isr_last/min/max_cycles`。

目标端只有在 `FOC_ISR_TIMING_PROBE=y` 时更新这些字段。默认构建不执行间隔统计，
避免为了诊断改变正常 ISR 时序；`foc_status` 在所有构建中保留字段显示，默认值为 0。

## 6. 失败与修正

1. CubeProgrammer `-r8` 单次读取 128 KiB 失败，工具限制最大 32 KiB。改用
   `--upload 0x08000000 0x20000 <file>` 后完整备份成功。
2. 使用普通 SWD 连接读取运行态寄存器得到全零，因为调试连接改变了目标状态。该组
   数据作废；复位正常运行后改用 `mode=HOTPLUG`，读回值与串口采样计数一致。
3. 第一版 DWT 只有 last/min/max，无法区分入口抖动与平均周期。增加累计周期和样本数
   后，用 716,025 个样本验证平均值。

## 7. 证据等级与下一步

本轮达到 S4，仅证明：

- 候选可以下载、启动和通信；
- TIM1/ADC/GPIO 运行态寄存器符合 24/12 kHz 设计；
- ADC ISR 的长期平均触发间隔符合 12 kHz；
- 整个验证过程中功率输出保持关闭。

仍未证明：

- PA5、UEV、ADC 采样沿与 active CCR 的外部同屏相位；
- 完整 Rust FOC 在候选时序下的 WCET；
- 24 kHz 对电机噪声、电流纹波、观察器或闭环品质的改善；
- 功率级、电机和保护在候选配置下可用。

下一道门仍应是外部示波器/逻辑分析仪的无功率相位捕获。若暂时没有仪器，不应跳过
这一证据直接把候选设为默认；可以在用户明确确认后，将 24/12 kHz 作为可立即回退的
受限 S5 A/B 候选，使用 2 A 限流、空载、短时、先开环后闭环的既有安全流程。

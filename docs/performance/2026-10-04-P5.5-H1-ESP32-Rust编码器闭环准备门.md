# P5.5-H1 ESP32 Rust 编码器闭环准备门

## 结论

经典 ESP32 路径现在能把 Rust `no_std` 静态库直接链接进 PlatformIO，并具备独立的
编码器实时 FOC ABI。该 ABI 每拍由 C 提交两相电流、母线电压、已校准 AS5600 电角度、
机械速度、序号和故障；Rust 一次完成速度环、电流环、角度补偿和 SVPWM，C 不再拼接
`speed_step + fast_step`。

本轮已达到 USB-only S4，但没有达到带功率 S5。COM13 上完成了实际烧录、启动、
异步 ADC 连续采样、Rust ABI 和 2 kHz 影子控制环验证；`GPIO12`始终禁用，三相发生器
始终强制低，Rust 输出只记录且`output_commit=0`，没有接通 12.3 V 主电源或运行电机。

## 两条路径不混用

| 路径 | 用途 | 当前门 |
|---|---|---|
| 编码器实时FOC | 先让DengFOC板得到可对照AS5600的全速域有感闭环，给后续HFI/SMO提供真值 | USB-only影子环与MCPWM事件owner通过；零偏标定固件已准备，仍缺带功率标定结果 |
| HFI + BEMF/SMO | 最终全速域无感产品路径 | 继续执行正式硬件能力门，不因有感路径而降低 |

## ADC边界

`dengfoc_adc_stream`使用ESP-IDF ADC continuous驱动采GPIO39/36，记录DMA pool overflow、
read error、丢失PWM窗口以及MCPWM full事件到首个完整A/B样本的CPU cycle延迟。初始
120 ksample/s 两通道总速率会持续产生 pool overflow；改为60 ksample/s总速率并把pool/read
缓冲扩展为8192/1024 B后，15 s内`overflow=0/read_err=0`。

板端实测约29.985 kPWM事件/s，而完整A/B样本约24.5 k对/s，累计`missed_pwm_window`持续
增加。因此该ADC路径能支持2 kHz编码器实验的“取最新样本”策略，却不能保证每个PWM周期
都有样本，更不能提供固定PWM相位的电流采样。

这仍是异步连续采样：软件可以选择某个PWM事件之后的首对样本并测其界限，但不能把它
标为`PHASE_LOCKED_CURRENT_SAMPLE`。正式无感/HFI门仍要求硬件触发或等价且独立验证的确定性
采样链。

## 验证

- 定向Rust：56/56 PASS；
- 全量：Profile Python 166、Simulation Python 47、Rust 385、Host C 60/60、Clippy clean；
- 当前源码ESP32 Rust探针S2：RAM 19,040 B，Flash 202,011 B，BIN SHA-256
  `9151D8343289BD9E01959EB421758E9E8B965AC87721C781BF071ECF1F6E2CFF`；该镜像在功率
  policy结构更新后重新构建，但板上已换成标定镜像，不能把这个哈希冒充本轮S4运行镜像；
- COM13烧录和独立复位PASS：`period=1334/peak=667`、实际29,985 Hz，三相duty均0，
  `allow_actuation=0`且arm被拒绝；
- 15 s串口窗口：148个ADC健康窗口全部`alive=1`，`overflow=0/read_err=0`，无panic/FATAL；
- 早期`esp_timer` 2 kHz影子环曾记录到1次大于750 us的调度间隔；改成MCPWM每15个
  full事件通知固定高优先级任务后，12 s窗口得到21,213个Rust完整控制步、`step_error=0`、
  `deadline_miss=0`，周期450～563 us，最大计算99,973 cycles、最大唤醒11,558 cycles，
  始终`output_commit=0`；
- 串口从115200改到921600后，AS5600的`invalid_angle`只保留启动阶段16次，不再随100 ms
  日志增长，说明旧增长来自低波特率阻塞导致的20 ms陈旧门，而非I2C读失败。

首次烧录曾在ESP-IDF启动阶段出现`Cache disabled but cached memory region accessed`。ELF回溯
确认Rust `compiler_builtins`的弱`memset/memcpy/memmove`抢先满足了ESP-IDF启动符号，缓存关闭
时进入Flash。构建脚本现在复制Rust archive并把五个内存符号重命名到
`__fluxrt_rust_*`私有命名；最终ELF的公共`mem*`恢复为libc/IRAM实现，启动循环消失。

另一个板端纠错是MCPWM `period_ticks`：ESP-IDF的up-down模式把它定义为完整
`0 -> peak -> 0`周期，原实现误当成peak，导致实际事件约59.97 kHz且未来compare可能越界。
现已改为`period=1334`、`peak=667`、compare按peak换算，板端计数复核约29.985 kHz。

## 下一门

1. 保留当前异步ADC能力门：不得置位`PHASE_LOCKED_CURRENT_SAMPLE`；
2. MCPWM事件通知owner已经关闭USB-only时序门，保持该实现；
3. 独立`dengfoc_alignment_calibration`已完成默认禁用、限时、限流和一次性令牌的USB-only S4；
4. 再请求12.3 V、2 A、空载自由旋转条件，执行低电压短时标定；
5. 至少重复两次并核对零偏离散后，才写入版本化配置并允许首个极低速编码器闭环试验；
6. 正式HFI仍等待PWM相位锁定采样与独立硬件快速关断，不因校准专用电压模式降门。

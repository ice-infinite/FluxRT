# P4.2D motion双仿真验证

## 1. 结论

P4.2D Rust PC与MATLAB独立motion模型已经完成D0～D4严格对拍：8个场景、192行trace全部
PASS，15个连续通道在当前9位小数输出精度下最大绝对差均为0。修复后的全量回归和默认关闭
四档目标构建也全部PASS，四档map均无motion符号。

因此P4.2D达到S3软件双仿真门，但不包含目标owner/ISR接线、板端WCET、真实反馈、烧录或电机
运行；不能据此声称P4.2E或实机运动控制完成。

## 2. 首轮失败与修复

首轮Rust engine成功生成8 cases/192 rows，MATLAB在加载comparison合同时被严格字段门拒绝：

```text
comparison field set mismatch
load_fluxrt_simulation_contract>exact_fields
```

原因是`comparison-gates-v1.json`新增`motion_numeric_tolerances`，Rust严格白名单已经同步，
MATLAB共同loader仍只允许旧字段。修复只修改`simulink/load_fluxrt_simulation_contract.m`：

- 把`motion_numeric_tolerances`加入精确字段集合；
- 每项只允许`channel/absolute/relative`；
- absolute/relative必须有限且非负；
- channel非空、唯一，并精确覆盖冻结的15个motion连续列。

没有修改JSON、hash、容差数值或控制算法，也没有通过放宽容差绕过差异。

## 6. 下一步边界

P4.2D完成后仍不能直接转动电机。P4.2E至少先分成：

1. 无功率：Diagnostic owner/生命周期接线、disable/fault清零、命令超时和管理状态；
2. 目标软件：candidate-on交叉构建、map/反汇编、motion step与完整ISR WCET；
3. 仿真：给Torque/Velocity/Position分别冻结受限验收场景和通过条件；
4. powered：重新确认电源/限流/空载/立即断电条件后，按Torque→Velocity→Position逐级进行，
   三种模式证据不能互相替代。

## 结论

目标端已经加入一个**默认关闭、仅 Diagnostic 可用**的 24/12 kHz 定时候选，并通过
Host 测试、STM32 交叉构建以及 Rust、MATLAB/Simulink 两套修正时序仿真。它不改变
Rust 控制周期：TIM1 载波为 24 kHz，`RCR=3` 把 Update Event 分频到 12 kHz，ADC
注入组和完整控制 ISR 都由该 Update Event 触发；ISR 写入的 CCR preload 在下一次
12 kHz Update Event 生效，因此采样到输出生效的设计延迟是 **2 个 PWM 周期，即
1 个控制周期（83.33 μs）**。

A7 使用的“24/12 kHz + 1 个 PWM 周期延迟”已被否决。当前完整 ISR 的实机最坏记录
约为 7,975 cycles，而 170 MHz / 24 kHz 只有约 7,083 cycles；现有实现不可能稳定地
在下一个 24 kHz 载波边界前完成。

本轮没有烧录、没有使能功率级、没有驱动电机。候选不能设为默认，也不能据此宣称
刺耳声已解决；下一道门是断电/禁输出条件下的寄存器和示波器时序验证。

## 1. 真实目标链路

```text
TIM1 中心对齐 24 kHz，ARR=3541，RCR=3
  │
  ├─ 每 4 个半周期产生一次 UEV/TRGO = 每 2 个完整 PWM 周期 = 12 kHz
  │    └─ ADC1/ADC2 injected 同步采样
  │         └─ ADC1 JEOS IRQ（唯一快环入口）
  │              ├─ 读取两相电流并重构第三相
  │              ├─ 过流/驱动故障检查
  │              ├─ foc_rust_realtime_step()
  │              ├─ 输出范围复核
  │              └─ 写 CCR1/2/3 preload
  │
  └─ 下一次 12 kHz UEV：preload 转入 active CCR，命令开始生效
       └─ 固定设计延迟 = 2 个 24 kHz PWM 周期 = 83.33 μs
```

STM32G4 参考手册规定：中心对齐模式下重复计数器按半个 PWM 周期计数，`RCR+1`
决定 UEV 间隔；UEV 同时承担预装载寄存器向活动寄存器的传送。本设计因此使用
`RCR+1 = 2 × fpwm/fcontrol = 4`。依据见
[STM32G4 Reference Manual RM0440](https://www.st.com/resource/en/reference_manual/dm00355726-stm32g4-series-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。

## 2. 为什么不用 24 kHz ADC/ISR

| 项目 | 数值 | 结论 |
|---|---:|---|
| MCU / TIM1 时钟 | 170 MHz | 当前目标配置 |
| 24 kHz 单载波预算 | 7,083 cycles | 仅 41.67 μs |
| 已记录完整 ISR 最坏值 | 7,975 cycles | 超过单载波预算约 12.6% |
| 12 kHz 控制预算 | 14,166 cycles | 保留现有完整快环频率 |
| 候选设计延迟 | 2 PWM 拍 | 与一个 12 kHz 控制间隔一致 |

如果仍用 OC4REF 在每个 24 kHz 周期触发 ADC，前一次 ISR 可能尚未完成，下一次
注入转换就已经到达，造成重入、积压或丢采样。因此多速率候选禁止 OC4REF，统一用
经 RCR 分频的 Update TRGO。

## 3. 默认路径仍有一个待测相位

默认配置保持原来的 12/12 kHz、`RCR=1`、OC4REF rising 触发，未为了文档结论去改变
已经实机运行过的采样位置。仿真用 `actuationDelayPwmTicks=1` 表示整 PWM 拍离散近似，
但这不是实测值：OC4REF 位于顶点附近，而 UEV 出现在中心对齐计数边界；具体 UEV
落在溢出还是下溢还受 RCR、UG 和启动顺序影响。当前约 46.9 μs 的最坏 ISR 时间也
略长于 12 kHz 半载波的 41.67 μs。

因此必须区分：

- 24/12 kHz Update 候选：相邻控制 UEV 之间固定 2 个 PWM 周期，设计延迟确定；
- 12/12 kHz OC4REF 默认：1 拍是当前离散模型的名义值，物理采样到 active CCR 的
  精确延迟可能包含额外半周期，必须用示波器/逻辑分析仪确认；
- 两者的 PC 仿真结果只能作为设计比较，不能代替目标板相位测量。

## 4. 代码和配置落位

| 路径 | 作用 |
|---|---|
| `foc/include/foc_pwm_timing.h`、`foc/runtime/foc_pwm_timing.c` | 纯 C 定时契约；校验整数频率比、ARR、RCR、触发源和名义延迟 |
| `foc/platform/stm32g431/foc_platform_stm32g431.c` | 默认 12/12；Diagnostic 候选 24/12、RCR=3、Update TRGO；初始化前先校验契约 |
| `board/Kconfig` | 新增默认 `n` 的 `FOC_PWM_24K_CONTROL_12K_CANDIDATE` |
| `custom.cmake` | 构建时打印最终有效时序；Production 明示忽略残留候选开关 |
| `applications/main.c` | 状态输出 PWM/control/ratio/delay/trigger；Rust 控制频率与平台控制频率不一致时拒绝绑定 |
| `tests/host/test_foc_platform.c` | 锁定两种合法方案并拒绝错误 RCR、延迟和触发源组合 |
| `rust/crates/foc-sim/src/scheduler.rs` | 默认 12/12 + 1 拍；候选 24/12 + 2 拍；允许延迟等于一个控制间隔 |
| `simulink/*` | 同步 1/2 拍真实候选，修复两拍 Delay block 初值维度 |

保护边界：

- `.config` 默认仍为 `# CONFIG_FOC_PWM_24K_CONTROL_12K_CANDIDATE is not set`；
- `closed_loop_enable=0` 不变；
- Production 即使残留候选宏，也无条件构建为 12/12 kHz；
- 初始化时定时契约失败会调用紧急停机，不继续配置功率级；
- 本轮未修改 Rust FOC 算法、观察器参数、PI 参数或保护阈值。

## 6. 本轮发现并修正的失败

1. 把默认延迟从 0 改为 1 后，死区补偿单元测试阈值失败。该测试的目的只是隔离比较
   补偿效果，因此显式使用零延迟，没有放宽断言。
2. Simulink 两拍延迟首次因 Delay block 初值维度错误失败：`3x1` 和 `3x2` 都不符合
   三相、两拍状态维度；修正为 `3x1xN` 后通过。
3. A7 的一拍候选假设经目标源码核对后被否决；A7 保留为历史记录并指向本报告。

## 7. 证据边界与下一道门

本轮证据等级为 S0/S1/S2/S3，没有 S4/S5：

- 未烧录本轮三个镜像；
- 未读取板上 TIM1/ADC 寄存器；
- 未用 PA5 timing probe 测 ADC ISR 周期、脉宽和抖动；
- 未测 ADC 触发沿到 CCR active 生效的真实相位；
- 未使能三相输出，也未运行电机。

下一步应先做**无功率输出时序门**：保持栅极使能、CCER1..3 和 MOE 关闭，烧录
Diagnostic 候选，核对 ARR/RCR/MMS/ADC JEXTSEL/JEXTEN；用 PA5 timing probe 测得
12 kHz ISR 周期和最坏脉宽，再用计时器输出/调试捕获确认 UEV 与 CCR preload 生效
关系。只有该门通过，才申请 2 A 限流下的短时空载电机 A/B。

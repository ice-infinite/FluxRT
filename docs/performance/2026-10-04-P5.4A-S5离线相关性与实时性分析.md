# P5.4A 第九次 S5 离线相关性与实时性分析

## 1. 结论

用户已确认断开 12.3 V 主电源。本轮只复核既有源码、S3 仿真 CSV、历史实机 trace 和
第九次 S5 结果，没有访问串口、烧录、arm 或运行电机。

三项待分析数据的结论如下：

1. `796 rpm` 不是已证实的稳态速度误差，也没有发现 rpm、rad/s 或极对数换算错误。
   第九次事务恰好在接管过冲尚未回落的 7.254 s 左右自动结束；同板历史实机在 7.26 s
   的 64 ms 观察器均值为 795 rpm，S3 同构模型约为 785 rpm。该数值属于已知接管瞬态。
2. `0.912 A` 是三相 ADC 样本的全事务瞬时最大值，不是 0.8 A 的稳态 `Iq` 给定。
   它落在既有同板启动约 0.896～0.939 A 的重复包络内，当前没有新过流回归证据。
3. `12,469 / 12,750 cycles` 没有 deadline miss，但对项目软件截止只余 281 cycles
   （2.20%）。相对 170 MHz / 12 kHz 的物理周期约 14,167 cycles，余量约 1,698 cycles
   （11.98%）。这足以解释本次 PASS，不足以授权叠加其它 Advanced feature。

因此当前不修改控制参数、不提高 deadline、不放宽观察器门，也不重跑 powered S5。
下一步应先做 Advanced 热路径结构优化和分模式 S2/S4 WCET 复验。

| CM4/A10 历史报告与 WCET 日志 | 电流峰值和 Basic 热路径范围 | 不同诊断组合不能当成严格 A/B |

瞬态是否一致”，不能确认实机真实机械速度等于观察器输出。

## 3. `796 rpm` 的时间对齐

第九次 S5 的连续可靠窗从第 85,851 拍开始，在第 87,050 拍结束；按 12 kHz 换算为
约 7.154～7.254 s。完成快照中的 `speed=796` 是观察器最近 64 个 1 ms 统计样本的均值，
不是命令值，也不是单拍值。

| 时刻/数据源 | observer 64 ms 均值 | 模型真实速度 | 说明 |
|---|---:|---:|---|
| S5 完成，约 7.254 s | 796 rpm | 无 | 第九次板端快照 |
| 历史同板实机，7.26 s | 795 rpm | 无 | 与 S5 只差 1 rpm |
| S3 同构模型，7.254 s | 约 785 rpm | 约 782 rpm | 与 S5 相差约 11 rpm / 1.4% |
| 历史同板实机，8.00 s | 599 rpm | 无 | 已明显回落 |
| 历史同板实机，10.00/12.00 s | 582/582 rpm | 无 | 后续窗口回到目标附近 |
| S3 同构模型，9.00 s | 约 574 rpm | 约 574 rpm | 模型中观察器与 plant 同步回落 |

历史实机还显示接管后均值峰值约 829 rpm；S3 中观察器与 plant 同时加速到约 780 rpm，
说明仿真把这段现象解释为启动/接管的机械过冲，而不是单纯观察器比例偏差。由于实机没有
机械速度真值，这仍是有数据支持的推断，不能写成已确认事实。

源码换算链也保持一致：PLL 电角速度乘 `30/pi` 后除以 7 对极得到机械 rpm，遥测再由机械
rad/s 乘 `30/pi` 输出 rpm；没有发现重复除极对数、漏除极对数或 `60/(2*pi)` 写错。

结论：第九次 100 ms 窗结束得太早，不能用结束快照评价稳态速度。后续若需要证明稳态，
必须设计新的有界长窗并取得独立速度真值；当前不因 `796` 修改 PI 或观察器增益。

## 4. `0.912 A` 的口径

板端 `pk=572(912mA)` 是启动至停止期间三相电流 ADC 相对零点的最大绝对样本。它与
`startup_current_a=0.8 A`、速度 PI 的 0.8 A `Iq` 限幅不是同一统计量：前者含换相纹波、
采样噪声、零点误差和启动瞬态，后者是旋转坐标系电流矢量给定。

既有同板数据包括：

- CM4 多次启动的全局峰值约 0.896～0.936 A；
- A10 的三次 12/12 kHz 闭环峰值约 0.903～0.908 A；
- 历史同配置 582 rpm 正向记录约 0.939 A；
- 第六至第九次 P5.4 数据约 0.869～0.912 A。

所以本次 0.912 A 位于已有包络内，并低于 1.15 A 软件 trip。它不能证明电流标定准确，
也不能据此提高电流限值。保持 0.8 A 给定和 1.15 A 保护不变。

## 5. WCET 归因

第九次同拍最坏记录为：

```text
total=12469, pre=1206, control=9959, post=1304 cycles
peak_control=10016, deadline=12750, miss=0
```

三个分段相加严格等于 12,469，说明最坏完整拍记录自洽。`peak_control=10016` 是独立分段
峰值，不能与该拍的 pre/post 再相加。

对比当前 Basic ELF 和保留的 Advanced ELF，静态符号显示：

| 符号 | Basic | Advanced 历史镜像 | 增量 |
|---|---:|---:|---:|
| `foc_rust_realtime_step_core` | 3,556 B | 4,592 B | +1,036 B |
| `ADC1_2_IRQHandler` | 2,024 B | 3,528 B | +1,504 B |

这与源码调用链一致：Advanced Diagnostic 即使 `feature mask=0`，P5.4 owner 每拍仍执行
`begin_tick`、基础 Rust realtime、紧凑 snapshot 获取、控制包络验证和 commit 计数。
Rust 内部 feature=0 已跳过 Advanced 算法 supervisor，但更大的 realtime core、额外 FFI/
快照和 ISR 分支仍会影响 Flash 取指与 post-control 时间。

以上只能定位优化方向，不能把代码字节数换算成周期。P5.3 全功能固定输入曾测得
12,548/12,750 cycles，只余 202 cycles，也说明风险不只来自本次 P5.4 Shell owner。

## 6. 后续整改顺序

按风险和可验证性排序：

1. **拆分 Basic 热路径**：让 feature=0 走独立的小型 `#[inline(never)]` 基础快环函数，
   Advanced policy 作为显式 wrapper，避免可选策略扩大常态指令路径；不得改变控制公式。
2. **消除第二次状态读取**：P5.4 Diagnostic 由同一次 realtime ABI 返回紧凑验收字段，避免
   每拍再次进入 `foc_rust_get_advanced_power_trial_snapshot()`；仍须在 CCR commit 前验证。
3. **建立分模式周期矩阵**：分别测 feature=0、dq decoupling、MTPA、FW、MTPV、调制策略，
   记录完整 ISR 和 control/post 分段，不能只测“全部功能固定输入”。
4. **保持 12,750-cycle 截止**：禁止用提高 deadline 掩盖超预算；优化后先过 Host/ARM/S2，
   再在主电源断开的 S4 复测 DWT 与 PA5。
5. **容量同步门**：Advanced 镜像只余 864 B Flash，任何 ABI/诊断新增都要同时给出 size/map，
   必要时先裁剪 Shell 文本和仅实验使用的报告字段。

只有 feature=0 和计划启用的单项 feature 都取得可接受且可重复的余量，才重新评审下一次
powered 验证。当前不会自动进入 dq decoupling 或延长电机运行时间。

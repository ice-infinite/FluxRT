# P5.5-H3 反向固定查询与双向离线验收软件门

## 结论

H3 专用镜像已从正向查询切换为**编译期固定反向查询候选**。源码、Host测试、目标
交叉构建以及主电断开条件下的USB/ST-LINK S4均已完成；没有使能PWM，也没有接触
12.3 V主电源。

该候选仍然不是参数批准或全速域能力批准。它只为下一次单次带功率授权准备反向证据，
用于与 2026-10-05 已取得的正向 H3 证据做离线一致性比较。

## 固定包络

- 唯一操作令牌：`P55-H3-REV`；旧 `P55-H3-QUERY` 在该镜像中不再接受；
- 目标机械转速：`-582 rpm`，符号由编译期常量固定；
- Rev-Up 终速配置仍使用正的 `582 rpm` 幅值，运行方向只由带符号 start 命令决定；
- active 窗口仍为 1,200 个已提交控制拍；
- Advanced feature mask 仍为 0；
- 电流、速度幅值、时长、feature 和方向都不能由 Shell/Host 修改；
- Host 每次进程只发送一次命令，没有重试循环；失败后只执行 `foc_stop`；
- fault epoch 变化、deadline miss、观察器回退、同步锚点失败或结果格式异常仍立即失败；
- 结果必须证明负转速、`miss=0/0`、`diagmiss=0`、`finish=0` 和最终
  `FOC st=0 rf=00000000 duty=0/0/0`，否则 capture 标记失败。

下一次带功率命令形式固定为：

```text
foc_advanced_trial P55-H3-REV <session> <start_sequence> <start_tag>
```

Host 采集工具要求新的人工授权串：

```text
P55_H3_REVERSE_12V3_2A_UNLOADED
```

它与此前正向授权不通用，不能复用旧授权启动反向试验。

## 正反向离线比较

新增 `tools/foc_h3_bidirectional_compare.py`。工具不访问串口、不修改目标配置，只读取一个
`fluxrt-h3-bidirectional-consistency` V1 manifest，并对每一侧绑定以下 SHA-256 证据：

1. `capture.summary.json`；
2. `time-map.manifest.json`；
3. 应用独立 alignment offset 后的 `time-map-*.result.json`；
4. `alignment-offset.result.json`。

工具还会从 capture summary 绑定的 `raw-lines.csv` 回查：

- 每个方向恰好只有一个完成的 H3 attempt；
- 正向最终速度为正、反向最终速度为负；
- 1,200 accepted ticks、fault epoch 未变化、零 deadline miss；
- feature/status/observer-loss 均为零，闭环和观察器可靠；
- `FH3R` 与 summary 锚点数一致；
- `FH3R` 之后存在 disabled/zero-duty 终态。

manifest 自己提供并冻结以下比较界限，工具不在代码中偷偷替用户决定产品阈值：

- 单侧最少锚点、query 和可靠样本数；
- 时钟漂移与锚点残差；
- 单侧 RMS/最大角误差；
- alignment candidate 离散度；
- 正反向 alignment offset 圆周差；
- 正反向最终速度幅值差；
- 正反向 RMS/最大角误差差。

任一文件哈希、身份、方向、安全终态或界限不满足都会拒绝生成结果。成功结果仍固定为：

```text
bidirectional-consistency-candidate-not-approved
```

且 `parameter_approval`、`target_capability_approval` 都保持 `not-granted`。

schema 位于：

```text
profiles/schema/fluxrt-h3-bidirectional-consistency-v1.schema.json
```

- 旧令牌`P55-H3-QUERY`返回`FADVP,h3-token`；

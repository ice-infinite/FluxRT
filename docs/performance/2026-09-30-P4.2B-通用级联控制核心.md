# P4.2B 通用级联控制核心

## 范围

本阶段在P4.2A参考规划器之后新增`foc-control::motion_cascade`，实现默认关闭、无堆、
板级无关的`Position P -> Velocity PI -> Torque -> Iq`级联。它复用既有PI的反算
anti-windup和`preload_output`，但不修改V19/V20快环、电机参数、配置schema、C ABI、
Shell、ISR或硬件。

## 交付

- `MotionCascadeConfig`：真实控制周期、位置P、速度PI和外部提供的转矩常数；
- `MotionCascadeFeedback`：机械位置/速度与实际q轴电流及有效位；
- `MotionCascadeController`：三模式级联、前馈合并、动态PI余量、最终转矩/电流限制；
- transition契约：首次或模式/InputMode变化必须显式标记，并从实测Iq预装输出；
- 事务式失败：非法配置/参考、未知flag、缺失/非有限反馈和非法切换不改变PI或输出状态；
- 12项专项测试：默认关闭、事务拒绝、三模式、切换预置、反馈门、前馈余量、长饱和、
  反向解除和P4.2A→P4.2B字段直连。

## 控制与限制顺序

```text
P4.2A MotionReference
  Position: position error * Kp + planned velocity + velocity feed-forward
  Velocity: velocity reference
                         |
                         v
                  velocity limit
                         |
                         v
              Velocity PI + torque feed-forward
                         |
                         v
     min(torque_limit, current_limit * torque_constant)
                         |
                         v
              Iq = torque / torque_constant
```

转矩前馈先从PI可用输出范围中扣除，PI饱和时使用既有反算逻辑；相加后仍执行最终限制。
因此前馈不能绕过anti-windup或电流上限。`torque_constant_nm_per_a`由以后配置映射提供，
本阶段没有写死GBM2804H-100T候选值。

## 失败与修正

- 第一轮专项测试有两个断言失败：测试构造的position/velocity transition参考没有像P4.2A
  那样从实测位置/速度预置，导致该用例无法保持指定转矩；已修正测试输入以符合真实上下游
  契约，没有放宽控制器检查。
- 另一项暴露“PI动态边界已生效但输出标志未记录”的诊断缺口；现在PI输出落在动态边界时
  明确置`TORQUE_LIMITED`，最终数值限制本身未改变。
- 一次只读哈希汇总命令因PowerShell把直接`foreach ... |`解析为空管道失败；改为先收集数组
  再格式化，未修改源码或构建产物。

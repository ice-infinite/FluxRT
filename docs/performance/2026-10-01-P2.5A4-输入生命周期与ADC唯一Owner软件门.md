# P2.5A4 输入生命周期与 ADC1 唯一 Owner 软件门

日期：2026-10-01
证据等级：S1 主机测试 + S2 STM32G431 交叉构建
硬件状态：未烧录、未连接串口、未采集 PC2、未使能功率级、未转电机

## 1. 本批结论

P2.5A4 的**软件部分**已经接通：管理任务中的唯一 input owner 负责 raw port
启停、读取最新样本、调用 Rust 归一化、提交 `InputService -> CommandService`，并在无样本超时、
越界、坏布局或端口故障时把来源标为不健康并提交一次 `RELEASE`。ADC1 regular group 也有了
显式唯一所有权：PC2 raw driver 持有时，旧 HAL 轮询监控不会再改写 `SQR1/SMPR1/ADSTART`。

这还不是 Analog 产品功能完成：STM32G431 的 `board_input_mask` 仍为 0，默认 Kconfig 仍关闭，
没有真实配置服务调用启停事务，也没有无功率 S4、ISR WCET/jitter 或 PC2 电气范围证据。

## 2. 数据与所有权主线

```text
ADC ISR 静态 tick
    -> STM32G431 PC2 raw driver（仅原始码/时间戳/质量）
    -> target-neutral raw port
    -> ExternalInputOwner（10 ms management owner）
    -> Rust foc-input Analog 归一化
    -> SimpleInputCandidate（只允许 Setpoint）
    -> InputService
    -> CommandService
    -> Rust CommandArbiter
```

禁止边界保持不变：raw driver 和 input owner 都不能请求 Axis、arm 功率级、写 TIM1 CCR 或直接
修改 FOC context。

## 3. 实现内容

### 3.1 生命周期 owner

新增 `applications/foc_external_input_owner.h/.c`：

- 只有在 `Disabled + drive_active=0 + active_fault_flags=0` 时接受配置；
- 根据 active config 的 input mask 启停 raw port；
- 每个输入只消费新的 sequence，重复快照不会重复生成命令；
- Analog 样本通过现有持久化标定映射到 Rust `foc-input`；
- 成功样本更新 healthy、setpoint、recovery 计数；
- timeout、越界、坏 raw 或端口故障只在每个故障 episode 首次提交一次 `RELEASE`；
- 新失败样本优先于同拍 timeout，避免故障原因被错误覆盖；
- 管理循环现在真实调用既有 External I/O poll，不再只有初始化没有 owner tick。

配置声明 `ControlledStop` 时，状态会保留“请求动作=ControlledStop”，但当前有效动作仍是
`RELEASE`。原因是简单输入的 source policy 只授权 Setpoint/Release，MotorService 还没有执行
ControlledStop 的入口。擅自把它伪装成已执行的 ControlledStop 会扩大权限，因此保持显式降级。

### 3.2 InputService 失效/恢复状态

`foc_input_service_mark_unhealthy()` 提供 owner 可调用的失效入口，并增加 `failure_count` 和
`recovery_count`。超时和外部判定失效都清除 healthy、置 expired；下一份有效新 sequence 才
恢复健康并累计 recovery。

### 3.3 ADC1 regular 唯一所有权

`foc_external_input_platform_regular_adc_owned()` 是平台私有所有权查询：

- PC2 driver 启用时，旧 `foc_platform_sample_monitor_inputs()` 不再对 ADC1 发起 HAL regular
  conversion；
- stop 时若 `ADSTART` 尚未清除，返回 `BUSY`，不提前把 ADC1 所有权交还；
- ADC injected current/Vbus 路径不由该 regular owner 接管，运行期同步采样仍保持原 owner；
- ADC1 被 PC2 占用且 injected 尚未运行时，监控路径明确 fail-closed，不会偷用 ADC1。

最后一条也意味着当前镜像不能据此开放 Analog 产品能力：arm 前的 Vbus/自检仍需要 ADC1
regular 监控。A4 硬件阶段必须先确定可验证的共享调度或把安全监控迁到独立采样路径，不能
简单把 `board_input_mask` 改成 Analog。

## 4. Flash 超限与结构修正

第一次 Analog feature-on 目标链接失败：ROM 145,212 B，超过 128 KiB 14,140 B。主要原因不是
本批 C owner，而是命令 ABI 为来源数 1～8 分别实例化 `CommandArbiter<N>`，把相同仲裁逻辑
单态化八次。

修正后：

- Rust 核心新增 `CommandArbiter::new_with_active_count()`；
- ABI 永远只保留一个 `CommandArbiter<8>`；
- `active_source_count` 决定有效前缀，尾部槽不会被查找、轮询或输出；
- 0、超容量、重复 ID、坏 lease/timeout 继续 fail-closed；
- C ABI、4 KiB caller-owned storage 和最多 8 来源的产品契约不变。

同一 feature-on 配置最终为 ROM 126,588 B、RAM 28,512 B，成功链接。该优化解决的是重复代码
生成，不改变仲裁优先级、sequence、lease、timeout、fault 或 EStop 语义。

## 6. 未关闭事项与下一门

1. `board_input_mask=0`，默认配置和 Kconfig 均关闭；不得把 S2 解释为板端可用。
2. 真实 Flash/RT-Thread 配置服务尚未调用 `foc_external_input_owner_apply_config()`；当前只有
   默认关闭的组合根和经 Host 证明的事务 API。
3. `ControlledStop` 等待 MotorService；目前只执行 `RELEASE` 安全降级。
4. PC2 与 arm 前 ADC1 Vbus/自检的共享调度尚未解决；这是开放 board capability 前的阻断项。
5. 尚未测 regular/injected 交错、ISR WCET/jitter、ADC 电气端点、断线噪声和恢复迟滞。
6. 下一步应先在明确断开电机主电源的条件下做 P2.5A4-HW 无功率 S4：烧录 feature-on
   诊断镜像、确认默认不启动、读取 `FRAW/FINPUT`、测启用前后 ISR 时序；但在第 4 项方案确定前
   仍不能开放 Analog 或用于 arm。

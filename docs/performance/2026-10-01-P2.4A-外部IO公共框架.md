# P2.4A 外部 I/O 公共框架检查点

## 1. 结论

P2.4A 已完成设备端、默认关闭、无物理驱动的外部控制与通信公共层：

- 固定布局的 capability、`ExternalIoConfig` 和资源冲突契约；
- 每个物理实例独立的 8 深度 RX/TX SPSC 队列；
- transport 健康与 CRC/parse/framing/drop/overflow/bus-off/watchdog 统计；
- 规范化输入的 source、sequence、quality 和 timeout 状态；
- adapter 到未来 Rust `CommandArbiter` sink 的唯一命令入口；
- Kconfig 总开关 `FOC_EXTERNAL_IO_FRAMEWORK`，默认关闭。

本检查点没有 UART、USB、CAN、PWM、DShot、Analog、Step/Dir 或 EtherCAT 驱动，也没有
协议 codec、持久化配置接线、真实 Rust arbiter sink、Host SDK 或 FluxRT Studio。

## 2. 代码边界

| 路径 | 职责 |
|---|---|
| `foc/include/foc_external_io.h` | transport/protocol/input mask、来源策略、配置、capability和验证结果ABI |
| `foc/runtime/foc_external_io.c` | compiled/board/configured三层校验、依赖、来源、时限和资源冲突 |
| `applications/foc_transport_service.c/.h` | 每实例SPSC收发、健康和统计；不解析协议 |
| `applications/foc_input_service.c/.h` | 保存adapter已经规范化的输入快照并检测timeout；不生成PWM或arm |
| `applications/foc_command_service.c/.h` | 配置唯一sink、来源权限和命令时效门；不直接访问MotorService/FOC/PWM |
| `board/Kconfig` | 只增加有真实实现的公共框架总开关；物理feature开关尚未创建 |
| `applications/SConscript`、`foc/SConscript` | 关闭时不编译P2.4A服务和runtime |

## 3. 安全和并发约束

1. 默认配置的transport/input mask全为0；编译框架不会启用任何入口。
2. 编译capability不自动声明板级capability，目标BSP必须再次提供物理资源表。
3. 启用transport或应用input/command配置必须处于Axis Disabled、drive inactive、无active fault。
4. 简单输入只能申请Release和Setpoint权限，不能通过配置获得AxisRequest/ClearFault/EStop。
5. `foc_command_service`必须先把来源策略交给唯一sink配置，之后才允许提交命令。
6. RX/TX队列均为单生产者/单消费者；多生产者必须在上层串行化，不得共享调用同一实例。
7. input timeout只产生expired状态；后续P2.4B2/P2.5通过arbiter生成Release/Stop，不在输入服务旁路。
8. bus-off/watchdog/driver error使transport unhealthy，恢复需要显式健康确认。

## 4. 验证证据

### 4.1 专项 Host 测试

严格选项：MinGW GCC `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror`。

| 测试 | 结果 |
|---|---|
| capability/config/compiled-board分离/CAN模式/来源/资源冲突 | PASS |
| feature宏到compiled mask，且不伪造board capability | PASS |
| RX/TX容量、FIFO、overflow、health和bus-off | PASS |
| input安全应用、来源、sequence回绕规则、timeout和恢复 | PASS |
| command默认关闭、来源权限、时效、sink配置/拒绝 | PASS |

专项结果：`5/5 PASS`。

### 4.2 全量 Host C

重新配置并构建`tests/host`后：`35/35 PASS`。其中前5项是本阶段新增，其余30项为现有回归。

### 4.3 ARM 严格交叉编译

四个新增实现使用Cortex-M4 hard-float、`-std=gnu11`、`-Os`和与Host相同的严格告警
直接编译通过。`arm-none-eabi-size`报告的代码段为：

```text
foc_external_io.o          1067 B text
foc_transport_service.o    1036 B text
foc_input_service.o         696 B text
foc_command_service.o      1064 B text
```

`arm-none-eabi-nm -u`没有发现`libatomic`依赖；只有预期的`memcpy/memset`和模块间符号。

### 4.4 默认关闭目标构建

执行Diagnostic `s`重新生成和构建：

```text
ROM 111516 B / 128 KiB (85.08%)
RAM  22472 B / 32 KiB  (68.58%)
```

`.config`为`# CONFIG_FOC_EXTERNAL_IO_FRAMEWORK is not set`；map中以下符号匹配均为0：

- `foc_external_io_validate_config`；
- `foc_transport_service_init`；
- `foc_input_service_init`；
- `foc_command_service_init`。

因此默认镜像没有携带该候选代码。该结果只证明构建隔离，不证明任一外部接口可用。

### 4.5 全工程测试边界

`test.ps1`已执行到Rust Clippy：Python profile `147 PASS`、simulation tools `40 PASS`、Rust
`75 + 129 + 49 + 39 PASS`、闭环仿真PASS；随后被当前工作树既有Rust改动的两个Clippy问题
阻断：`advanced_foc.rs`的`field_reassign_with_default`和`controller.rs`的
`too_many_arguments`。它们不在P2.4A新增C文件中，本阶段未修改这些并行工作内容。

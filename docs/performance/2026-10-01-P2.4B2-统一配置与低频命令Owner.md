# P2.4B2：统一配置 V3 与低频命令 Owner

## 1. 结论

P2.4B2 已完成软件架构门：外部控制配置不再是旁路内存对象，而是进入同一套
`candidate -> validate -> apply -> commit/rollback` 配置模型；命令仲裁增加了唯一的低频
poll owner 和定宽只读事件快照。当前仍没有物理 UART/USB/CAN/PWM 等驱动，也没有把仲裁
结果送入 MotorService，因此不会 arm、启动 FOC 或修改 PWM。

本阶段把持久化 schema 从 V2 升为 V3，把当前槽从 512 B 扩为 768 B，并保持对旧
V0/V1/V2 512 B 记录的读取能力。旧记录迁移后 `ExternalIoConfig` 必定为全关闭默认值。

## 2. 实现范围

### 2.1 统一配置记录

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| schema | V2 | V3 |
| 当前槽大小 | 512 B | 768 B |
| 当前 payload | 340 B | 636 B |
| 当前 commit offset | 508 | 764 |
| 配置管理 ABI | V2 `0x00020000` | V3 `0x00030000` |
| C/Rust bundle | 348 B | 644 B |
| 调用者上下文上限 | 2 KiB | 4 KiB |
| 配置分组 | 6 | 7，增加 `ExternalIoConfig` |

V3 新增的 296 B `ExternalIoConfig` 固定包含四个 link、四个 simple input、来源权限、
优先级、lease、timeout、控制模式和失效动作。Rust 校验器拒绝未知位、重复 source ID、
矛盾的 CAN classic/CAN-FD 选择、非法时序和非规范关闭字段。

旧 V0/V1/V2 仍在 offset 508 检查 `CMIT`，V3 在 offset 764 检查；写计划携带实际
commit offset，避免把旧记录误按新槽尾解析。迁移只发生在 RAM，仍要求停机事务明确重存，
不会在启动恢复时偷偷擦写 Flash。

### 2.2 配置事务与 C ABI

- 新增 `CONFIG_GROUP_EXTERNAL_IO`，变更分类为 `ManagementOnly`；
- 新增 `ConfigPatch::ExternalIo` 和 `foc_rust_config_set_external_io()`；
- C executor 对 `APP | EXTERNAL_IO` 发出 Management action；
- `foc_external_io_management_apply_config()` 先用能力/资源/安全 guard 验证候选，失败时保留
  旧 active config；
- 真实 Flash adapter、RT-Thread 参数服务和启动恢复接线仍未实现。

### 2.3 唯一低频 poll owner

`foc_external_command_owner` 是 `CommandArbiter::poll()` 的唯一低频所有者。每次 tick 生成
308 B 定宽事件，包含 sequence、设备单调时间、poll 结果、仲裁决定和完整状态快照。

当前 owner 只发布只读事件：

- 没有 MotorService callback；
- 不进入 ADC/PWM ISR；
- 不创建 RT-Thread 线程或定时器；
- 不自动 arm，也不把 setpoint 写入 FOC；
- 没有物理 source 时，目标链接器可裁掉未被启动路径引用的 poll/配置符号。

P2.5/P2.6 接入真实输入源后，仍由一个管理任务串行调用该 owner；MotorService 消费者必须是
下一道独立安全门，不能让协议或 owner 直接控制功率级。

Flash、RAM、线程栈、ISR 和总线预算。

## 4. 已关闭与未关闭问题

已关闭：

- 外部配置与主配置原子性分裂；
- 512 B 当前槽容不下 296 B 外部配置；
- V0～V2 迁移可能意外启用新接口；
- 多个调用方直接 poll Rust 仲裁器；
- 配置失败覆盖现有 active config。

仍未关闭：

- 目标 Flash 擦写、磨损、掉电实测和 RT-Thread 参数服务；
- PWM/DShot/Analog/Step-Dir 采集；
- Native UART/USB/CAN/CAN-FD codec 与 transport；
- DroneCAN/VESC CAN/CANopen 映射和 EtherCAT 平台；
- 仲裁决定到 MotorService 的执行安全门；
- P2.9 设备端上位机消息以及最终 FluxRT Studio。

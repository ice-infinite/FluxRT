# P2.5A4-HW1 ADC2 母线安全采样前置门

日期：2026-10-01
证据等级：S1 主机测试 + S2 STM32G431 交叉构建
硬件状态：未烧录、未连接串口、未采集 PC2、未使能功率级、未转电机

## 1. 结论

PC2/ADC1_IN8 持有 ADC1 regular group 时，故障恢复不再尝试抢回 ADC1。安全监控改从同一
物理母线分压信号 `PA0/ADC12_IN1` 的 ADC2 通路读取新鲜 Vbus；温度也继续由 ADC2 读取。
相电流与电位器不会在这条降级路径上伪造新样本，只有同步 injected monitor 重新启动后，
相电流反馈才重新标记为有效。

这关闭了 A4-HW 的**软件调度阻断项**，但还不是板端验收：`board_input_mask` 仍为 0，默认
Kconfig 仍关闭，也没有真实 ADC1/ADC2 一致性、regular/injected 交错、WCET 或 PC2 电气证据。

## 2. 冲突窗口与路由

真正的冲突窗口是：Break/紧急停止已经停掉 TIM1 injected 时基，而 PC2 输入配置仍启用。
此时 fault-clear preflight 必须取得新鲜 Vbus，却不能改写 PC2 owner 正在使用的 ADC1
`SQR1/SMPR1/ADSTART`。

| Sync monitor | ADC1 regular owner | 软件轮询计划 |
|---|---|---|
| 停止 | 无 | ADC1 采相电流、Vbus、电位器；ADC2 采 W 相与温度 |
| 运行 | 无 | 沿用 injected 相电流；ADC1 采 Vbus/电位器；ADC2 采温度 |
| 停止 | PC2 | **ADC2 采 Vbus/温度**；不采相电流、不碰 ADC1 |
| 运行 | PC2 | injected 相电流/Vbus持续更新；管理监控只用 ADC2，不碰 ADC1 |

`foc_monitor_sampling_plan()` 是不含 HAL 的纯策略函数，四种组合均由 Host 测试锁定。

## 3. 安全边界

- ADC1 被 PC2 持有时，监控计划中不存在任何 ADC1 regular conversion；
- Vbus 仍来自同一 `PA0/ADC12_IN1`，只是 ADC 实例从 ADC1 切到 ADC2；
- 使用 ADC2 fallback 成功后置位历史诊断位
  `FOC_PLATFORM_DIAG_ADC2_VBUS_FALLBACK_USED`；
- 全量 emergency stop 和 Break IRQ 停止同步时基时，同时清除
  `FOC_PLATFORM_DIAG_SYNC_SAMPLES_VALID`，避免把停机前相电流当作新鲜反馈；
- fallback 采样失败仍置 `FOC_PLATFORM_DIAG_ADC_READ_ERROR` 并使 fault-clear fail-closed；
- 不改变 input owner、CommandService、arm、TIM1 CCR、Gate/MOE 或功率级所有权。

## 5. 下一门

用户明确确认电机主电源断开后，才能生成并烧录 feature-on 诊断镜像，执行无功率 S4：

1. 启动后证明 Analog 默认未启用、Gate/MOE/CH1～3 均关闭；
2. 比较 ADC1 与 ADC2 对同一 Vbus 的原始码和换算值，建立允许偏差；
3. 启用 PC2 raw capture，观察 `FRAW/FINPUT` 的 sequence、漏采、超时和恢复；
4. 触发停机/恢复路径，确认 ADC2 fallback 位和 fault-clear 行为；
5. 测 regular/injected 交错下的 ISR WCET、间隔抖动和 deadline miss；
6. 全部通过前保持 `board_input_mask=0`，不接 MotorService、不允许输入自动 arm。

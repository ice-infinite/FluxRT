# 2026-10-07 P5.5 复合快环 256 拍分解：稳态成本与首拍同量级，全程超出软件 deadline 约 31%

日期：2026-10-07
基线：`main@e277d49` + 本提交（mode 3 分解记录器）
证据等级：S4（烧录 + 无主电板端运行）
板：NUCLEO-G431RB + X-NUCLEO-IHM16M1，ST-LINK `00400027544B500120343637`，COM6@115200
主电源：**12.3 V 物理断开**，全程仅 USB/ST-LINK；未使能 Gate/MOE/CCER，电机未动

---

## 1. 结论

**复合快环入口不存在可优化的"冷启动惩罚"。** 首拍与随后 255 拍的整拍耗时同量级，全程约为 12,750-cycle 软件 deadline 的 **131%**：

| 项 | 整拍 cycles | control 段 | 占 deadline |
|---|---:|---:|---:|
| 首拍（tick 0） | 16,648 | 16,130 | 130.6% |
| 后续最小 | 16,723 | 16,218 | 131.2% |
| 后续最大 | 16,818 | 16,313 | 131.9% |
| 256 拍均值 | ≈16,760 | ≈16,255 | ≈131.5% |

**因此：**

- 复合快环**当前形态无法满足 12,750-cycle 的每拍预算**，且超出门槛约 4,000 cycles（31%）；
- 超支**不是**初始化、观测器复位、分离器首次更新或首次三角计算造成的——那些是一次性的，此处看不到；
- **control 段占整拍约 97%**，说明成本集中在快环计算本身，而非前后处理。

**这条结论把裁剪目标从"优化冷启动"改为"削减稳态计算约 4,000 cycles（24%）"。**

## 2. 测量方法与原始数据

### 方法

mode 3 采集 256 拍，每拍的 `timing_sample.total_cycles` 与 `control_cycles` 在 ISR 内写入固定 RAM 缓冲（`uint16_t[256] × 2`），ISR 退出后由 Shell 命令 `foc_sensorless_wcet_decomp` 输出。**ISR 内不打印**（见 `AGENTS.md` 第 8 条）。

### 唯一的阈值放松（已评审的例外）

为让探针活过自身超支，仅放宽**一个比较**：mode 3 探针仍在填缓冲期间，ISR deadline 比较使用 `FOC_SENSORLESS_PROBE_DEADLINE_RELAXED_CYCLES = 1,000,000`。

- 超支**仍然计数**、仍然置 `FOC_PLATFORM_DIAG_DEADLINE_MISSED`、仍然上报（实测 `miss=1`）；
- 不触碰任何故障锁存、安全位、arm 门、电流限、母线窗；
- 存在理由仅在于：deadline 守卫保护的是**活动控制环**，而本探针没有——控制器未 arm、Gate/MOE/CCER 每拍复核 safe-off、输出无法到达引脚；
- 由缓冲容量界定，随探针结束而失效。

**此例外不得复制到任何 armed 路径。**

## 3. 观察与边界

### 观察

1. **首拍不比稳态便宜**：16,648 vs 16,723–16,818。差异约 1%，落在抖动内。
2. **抖动小**：256 拍极差 95 cycles（16,723–16,818），约 0.57%。重复采样（如 `16740` 连续两拍、`16817` 连续三拍）说明计时量化远低于拍间差异。
3. **control 段主导**：占整拍 96.9%（16,130/16,648）～97.0%。前后处理合计约 520 cycles。
4. **仍有 ~2.15% 的余量结构**：整拍 16,648 中 control 16,130，前段+后段约 518 cycles——若 control 段能压到 12,232，整拍即可回到 12,750。

### 边界（不得外推）

- 这是**单一镜像、单次运行、单板、空载、合成电流**的样本；
- 合成电流为未通电 ADC 读数（约 1.5 mA 量级），**不代表带功率工况**；带功率的电流幅值、观察器可靠性状态与启动链阶段都会改变分支走向，成本可能不同（更高或更低）；
- 256 拍仅为 12 kHz 下的 21 ms，**不覆盖长测**；
- 未测带功率、未测不同 feature 组合、未测不同目标转速。

### 仍未澄清

`r=5`（`FAULT_EPOCH_CHANGED`）的产生点。本轮已能确定它**不是** `complete_commit` 内部独立检测到的早期纪元变化：256 拍连续采集期间 `chain_status` 为 0 且链全程 Ok，说明提交路径本身工作正常；探针在第 256 拍停止与缓冲填满同拍发生，指向"deadline 超支在缓冲填满后重新锁存故障"这一机制（正常阈值恢复 → 尾部 deadline 检查 → 锁存 → 纪元递增）。

**该项不影响第 1 节结论。**

## 4. 建议的下一步

裁剪目标已量化：**稳态需削减约 4,000 cycles（24%），且必须落在 control 段内（占 97%）。**

建议按"先测量、后裁剪"推进，避免对成本分布错误的部位做优化：

1. **对复合事务做分段计时**：在 `foc_rust_realtime_step_sensorless` 内部按阶段（Clarke、链步进/融合、Park/逆 Park、电流 PI、HFI 注入合成、最终圆限幅、SVPWM）逐段取 DWT 差值，写入 RAM 缓冲后由线程输出。**这需要在 Rust 侧提供分段计时钩子，或由平台在调用前后分点采样**；
2. 依据分段结果选择裁剪对象。既有记录中已验证有效的手段（`LOG-20261003-007`）：降低观察器与区域策略速率、减少搜索步数、合并重复的三角函数与限幅事务；
3. 裁剪后重跑本分解测量，以同样的 256 拍窗口对比。

**在分段数据到手之前不建议盲目改算法**——上一轮的教训（把不是瓶颈的契约当作瓶颈修了多轮）正适用于此。

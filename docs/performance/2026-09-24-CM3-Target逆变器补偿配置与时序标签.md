# CM3 Target 逆变器补偿配置与时序标签

## 1. 结论

CM3 的软件接入阶段已完成：CM2 的死区/器件压降模型已进入目标控制路径，
但三层开关默认全部为 `0`，因此当前默认控制数值不变。目标映像的 map 中
`feedforward_pwm` 和 `observer_equivalent_pwm` 均有真实 Flash 地址，不再是 CM2 的
`0x00000000` 已丢弃 section。

本轮已达到 S1/S2/S3、无功率 S4 和受限开环 S5 首轮：Calibration 和 Diagnostic
完成 SWD download/verify/reset，Diagnostic 已实机验证 stage `0/1/2/3/4/0`
配置与 `FTIMING` 标签一致；随后在约 12.3 V、2 A 限流、空载条件下完成五档各 5 秒
开环 WCET/A-B，均为 0 error/miss/fault。当前板上是修正 tshell 栈溢出后的 CM3
Diagnostic，已复位回 stage 0、输出关闭。后续 CM4 已完成多次开环启动，但首次基线
闭环请求因 observer startup timeout 未完成接管；详见本文末尾的 CM4 报告入口。

## 2. 配置与 ABI

| 项目 | CM2 | CM3 |
|---|---:|---:|
| Rust ABI | V12 | V13 (`0x000D0000`) |
| Runtime config | V6 / 240 B | V7 / 276 B（69 words） |
| 逆变器子配置 | 无 | 36 B（9 words） |
| runtime CRC-32 | `0x8C7A8DF4` | `0xBA1927ED` |
| profile record CRC-32 | 旧值 | `0x62724C5E` |

逆变器子配置包含三个层次的开关：

1. `enabled`：总门；
2. `observer_voltage_correction_enable`：只修正观测器使用的上一拍等效电压；
3. `pwm_feedforward_enable`：只修正实际下发 PWM。

任一子门在总门为 `0` 时都会被配置校验拒绝。启动默认为
`enabled/observer/feedforward = 0/0/0`；候选参数仅是待实测起点：

| 参数 | 默认值 |
|---|---:|
| 载波频率 | 12,000 Hz |
| 死区 | 550 ns |
| 补偿增益 | 1.0 |
| 零电流软带 | 0.005 A |
| 极性滤波 alpha | 1.0 |
| 等效器件压降 | 0 V |

`pwm_carrier_frequency_hz` 是实际载波频率，不是历史字段
`pwm_frequency_hz` 代表的控制频率。校验要求载波不低于控制频率且为其
整数倍；启动时还会将这两个值分别与平台诊断快照核对。

## 3. 运行路径与管理门

```text
三相电流 -> 一次/控制拍更新极性滤波
                 |-> observer gate -> 修正上一拍 PWM -> CommandModel -> SMO/BEMF-PLL
PI/SVPWM --------|-> feedforward gate -> 修正本拍 PWM -> C 二次安全检查 -> TIM1
```

Diagnostic 档只提供一个紧凑的停机配置入口，避免继续向 128 KiB Flash
中加入大量 Shell 解析代码：

| 命令 | 总门 | 观测器修正 | PWM 前馈 |
|---|---:|---:|---:|
| `foc_cfg invstage 0` | 0 | 0 | 0 |
| `foc_cfg invstage 1` | 1 | 0 | 0 |
| `foc_cfg invstage 2` | 1 | 1 | 0 |
| `foc_cfg invstage 3` | 1 | 0 | 1 |
| `foc_cfg invstage 4` | 1 | 1 | 1 |

`foc_cfg` 在 `REALTIME_ARMED` 时拒绝所有修改，候选配置必须先整体通过 Rust
校验才原子提交。Production profile 还会显式把三个门恢复为 `0`，当前
`approvals=0` 的档案仍不允许闭环。

参数本身的正式入口是 V7 ABI/profile，而不是在高度紧张的 Diagnostic 镜像中
为每个浮点数增加独立 Shell 命令。

## 4. 时序证据接口

`FTIMING` 格式版本由 1 升到 2，尾部新增三个字段：

```text
inverter,inverter_observer,inverter_feedforward
```

这使每条 WCET 记录都能证明当拍所属的补偿阶段。
`simulation/capture_timing_baseline.py` 会拒绝旧版格式、非 0/1 标志，以及
总门关闭时子门仍打开的不可能状态。

## 7. 受限 S5 首轮开环 A/B

用户重新确认 2 A 电源限流、电机空载自由旋转且可立即断电后，在约 12.3 V 母线下按
stage `0 -> 1 -> 2 -> 3 -> 4` 各运行 5 秒。目标 582 rpm，开环电流目标 800 mA，
trace 关闭，保护阈值和 PI/SMO/PLL/Rev-Up 均未修改。每组开始和结束都执行
`foc_stop`。

| Stage | 逆变器门 `总/观测/PWM` | 控制拍 | 完整 ISR WCET | 相对 stage 0 | 截止余量 | error/miss/fault | 峰值电流 | 结束时 observer |

| 0 | `0/0/0` | 66,086 | 9,253 cycles | 基线 | 25.98% | `0/0/0` | 约 938 mA | unreliable，估计 -797 rpm |
| 1 | `1/0/0` | 66,059 | 9,400 cycles | +147 | 24.80% | `0/0/0` | 约 914 mA | reliable，估计 592 rpm |
| 2 | `1/1/0` | 66,042 | 9,884 cycles | +631 | 20.93% | `0/0/0` | 约 916 mA | reliable，估计 633 rpm |

本轮能证明五种路径在这 5 秒开环包络内没有 deadline miss、控制错误或过流故障，且
最坏 stage 4 仍有 16.30% 软件截止余量。它不能证明补偿改善了真实转速、转矩或角度：
每个 stage 只有一次运行，`foc_status` 只是停机后的单点快照，没有编码器/独立电流真值；
尤其 stage 1 不改变观测器或 PWM 输出，却与 stage 0 得到不同可靠性，说明启动与观测器
本身存在明显的轮次波动，不能把单次 reliable 变化归因于补偿。

收尾时已恢复 stage 0 并执行 MCU reset。最终回读为 `uninitialized`、`0/0/0`、
Vbus 12.288 V、0 step/error/miss、duty `0/0/0`。

反向估速问题。没有编码器/独立电流真值时，也不得声称补偿已达到真实电压/转矩最优。

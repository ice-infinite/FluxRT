# EXP-B3 S4.9：一次性会话、ADC ISR 与无功率板端门

## 1. 结论

S4.9 的 **S1 / S2 / 无主功率 S4 PASS**。冻结 Ls(I) 状态机、Rust 计划器、C executor、
STM32G431 私有 preload permit 和 ADC ISR 已组成一条一次性会话链；Shell 只增加固定命令
`foc_lsi_start LSI1`，没有 duty、电压、拍数或电流参数入口。

本次没有接通主功率，没有使能 gate/MOE/CCER，没有运行电机。无功率门只能证明启动拒绝
和原有采集链不退化，**不能证明 active ISR WCET、带电 preload→active 相位、注入电流或
0.2 A 包络**。S5 仍需用户重新确认 2 A 电源限流、电机空载可自由旋转且可立即断电。

## 2. 实现边界

### 2.1 一次性管理 token

`foc_lsi_management` 版本升至 2，新增 `start_command_count/start_consumed` 和唯一共享实例：

- 错误 confirmation 返回 `REFUSED`，不消耗 token；
- 平台所有 live preflight 通过后才调用正确 confirmation；
- 正确请求每次上电最多成功一次；`abort/reset` 保留 `start_consumed=1`，不能获得第二次运行；
- 软件/硬件故障自动 abort 不冒充操作者 abort 计数。

### 2.2 平台 preflight

`foc_platform_lsi_start()` 只在 Identification + STM32G431 有效，并在关中断临界区检查：

1. TIM1/ADC/校准/同步采样和 bits 19、21～24 全部就绪；
2. 无 driver fault、Break、ADC error、current trip、deadline、control/output/capture error；
3. gate、MOE、CC1E/2E/3E 全关；
4. 同序列 Vbus 在 7～18 V；三相重构电流峰值不超过 0.05 A；
5. capture 未 armed、状态机 IDLE、一次性 token 未消耗；
6. 私有 active session 成功打开后，才消费 `LSI1` token 并置 live bit 25。

任一前置条件不满足都不进入状态机、不打开 permit、不消耗 token、不写 CCR。

### 2.3 ADC ISR 会话

ADC ISR 每拍先抓取 U/V/Vbus、当前 active CCR/ARR 与前一拍 drive/polarity，再重构三相电流：

```text
PREFLIGHT -> OFFSET_CAL(256 拍，输出关闭)
          -> BIAS(120 拍)
          -> +PULSE/-PULSE(4+4 拍 × 6 对)
          -> COOLDOWN(24 个低电流拍，输出关闭)
          -> COMPLETE
```

- 固定窗只在首次 active request 时 arm，不被 256 拍 offset 占满；
- 首笔 preload 要求输出全关，写入后临时屏蔽 TIM1 Update TRGO，再用 UG 装载 CCR，随后才开
  CCER/MOE/gate；屏蔽 TRGO 防止在 ADC ISR 内产生额外注入转换；
- 后续每拍要求输出全开并验证上一拍 tick/CCR/drive/polarity ledger；
- active→cooldown 同拍先关功率但保留采集，完成 24 拍尾流后关闭 capture/session；
- capture、executor、permit、寄存器复核、Vbus、过流、Break、driver fault、deadline 任一失败
  都同拍走快速关断并使管理状态 ABORTED。

诊断 bit 25 是 live `LSI_SESSION_RUNNING`，不是静态能力位；停机或无功率拒绝时必须为 0。

## 4. 无主功率 S4

硬件为 NUCLEO-G431RB + X-NUCLEO-IHM16M1，ST-LINK
`00400027544B500120343637`，COM6 @115200。烧录前先在 S4.8 固件执行 `foc_stop`：Vbus
raw=3、同步 Vbus=1、duty/step/error/miss=0、state 未启动、flags=`0x01E8231F`。

CubeProgrammer v2.19.0 将 S4.9 HEX 下载 110.46 KiB，download/verify/reset 均成功。启动：

```text
FLSI_STATUS,2,0,1,0,0,1,0,1,1,1,0,0,0,0
FLSI_HW,1,1,1,...,0,7083,...,296,275,863,...,31990559
```

状态表示 start/PWM/ADC 适配器已暴露，管理 state/drive=`IDLE/OFF`，token 计数 0/0；
`31990559=0x01E8231F`，静态 bits 19、21～24 保持，live bit 25 正确为 0。

拒绝门：

- `foc_lsi_start WRONG`：Shell 严格拒绝，token 仍为 0/0；
- `foc_lsi_start LSI1`：返回平台状态 2 `FOC_STATUS_NOT_CONFIGURED`，因为同步 Vbus=0，
  token 仍为 0/0，CCR/gate/MOE 未变化；
- `foc_start 582`：Identification 编译门继续拒绝。

断电固定窗结果：

```text
count=256 sequence_ok=True tick_ok=True
sequence=0..255 tick=430363..430618
iu=1946..1956 iv=1930..1934 vbus=0..7
ccr_u=0 ccr_v=0 ccr_w=0 arr=7083 flags=128
FLSI_CAP_DUMP,1,256
```

最终 `foc_stop` 后 capture unread/overflow/contract/storage=`0/0/0/0`，管理 IDLE/OFF、token
0/0、duty/step/error/miss=0；无功率 monitor ISR max=1,606 cycles。主功率全程断开，电机
未运行。

首次串口批量探测未形成输出；随后一次整串发送因 RT-Thread Shell 接收节奏只解析到尾部
`us`。改为逐字符约 2～3 ms 发送后，全部机器行稳定回读。该问题只影响上位机发送方式，
没有改变固件状态或硬件输出。

## 5. 下一门：S5.0

下一步不再是继续静态补代码，而是首次 0.2 A powered session。执行前必须重新确认：

1. 主电源约 12.3 V、限流 2 A；电机空载且可自由旋转；异常可立即断电；
2. 只运行一次 `foc_lsi_start LSI1`，不自动重试；
3. 同步采集 FLSI raw、状态、fault 和完整 active ISR WCET；任一 fault/miss/电流越界立刻停止；
4. 先审查捕获的 tick/CCR/polarity/电流，再离线拟合；本门不直接更新生产参数。

在该确认和实测完成前，不得把 S4.9 写成“注入已运行”或“Ls(I) 已辨识”。

# P5.4 Advanced 受限实机前置门

## 1. 本轮结论（第三次S5与arm阶段诊断后更新）

P5.4 已完成 **S0～S4**，并按固定token执行了三次feature=0的powered S5。首次被deadline
门安全拒绝，第二次进入active后26拍被observer fallback门安全关断，第三次在首个实时拍前
被Break拒绝，因此当前仍不得继续高级功能上电：

- Rust/MATLAB 通用高级策略矩阵 9/9 PASS；它使用 48 V、`Ld != Lq` 的虚拟 IPMSM，
  只能证明算法合同，不能证明 GBM2804H-100T 适用；
- GBM2804 参数路径的全速动态双仿真 6/6、1,256 行 PASS，覆盖 dq 解耦、弱磁、正反转、
  负载阶跃、母线跌落和再生换向；模型使用理想转子反馈，仍不是无感或硬件真值；
- 已新增 P5.4A 专用的“固定配置 → 正常无感启动 → 闭环稳定确认 → 有界 active 窗 →
  ISR 自动关断 → 恢复 disabled”owner；Advanced Lab 普通 `foc_start` 被拒绝，Shell 只接受
  精确 token `P54-BASIC-100MS`；
- S4 在 Vbus 原始码 0～2 时验证：普通启动拒绝、错误 token 拒绝、正确 token 进入 owner
  后由平台母线预检拒绝，返回 `state=5/result=9`；前后均为 disabled、duty 0/0/0、
  fault 0、deadline miss 0；
- 首次powered S5在第83,930拍、观察器获取/交接附近出现一次完整ISR 12,972 cycles，
  超过12,750硬门222 cycles；owner返回`result=6`并关断，`active_ticks=0`，峰值电流
  约0.896 A，低于1.15 A软件trip；该结果证明关断门生效，不证明闭环稳定；
- 未放宽deadline。已把试跑owner每拍的100 B基础+68 B Advanced完整遥测复制替换为
  28 B版本化紧凑快照；初版因新增常驻对象使RAM增加24 B并在启动时触发串口FIFO分配断言，
  随后用无功率探针/试跑owner互斥共享union把RAM恢复至23,440 B，重复S4通过；
- 第二次S5后的诊断整改已把该28 B快照中的最终controller state、observer reliability和
  closed-loop位导出到Shell；全量S1、Advanced S2和断电S4通过，未改变控制律、参数、
  fallback门或保护阈值；
- 第三次S5没有进入实时控制拍，返回`start=4/FFAULT=0x1/snap=0`；Break路径安全关断，
  peak current、step和deadline miss均为0，随后恢复Basic；
- 已补不增加常驻RAM的arm阶段/事实诊断，区分BEGIN、开门前PRE和开门后POST，并记录
  BIF/B2IF、driver、Gate/MOE/CCER和commit；全量S1、Advanced S2与低母线S4通过，
  最终烧回新版Basic，真实Break非零事实仍待新的单次授权；
- 电机参数候选仍全部未审批。三次反电势测量的磁链重复性通过，但逐板相电压增益、负载、
  温度和独立真值仍缺失；LCR 包络也只是 line-to-line/2 的诊断范围，不是 `Ld/Lq` 辨识。

结论是：**第二次S5进入ClosedLoop active后26拍由observer fallback关断；第三次S5又在
首个实时拍前由Break关断。** 仍没有完成100 ms连续可靠闭环，也没有取得有效最终快照。
板上已恢复新版Basic，arm前/后Break阶段诊断已完成到断电S4；禁止直接进入dq解耦、放宽
fallback门或清故障重试。本报告不授权新的上电试验。

## 4. P5.4A 已落地的目标代码

1. `foc_advanced_power_trial.[ch]` 是硬件中立状态机；它不拥有寄存器，也不能自行 arm；
2. STM32G431 Advanced Lab 平台是唯一功率 owner，只在 stopped/fault-free 条件下提交候选；
3. 内部白名单只有 `feature=0` 和单独 dq 解耦；当前 Shell 只开放 feature=0；
4. owner 私有复制启动配置，把闭环和固定 582 rpm 只用于本事务，不放宽持久化 Profile；
5. 使用正式 startup/observer；只有 ClosedLoop 且 observer 可靠后才开始 active 计数；
6. active 窗固定 100 ms（1,200 个 12 kHz tick），ISR 到期同拍关闭 Gate/MOE/CCER；
7. 总事务超时、active 阶段 observer fallback、advanced fault、deadline miss、fault epoch
   变化或非法 PWM 均同拍关断；startup 阶段允许观察器尚未获取，不把正常获取过程误判为故障；
8. Shell 只接受精确 token，不提供任意 feature mask、转速、电流或时长；
9. 正常完成和非锁存拒绝路径恢复 Advanced disabled 和调用者 Basic runtime；真实锁存故障
   保持 sticky，不能为恢复配置而自动 clear fault，必须经显式安全恢复后再开始新事务；
10. Advanced Lab 的普通 `foc_start` 无权 arm；Motion/Advanced 各有独立 authority，不复用
    面向人工的通用入口。

### 4.3 首次powered S5与实时性整改

实机条件为12.3 V、2 A限流、空载自由旋转。旧Advanced BIN
`634D215D...C1A0`只执行一次精确token，结果为：

```text
FADVP,state=5,result=6,ticks=0/83930,first=0,
epoch=0/0,miss=0/1,features=00,status=00000000,
wcet=12972,ctrl=10356,diagmiss=1,finish=3
```

完整ISR门为12,750 cycles，超出222 cycles；峰值电流约0.896 A、Vbus约12.30 V，
没有软件过流。`active=0/first=0`表示100 ms闭环窗尚未开始，不能将“电机曾启动”视为
闭环通过。失败后双重`foc_stop`、读取状态并重烧既有Basic，最终disabled、duty0/0/0、
fault0、miss0。

根因路径是P5.4A安全owner为了逐拍判定，在正常Rust控制之外又请求100 B基础遥测并获取
68 B Advanced遥测。整改增加28 B固定布局快照，只保留state、observer可靠位、闭环位、
feature和状态位；尺寸或版本错误仍立即fail closed。12,750 deadline、12 kHz频率、控制律、
观察器和保护阈值全部未改。

初版整改验证：全量`test.ps1`通过（Rust356/356、Host C53/53、Python153+47、Clippy
0 warning）；Advanced Diagnostic `s`为ROM128,140 B、RAM23,464 B，BIN
`BC8A6AC6D4DA1F01878D9A4C439E2EF7E622EBA02A3ACB4D8FB6C17A61CA0C0D`。但首次断电S4
启动时反复触发`rt_serial_open:788`的`rx_fifo != RT_NULL`断言，Shell不可用。硬复位后仍可
复现，说明不是COM打开时序；立即恢复Basic后启动正常。根因是原本只余112 B的Advanced
runtime heap又被新快照及对齐消耗24 B，链接成功并不等于RT-Thread能完成串口FIFO分配。

修复将无功率探针的68 B完整遥测和powered owner的28 B快照放入共享union。两个owner本来
互斥；管理层读取powered状态时从owner字段重建对外遥测，不会把紧凑成员误解为完整结构；
静态断言同时阻止共享对象扩大。修复后Advanced为ROM128,172 B、RAM23,440 B，恢复到既有
RAM基线。BIN/HEX/ELF SHA-256分别为：

- `8D3CBC99BBBC640E31FE25DBAD8F90D3973F6B74D0B76BAF4DAEF4FB2F713F78`；
- `B52CB143C2F1A495DEFF04BED8E126E7EE775877650C9E5A590F4BDB55391BBC`；
- `80D287E9E8A089B8BF63B460020DFD23A0849FD5ABD6CCF1D8D98F61DF36D8CB`。

### 4.5 修复后的第二次powered S5

用户重新确认12.3 V、2 A限流、电机空载自由旋转且可立即断电。烧录的Advanced
BIN仍为`8D3CBC99...3F78`，与4.4节通过S4的候选逐字一致。预检为disabled、duty0、
fault0、miss0，母线约12.26 V。只执行一次固定token，结果为：

```text
FADVP,state=5,result=7,ticks=26/85714,first=85688,
epoch=0/0,miss=0/0,features=00,status=00000000,
wcet=12345,ctrl=10063,diagmiss=0,finish=3
```

`result=7`是`OBSERVER_FALLBACK`：事务在总拍85,688首次进入active，26个已提交拍约
2.17 ms后，紧凑快照里的`closed_loop_active`或`observer_reliable`至少一个变为0。
Advanced策略feature/status仍为0，fault epoch未变，deadline miss未增加。当前Shell输出没有
保留并打印这两个最终字段，故本次证据不能进一步区分“控制状态先退出”还是“运行可靠性门
先掉”；不得凭推测修改参数。

该次完整ISR最坏12,345/12,750 cycles，余405 cycles；control最坏10,063 cycles；峰值电流
560 counts约0.893 A，低于1.15 A软件trip。关断后的Power fault `0x20`是CONTROL，Rust
fault `0x40`是ADVANCED_CONTROL，均由owner把observer fallback升级为fail-closed而锁存，
不是驱动器保护输入故障。PWM立即归零，随后没有重试并恢复Basic；最终约12.30 V、disabled、
duty0、fault0、miss0，Advanced命令不存在。

控制器本身已有`observer_loss_timeout_s`，允许短暂运行可靠性抖动并保持角度连续；当前试验
owner则在active后的第一拍fallback立即停止。二者语义需要在取得最终state/reliable/
closed-loop字段后统一设计。现在不能简单删除owner门，也不能把26拍失败解释为应当放宽参数。

### 4.6 fallback最终快照诊断S1/S2/S4

本轮没有修改ISR控制路径或新增全局对象。管理层状态接口在原有status/telemetry之外复制
共享union中已存在的28 B最终快照，并在尺寸/版本不合法时返回全零无效记录；Shell正常结束
和启动拒绝路径统一打印`snap/ctrlstate/orel/closed`。Rust ABI测试把controller遥测预置为
ClosedLoop、reliable=1、closed=1，确认getter保留三个字段。

验证结果：

- 全量`test.ps1`退出0：Profile Python153、Simulation Python47、Rust workspace356、
  Clippy clean、Host C53/53；
- Advanced Lab Diagnostic `s` + timing probe：ROM128,396 B、RAM23,440 B，常驻RAM没有
  增加；BIN/HEX/ELF分别为`A480579E...153E`、`CFC5A347...6C87`、`6D91CBBA...655F`；
- 主电源断开、Vbus raw2～3约26～39 mV时，普通start和错误token仍拒绝；正确token返回
  `result=9,snap=0,ctrlstate=0,orel=0,closed=0`，表明低母线发生在首个有效实时快照前；
- 全程disabled、duty0/0/0、fault0、miss0，没有arm或电机转动；最后重建、烧录并校验
  Basic BIN `C045A6D2...4EB8`，Advanced命令不存在。

低母线S4只能验证“无有效快照”的清零路径；真实`snap=1`和三个掉线字段必须由下一次经
重新授权的同一受限S5取得。这个限制不能用Host PASS或目标构建代替。

miss0。本轮没有arm或电机转动。板上暂留该Advanced候选等待用户重新接通12.3 V并确认
2 A限流、空载自由旋转和异常可立即断电；在这些条件确认前不得发送新的正确token。

### 4.8 第三次S5：Break预启动拒绝

用户重新确认12.3 V、2 A限流、空载自由旋转且可立即断电后，Advanced预检读取Vbus
raw953约12.288 V、disabled、duty0、fault0、miss0。只发送一次固定token，事务立即返回：

```text
FADVP,start=4,state=5,result=9,finish=3,
snap=0,ctrlstate=0,orel=0,closed=0
```

`start=4`是`FOC_STATUS_HARDWARE_FAULT`，`result=9`是平台拒绝；`snap=0`说明尚未到首个
实时控制拍。双重stop后的证据为`FFAULT first/last=0x1`、count/epoch=1/1，其中`0x1`
是`FOC_POWER_FAULT_BREAK`；Rust fault `0x10`是平台输入。step、peak current、deadline miss和
duty均为0，电机没有转动。这不是observer fallback复现，也没有取得真实最终快照字段。

源码路径表明arm事务会在打开CCER/MOE/Gate之前和之后检查TIM1 BIF/B2IF与driver fault；但
当前`foc_status`只刷新driver pin/gate/output位，不直接导出TIM1 BIF/B2IF，启动失败行也没有
记录“开门前检查”或“开门后复核”阶段。因此现有证据不能区分：

1. 主电源接通期间已出现瞬态Break，BIF/B2IF在arm前就已静默锁存；
2. Gate/MOE/CCER打开后driver pin拉低或硬件Break实际触发；
3. 其他只在arm临界区出现的功率级异常。

没有清故障或重试。随后under-reset重烧并verify既有Basic `C045A6D2...4EB8`；约12.275 V
时回读disabled、duty0、fault0、miss0，Advanced命令不存在。硬复位后故障归零只说明活动
锁存被复位，不能证明外部故障原因已经消失。

### 4.9 arm阶段与硬件事实诊断

用户断开12.3 V主电源后，旧Basic回读Vbus raw2、disabled、duty0、fault0、miss0。整改不改
控制律、参数、保护或启动权限，而是复用`foc_platform_diagnostics_t`内两个既有`uint16_t`
保留字段，记录最近一次arm拒绝：

- 阶段：`0=NONE`、`1=BEGIN`、`2=PRE_ENABLE`、`3=POST_ENABLE`；
- 事实：`0x001=BIF`、`0x002=B2IF`、`0x004=driver`、`0x008=safety state`、
  `0x010=fault epoch`、`0x020=bus`、`0x040=channels`、`0x080=MOE`、
  `0x100=Gate`、`0x200=commit`；
- `foc_status`的`FFAULT`在既有四字段后追加`ARM,<stage>,<facts>`，前导字段顺序不变。

`foc_arm_diagnostics`是无状态、寄存器无关编码器；STM32平台只在arm线程临界路径保存
事实，不改变Break ISR、立即关断和输出提交。全量回归通过：Profile Python153、Simulation
Python47、Rust workspace356、Clippy clean、Host C54/54。Advanced Lab+timing probe目标为
ROM128,780 B / RAM23,440 B，RAM不增加；BIN/HEX/ELF分别为`9691B57A...CBB`、
`4092A676...0D1F`、`497FE873...FF6B`。

断电S4中普通start、错误token、正确token低母线均拒绝；正确token为`result=9`，状态保持
disabled、duty0、fault0、miss0，`FFAULT ... ARM,0,0000`。这符合低母线在arm临界区之前
拒绝的路径，但不验证真实`PRE_ENABLE/POST_ENABLE`非零事实。随后恢复并烧录新版Basic：
ROM112,636 B / RAM22,472 B，BIN `AAE01E19...3E5B`、HEX `B833B749...E5E5`；回读
Vbus raw0～2、disabled、duty0、fault0、miss0，Advanced命令不存在。

## 5. 整改后的重试门

第三次S5已被Break预启动拒绝并恢复Basic；arm阶段诊断也已完成S1/S2/断电S4。当前仍不得
通过清故障或复位后直接重试。只有用户重新确认12.3 V、2 A限流、空载自由旋转且可立即
断电，才可重新评审一次新的feature=0事务，用`ARM,2/3,<facts>`区分开门前/后故障。
observer fallback的owner可靠窗口设计继续暂停，任何方案仍不得直接打开解耦。后续记录至少包括：

- 固件BIN/HEX哈希、Profile、ABI、参数CRC和feature mask；
- startup到ClosedLoop时间、active首拍、总tick、自动停止原因；
- 完整ISR/control WCET、deadline miss、observer可靠性和fault快照；
- 三相电流峰值、母线最大值、d/q参考与反馈、最终duty和Gate状态；
- 停止后controller disabled、duty=0/0/0、fault状态和Basic恢复结果。

在无编码器、转矩计和独立动态电流/相电压仪器时，首轮S5只能证明“受限运行没有触发已知
故障且自动关断有效”，不能证明效率、转矩纹波、MTPA/MTPV最优性或仿真实机一致性。

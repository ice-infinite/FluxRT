# P5.4 Advanced 受限实机前置门

## 1. 本轮结论（第八次S5精确相位取证后更新）

P5.4 已完成 **S0～S4**，并按固定token执行了八次feature=0的powered S5。首次被deadline
门安全拒绝，第二次进入active后26拍被observer fallback门安全关断，第三次在首个实时拍前
被Break拒绝；第四次用新增事实字段把它定位为开门前历史B2IF，因此当前仍不得继续高级功能上电：

- Rust/MATLAB 通用高级策略矩阵 9/9 PASS；它使用 48 V、`Ld != Lq` 的虚拟 IPMSM，
  只能证明算法合同，不能证明 GBM2804H-100T 适用；
- GBM2804 参数路径的全速动态双仿真 6/6、1,256 行 PASS，覆盖 dq 解耦、弱磁、正反转、
  负载阶跃、母线跌落和再生换向；模型使用理想转子反馈，仍不是无感或硬件真值；
- 已新增 P5.4A 专用的“固定配置 → 正常无感启动 → 闭环稳定确认 → 有界 active 窗 →
  ISR 自动关断 → 恢复 disabled”owner；Advanced Lab 普通 `foc_start` 被拒绝，Shell 只接受
  精确 token `P54-BASIC-100MS`；
- S4 在 Vbus 原始码 0～2 时验证：普通启动拒绝、错误 token 拒绝、正确 token 进入 owner
  后由平台母线预检拒绝，返回 `state=5/result=9`；前后均为 disabled、duty 0/0/0、
  fault 0、deadline miss 0；
- 首次powered S5在第83,930拍、观察器获取/交接附近出现一次完整ISR 12,972 cycles，
  超过12,750硬门222 cycles；owner返回`result=6`并关断，`active_ticks=0`，峰值电流
  约0.896 A，低于1.15 A软件trip；该结果证明关断门生效，不证明闭环稳定；
- 未放宽deadline。已把试跑owner每拍的100 B基础+68 B Advanced完整遥测复制替换为
  28 B版本化紧凑快照；初版因新增常驻对象使RAM增加24 B并在启动时触发串口FIFO分配断言，
  随后用无功率探针/试跑owner互斥共享union把RAM恢复至23,440 B，重复S4通过；
- 第二次S5后的诊断整改已把该28 B快照中的最终controller state、observer reliability和
  closed-loop位导出到Shell；全量S1、Advanced S2和断电S4通过，未改变控制律、参数、
  fallback门或保护阈值；
- 第三次S5没有进入实时控制拍，返回`start=4/FFAULT=0x1/snap=0`；Break路径安全关断，
  peak current、step和deadline miss均为0，随后恢复Basic；
- 已补不增加常驻RAM的arm阶段/事实诊断，区分BEGIN、开门前PRE和开门后POST，并记录
  BIF/B2IF、driver、Gate/MOE/CCER和commit；全量S1、Advanced S2与低母线S4通过，
  第四次S5取得`ARM,2,0002`，即PRE_ENABLE只有历史B2IF且同拍driver输入不活动；
- 第五次S5越过Break门执行85,679拍后以`0x20/0x40`关断，但旧主机窗口丢失完成行；现已
  用带`--no-power-proof`的确定性工具在真实COM6完成低母线S4，精确捕获`start=2/result=9`、
  双stop、最终输出关闭和JSON/raw证据。该S4没有运行电机，powered完成行仍须新授权后补取；
- 第六次S5使用确定性工具完整捕获：进入ClosedLoop后提交12拍即出现`observer_reliable=0`，
  owner以`result=7/OBSERVER_FALLBACK`安全关断；无deadline miss，峰值约0.909 A，最终duty0。
  这关闭了第五次的完成行缺口，但尚不能区分BEMF、相位误差等哪一道可靠性子门掉落；
- 第七次S5以`ogates=0x3f`把掉落定位到PLL相位门；第八次使用V3同拍快照取得
  `phase=+655 mrad`、`speed=793 rpm`、`lossus=83 µs`。相位误差仅比0.65 rad运行门高
  5 mrad（约0.29°），owner在首个失锁拍安全关断；这更像接管边沿瞬态证据，不支持
  “角度极性完全错误”或“持续失锁”的结论，也不授权直接提高阈值；
- 断电后的角度链审计没有发现极性或单位错误；Park/逆Park延迟补偿已存在且默认均为0，
  ST参考工程同样为0，该补偿不直接改变PLL原始相位可靠性门，因此本轮不改；
- 历史同板582 rpm闭环轨迹和当前逐控制拍PC仿真都表明接管后可能短时越过0.65 rad门，
  但在控制器既有0.20 s失锁期限内恢复。P5.4 owner此前“首个不可靠拍即停机”比控制器更严，
  现已改为：闭环所有权仍在时重置100 ms连续验收窗，只有控制器真正退出闭环、故障、
  deadline miss或总事务超时才关断；没有提高阈值，也没有自动重新arm；
- 第九次S5只执行一次固定token并完成`state=4/result=1`：连续可靠闭环1200拍/100 ms，
  `orel=1/closed=1/ogates=0x7f`、fault0、miss0，自动关断后恢复Basic。最终快照observer速度
  796 rpm、相位误差0.106 rad、峰值约0.912 A；ISR最坏12,469/12,750 cycles，只余2.20%；
- 电机参数候选仍全部未审批。三次反电势测量的磁链重复性通过，但逐板相电压增益、负载、
  温度和独立真值仍缺失；LCR 包络也只是 line-to-line/2 的诊断范围，不是 `Ld/Lq` 辨识。

结论是：**首拍关断确属P5.4试验owner与控制器0.20 s失锁策略不一致；修正后第九次S5已
首次完成100 ms连续可靠闭环并正常结束。** 这关闭了P5.4A feature=0短窗功能门，但不代表
速度跟踪、效率、转矩纹波或全工况完成：observer快照796 rpm明显高于582 rpm命令，且没有
编码器真值；ISR只余281 cycles。试验后已烧回并校验Basic。下一步转入离线分析速度超调和
实时性余量；禁止直接进入dq解耦、提高0.65 rad门或自动重复S5。

## 4. P5.4A 已落地的目标代码

1. `foc_advanced_power_trial.[ch]` 是硬件中立状态机；它不拥有寄存器，也不能自行 arm；
2. STM32G431 Advanced Lab 平台是唯一功率 owner，只在 stopped/fault-free 条件下提交候选；
3. 内部白名单只有 `feature=0` 和单独 dq 解耦；当前 Shell 只开放 feature=0；
4. owner 私有复制启动配置，把闭环和固定 582 rpm 只用于本事务，不放宽持久化 Profile；
5. 使用正式 startup/observer；只有 ClosedLoop 且 observer 可靠后才开始 active 计数；
6. active 窗固定 100 ms（1,200 个 12 kHz tick），ISR 到期同拍关闭 Gate/MOE/CCER；
7. 总事务超时、active 阶段 observer fallback、advanced fault、deadline miss、fault epoch
   变化或非法 PWM 均同拍关断；startup 阶段允许观察器尚未获取，不把正常获取过程误判为故障；
8. Shell 只接受精确 token，不提供任意 feature mask、转速、电流或时长；
9. 正常完成和非锁存拒绝路径恢复 Advanced disabled 和调用者 Basic runtime；真实锁存故障
   保持 sticky，不能为恢复配置而自动 clear fault，必须经显式安全恢复后再开始新事务；
10. Advanced Lab 的普通 `foc_start` 无权 arm；Motion/Advanced 各有独立 authority，不复用
    面向人工的通用入口。

### 4.3 首次powered S5与实时性整改

实机条件为12.3 V、2 A限流、空载自由旋转。旧Advanced BIN
`634D215D...C1A0`只执行一次精确token，结果为：

```text
FADVP,state=5,result=6,ticks=0/83930,first=0,
epoch=0/0,miss=0/1,features=00,status=00000000,
wcet=12972,ctrl=10356,diagmiss=1,finish=3
```

完整ISR门为12,750 cycles，超出222 cycles；峰值电流约0.896 A、Vbus约12.30 V，
没有软件过流。`active=0/first=0`表示100 ms闭环窗尚未开始，不能将“电机曾启动”视为
闭环通过。失败后双重`foc_stop`、读取状态并重烧既有Basic，最终disabled、duty0/0/0、
fault0、miss0。

根因路径是P5.4A安全owner为了逐拍判定，在正常Rust控制之外又请求100 B基础遥测并获取
68 B Advanced遥测。整改增加28 B固定布局快照，只保留state、observer可靠位、闭环位、
feature和状态位；尺寸或版本错误仍立即fail closed。12,750 deadline、12 kHz频率、控制律、
观察器和保护阈值全部未改。

初版整改验证：全量`test.ps1`通过（Rust356/356、Host C53/53、Python153+47、Clippy
0 warning）；Advanced Diagnostic `s`为ROM128,140 B、RAM23,464 B，BIN
`BC8A6AC6D4DA1F01878D9A4C439E2EF7E622EBA02A3ACB4D8FB6C17A61CA0C0D`。但首次断电S4
启动时反复触发`rt_serial_open:788`的`rx_fifo != RT_NULL`断言，Shell不可用。硬复位后仍可
复现，说明不是COM打开时序；立即恢复Basic后启动正常。根因是原本只余112 B的Advanced
runtime heap又被新快照及对齐消耗24 B，链接成功并不等于RT-Thread能完成串口FIFO分配。

修复将无功率探针的68 B完整遥测和powered owner的28 B快照放入共享union。两个owner本来
互斥；管理层读取powered状态时从owner字段重建对外遥测，不会把紧凑成员误解为完整结构；
静态断言同时阻止共享对象扩大。修复后Advanced为ROM128,172 B、RAM23,440 B，恢复到既有
RAM基线。BIN/HEX/ELF SHA-256分别为：

- `8D3CBC99BBBC640E31FE25DBAD8F90D3973F6B74D0B76BAF4DAEF4FB2F713F78`；
- `B52CB143C2F1A495DEFF04BED8E126E7EE775877650C9E5A590F4BDB55391BBC`；
- `80D287E9E8A089B8BF63B460020DFD23A0849FD5ABD6CCF1D8D98F61DF36D8CB`。

`result=7`是`OBSERVER_FALLBACK`：事务在总拍85,688首次进入active，26个已提交拍约

### 4.23 断电后的离线相关性与实时性结论

## 5. 整改后的重试门

第九次S5已完成100 ms连续可靠闭环，当前不需要再次重跑，也不得因为成功就提高0.65 rad
阈值或直接启用Advanced feature。任何新的powered事务仍需重新评审和用户确认。任一live pin
异常、BIF有效或清后B2IF重置位都要fail-closed且不得自动重试；observer可靠性门不得在
缺少最终字段时放宽。后续记录至少包括：

- 固件BIN/HEX哈希、Profile、ABI、参数CRC和feature mask；
- startup到ClosedLoop时间、active首拍、总tick、自动停止原因；
- 完整ISR/control WCET、deadline miss、observer可靠性和fault快照；
- 三相电流峰值、母线最大值、d/q参考与反馈、最终duty和Gate状态；
- 停止后controller disabled、duty=0/0/0、fault状态和Basic恢复结果。

在无编码器、转矩计和独立动态电流/相电压仪器时，首轮S5只能证明“受限运行没有触发已知
故障且自动关断有效”，不能证明效率、转矩纹波、MTPA/MTPV最优性或仿真实机一致性。

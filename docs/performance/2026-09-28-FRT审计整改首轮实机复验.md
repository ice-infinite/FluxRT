006/007` 的全部目标验收项。

## 4. WCET 整改过程

同步 Vbus、功率安全事务和提交前后复核带来必要的安全开销。首个整改镜像在同一场景
测得 10,344 cycles，超过 70% 门槛 9,917 cycles。随后只压缩等价热路径，不删除
审计要求的 state/epoch、BIF/B2IF、CCER/MOE、gate 和 driver 前后检查：

1. 常态没有 pending Rust fault 时不进入第二个 PRIMASK 临界区；
2. CCR 提交保持单一 ISR 调用契约并内联，冷故障锁存保持 noinline；
3. 固定周期校验用乘法替代每拍除法，序号使用 `u32::MAX` 哨兵；
4. 对轻量输入校验、PWM 合法性和观察器只读路由做定点内联；
5. 将每拍必经且只有一个目标调用者的 Rev-Up 状态更新内联。

收尾时还发现 Rust `///` 文档属性会参与 crate 元数据：把周期数直接写进该属性后，
BIN 从 `CC005ADC...` 变为 `A602D7BF...`，同样三轮仍为 9,792/9,762/9,754 cycles
且0 fault/miss。为避免“更新实测数字本身又改变被测镜像”的递归，源码最终只引用本
报告，不再嵌入具体周期数；重建后BIN逐字节恢复为已完成正式三轮的`CC005ADC...`。

| 阶段 | 完整 ISR | control | pre/post | 判定 |
|---|---:|---:|---:|---|
| 首个审计整改镜像 | 10,344 | 8,701 | 934 / 709 | 73.02%，未过 70% 门 |
| C/Rust 常态裁剪后 | 10,145 | 8,627 | 873 / 645 | 71.61%，仍未过门 |
| 轻量校验/观察器内联 | 9,884 | 8,387 | 873 / 624 | 69.77%，三次初筛通过但余量偏薄 |
| 最终 Rev-Up 内联 | **9,763** | **8,266** | 873 / 624 | **68.92%，三次正式复验通过** |

这里的 `pre/control/post` 是最坏同一拍的相关分段，不是三个独立峰值相加。

# FluxRT 注释规范

本文件定义 FluxRT 自有源码的双语注释约定。新增和修改文件时必须遵守。

This file defines the bilingual comment convention for FluxRT-owned sources.
Every new or modified file must follow it.

---

## 1. 适用范围

**要写注释的**：本工程手写代码与构建脚本。

```
applications/  board/  foc/  tests/  rust/crates/  simulation/  simulink/
build.ps1  test.ps1  SConscript  SConstruct  Kconfig  custom.cmake  rtconfig.py
```

**不写注释的**（官方或自动生成）：

```
packages/**            RT-Thread、STM32 HAL、CMSIS 官方包
rt-thread/**           上游 RT-Thread 源码
rtconfig.h             SCons 由 Kconfig 生成，重新生成会覆盖
.gitignore .gitattributes   配置文件
build/ cmake-build*/ rust/target/ slprj/ 仿真 results/   构建与运行产物
*.slx *.slxc *.elf *.bin *.hex *.map *.dblite
```

## 2. 语言与排版

**中文在前，英文在后。** 中文是主要说明，英文是等义补充。

Rust 使用文档注释 `///`（保证 `cargo doc` 能取到）：

```rust
/// 计算一次电流 Clarke 变换。
/// Computes one current Clarke transform.
///
/// 使用幅值不变形式，与固件 `foc_platform_stm32g431.c` 的换算保持一致。
/// Uses the amplitude-invariant form so it matches the C platform adapter.
pub fn clarke(input: Abc) -> AlphaBeta { ... }
```

C 使用 `/* ... */` 块注释：

```c
/*
 * 一次 ADC 注入采样到控制输出的完整路径。
 * Full path from one ADC injected sample to the control output.
 *
 * 必须在 ADC1_2_IRQHandler 内调用；本函数不加锁。
 * Must be called from ADC1_2_IRQHandler; it does not lock.
 */
```

Python / PowerShell / MATLAB 使用 `#` 或 `%`，同样中英各一段。

## 3. 注释密度

**文件头 + 每个函数/结构体 + 关键算法行。** 不逐行翻译代码。

### 必须有的三处

**① 文件头**：说明本文件职责、在架构中的位置、依赖方向。

```c
/*
 * FluxRT —— STM32G431 芯片平台适配层（快环入口）。
 * FluxRT - STM32G431 chip platform adapter (fast-loop entry).
 *
 * 职责 / Responsibility:
 *   - TIM1 中心对齐 PWM、ADC 注入同步采样、栅极使能与硬件关断
 *   - 唯一的 C 侧快环 ISR，调用 Rust `foc_rust_realtime_step()`
 *
 * 边界 / Boundary:
 *   - 不认识 Rust 控制器内部状态，只通过固定 C ABI 交互
 *   - 不做 FOC 算法；所有电流环/观测器计算都在 Rust 侧
 *
 * 参考 / Reference: docs/架构与安全边界.md, docs/C与Rust混合架构.md
 */
```

**② 函数/结构体**：说明做什么、参数单位与量纲、调用上下文约束、失败语义。

```c
/*
 * 把 duty 写入 TIM1 比较寄存器并复核输出范围。
 * Writes duty into the TIM1 compare registers and re-checks the range.
 *
 * 参数 / Parameters:
 *   output - 三相占空比，范围由 g_foc_platform_config 钳位 [0,1]
 *            three-phase duty, clamped by g_foc_platform_config
 *
 * 返回 / Returns:
 *   FOC_STATUS_OK            已写入且复核通过
 *   FOC_STATUS_DISABLED      未 arm，未写寄存器
 *   FOC_STATUS_HARDWARE_FAULT 有故障，已立即关断
 *
 * 上下文 / Context: 仅可由 ADC ISR 调用。
 */
```

**③ 关键算法行**：解释"为什么这么做"，而不是复述代码。重点是
硬件约束、单位量纲、取整/溢出、时序、以及踩过的坑。

```c
/* 电流极性约定为 (offset - raw)，与 IHM16M1/MCSDK 参考工程一致。
 * 写反会让 Id/Iq 同时变号，电流环仍能"稳定"，但观测器方向持续错误。
 * Current polarity is (offset - raw), matching the IHM16M1 reference.
 * Reversing it flips both Id and Iq; the loop still looks stable but the
 * observer stays wrong. */
```

### 不要写的

- 复述代码的字面意思（`/* i 加一 */ i++;`）
- 与实现不同步的过期描述
- 把设计文档整段抄进源码；应引用 `docs/` 下的文件
- 主观评价（"这段写得很烂"）

## 4. 必须标注的内容

工程内涉及以下内容时，注释中**必须**写明，这是本项目的硬要求：

| 类别 | 说明 |
|---|---|
| **单位与量纲** | `[V]` `[A]` `[rad]` `[rpm]` `[cycles]` `[counts]` `per-mille`。浮点与定点混用处必须写明 Q 格式 |
| **固定值来源** | 标 `[HW]` 实测、`[ST]` MCSDK 参考、`[FW]` 固件配置、`[VESC]` VESC 工程策略 |
| **未辨识参数** | Workbench 继承值必须标注"未经实物辨识" |
| **实时约束** | ISR 上下文禁止动态分配、阻塞、日志、Mutex 等待 |
| **安全语义** | 每个失败返回路径是否已清零输出、是否已关断栅极 |
| **ABI 影响** | 改动 `foc_*.h` 结构或函数签名时必须提示提升 ABI 版本 |
| **许可边界** | 借鉴 VESC 时只写公开控制理论，不粘贴 GPLv3 代码（见路线图 §3.3） |
| **兼容入口** | 保留的旧 API 要注明"仅供兼容/测试，实时路径不使用" |

## 5. 验证要求

改完注释后必须全部通过，任一项失败都必须先修好再提交：

```powershell
.\test.ps1                  # Rust fmt / 单测 / 仿真 / Clippy / 交叉编译 / C Host 测试
.\build.ps1 -BuildOnly      # 目标固件仍可构建
```

并自查：

- `git diff` 中**只有注释行变化**，没有逻辑改动；
- 注释里的量纲、返回值、失败路径与代码实际行为一致；
- 没有把待办或不确定的推断写成既成事实。

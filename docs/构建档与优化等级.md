# FluxRT 构建档与优化等级

## 1. 当前选择

日常开发默认使用：

```text
Profile = Diagnostic
RustOptLevel = s
```

原因是 A21.1 已移除应用层浮点文本解析链，A21.2 完成 V19 `z/s/3` 同口径实机
复测并选定 `s`，A21.3 又对默认 CommandModel 常态路径做数值等价裁剪。当前
Diagnostic + `s` 为 108,008 B ROM、剩余 23,064 B；trace-off 最坏完整 ISR 为
9,627/12,750 cycles，占 12 kHz 物理周期 67.96%，已通过 70% 阶段目标。
trace-on 最坏为 10,047 cycles，仍有 21.20% 软件 deadline 余量且 0 miss。
`z` 与 `3` 只作显式回归比较，不代表可因此提频或开放默认闭环。

`Production` 是可继续验收的生产候选构建档，不代表已经量产通过。它仍保持
`closed_loop_enable=0`，并保留立即关断、输出复核、过流、母线、驱动故障和 deadline
保护。A14 起三个构建档都会校验同一份编译期只读
`ProductionMotorProfile`；当前 revision 1 的审批位为 0，不授权闭环。

`Calibration` 是 A18 新增的停机采集专用档，不是可运行电机的调试档。它保留 A17
相电压固定窗，但不编入在线调参、实时 trace 或数学诊断，并在应用层和平台层两处
编译期拒绝 motor arm。

`Identification` 是 EXP-B3 新增的参数辨识专用档。当前有同步 raw 固定窗、Rust plan、
C executor、私有 bounded preload session、共享一次性管理 token 和 ADC ISR；普通
`foc_start` 仍由 `MOTOR_ARM_DISABLED` 双层拒绝。专用入口只接受 `foc_lsi_start LSI1`，
并在 token 前检查 7～18 V、近零电流、输出关闭和全部故障位。S5.0 已在独立确认后只执行
一次：bounded active/WCET 安全通过，但参数拟合被拒绝；该档仍不能自行重复功率实验或被
视为参数辨识通过。

## 2. 四种构建档

| 能力 | Diagnostic | Calibration | Identification | Production |
|---|---|---|---|---|
| `foc_status` / `foc_stop` | 保留 | 保留 | 保留 | 保留 |
| 正常 `foc_start` | 可用，仍受全部安全门约束 | 应用层与平台层编译期拒绝 | 应用层与平台层编译期拒绝 | 可用，仍受全部安全门约束 |
| `Ls(I)` 状态机启动授权 | 拒绝 | 拒绝 | 固定 `LSI1` + live preflight + 每次上电一次 | 拒绝 |
| 在线 `foc_cfg` 浮点调参 | 保留 | 裁剪 | 裁剪 | 裁剪 |
| `foc_trace` 与 64 项环形缓冲 | 保留 | 裁剪 | 裁剪 | 裁剪，API 返回未配置 |
| `foc_phase_capture` 与 4 KiB 固定窗 | 保留 | 保留 | 裁剪 | 裁剪 |
| 停机数学诊断/基准 | 按 Kconfig | 强制裁剪 | 强制裁剪 | 强制裁剪 |
| 同拍 WCET 与 deadline 保护 | 保留 | 保留；但不可 arm | 代码保留；但不可正常 arm | 保留 |
| 默认闭环权限 | 关闭 | 编译期禁止运行 | 编译期禁止正常运行 | 关闭 |
| 只读板卡/电机档案与 CRC | 开机校验，可停机临时调参 | 开机校验，无调参旁路 | 开机校验，无调参旁路 | 开机校验，无调参旁路 |
| 默认 Rust 优化 | `s` | `s` | `s` | `s` |
| 输出目录 | `cmake-build` | `cmake-build-calibration` | `cmake-build-identification` | `cmake-build-production` |

Production 裁剪在线调参的原因是固定参数候选不应在运行现场被 Shell 任意修改。A21.1前，
Diagnostic的`strtof`还会把newlib的`strtod`、断言和格式化依赖链拉入镜像；当前四档已统一
改为严格整数解析，Production只为保留的`foc_start`链接其中两个小函数。裁剪trace另回收
3,072 B 环形缓冲及其 ISR/输出代码。

档位主宏和能力宏集中在 `foc/include/foc_build_profile.h`。CMake 必须四选一定义
`FLUXRT_DIAGNOSTIC_BUILD`、`FLUXRT_CALIBRATION_BUILD`、`FLUXRT_IDENTIFICATION_BUILD`、
`FLUXRT_PRODUCTION_BUILD`；
若同时定义多个会编译失败。裸 SCons/Host 没有传档位时为了兼容既有流程默认 Diagnostic。
档位没有放进全局 `.config`，因为同一份 Kconfig 要能生成四套互不污染的 CMake 构建；
硬件、HAL 和算法候选开关仍由 Env/SCons/Kconfig 管理。

## 3. 常用命令

日常诊断构建：

```powershell
.\build.ps1 -Regenerate
.\build.ps1 -BuildOnly
```

Production 候选构建：

```powershell
.\build.ps1 -Regenerate -Profile Production -RustOptLevel s
.\build.ps1 -BuildOnly -Profile Production -RustOptLevel s
```

Calibration 停机采集构建：

```powershell
.\build.ps1 -Regenerate -Profile Calibration -RustOptLevel s
.\build.ps1 -BuildOnly -Profile Calibration -RustOptLevel s
```

Identification 参数辨识构建门：

```powershell
.\build.ps1 -Regenerate -Profile Identification -RustOptLevel s
.\build.ps1 -BuildOnly -Profile Identification -RustOptLevel s
```

重新比较 Rust 优化等级：

```powershell
.\build.ps1 -Regenerate -Profile Diagnostic -RustOptLevel 3
.\build.ps1 -Regenerate -Profile Diagnostic -RustOptLevel s
.\build.ps1 -Regenerate -Profile Diagnostic -RustOptLevel z
```

`-BuildOnly` 会检查所请求的 Profile/优化等级是否与 CMake cache 一致，不一致时拒绝
构建，避免把一个配置的固件误标成另一个配置。每个“档位 + 优化等级”都有独立 Rust
目录，例如 `build/rust-target-calibration-s`；CMake 显式链接对应归档，不能跨档复用
旧库。四档当前 Rust feature 相同，所以归档内容哈希相同是正常的，目录隔离仍是硬要求。

直接使用裸 SCons 时仍是 Diagnostic 语义，但 `rust/Cargo.toml` 的默认 `s` 在 A23 V19
后可能越过 Flash 容量；日常 VS Code、目标验证和 Production 构建统一走 `build.ps1`，
让脚本按档位选择并记录优化等级。

## 4. 实机采集

Diagnostic 支持 trace 关闭、10 Hz、50 Hz：

```powershell
python .\simulation\capture_timing_baseline.py `
  --profile diagnostic --port COM6 --rates 0,10,50 `
  --duration 5 --target-rpm 582 --allow-motor-run `
  --output .\simulation\results\timing-diagnostic.json
```

Production 已裁掉 trace，只能采集关闭状态：

```powershell
python .\simulation\capture_timing_baseline.py `
  --profile production --port COM6 --rates 0 `
  --duration 5 --target-rpm 582 --allow-motor-run `
  --output .\simulation\results\timing-production.json
```

脚本没有 `--allow-motor-run` 时拒绝启动；结束路径始终发送 `foc_stop`。闭环仍需另外
显式添加 `--closed-loop`，本构建档对比没有启用闭环。

## 5. 选择与发布规则

- 日常诊断、调参与波形采集构建使用 Diagnostic + `s`；A21.3 已使 trace-off
  完整 ISR 通过物理周期 70% 阶段门，但长测、提频和默认闭环仍需各自验收；
- `Ls(I)` 辨识开发只能使用 Identification + `s`；S5.0 单次注入已经完成且 token=1/1，
  禁止自动复位/重试；下一次必须先完成模型审查并重新人工确认；
- `3` 只用于性能回归基准；A21.2 中它比 `s` 多占 7,312 B 且最坏 WCET 略高；
- `z` 只作为体积下界，不得只凭尺寸改用；A21.2 中它使软件 deadline 余量降到 4.77%；
- 发布候选使用 Production + `s`，但还必须通过独立速度/角度真值、故障注入、长测和
  多板多电机一致性；
- 切换 Profile 或优化等级后必须重新记录 BIN SHA-256、`text/data/bss` 和板端 WCET；
- 不得仅凭“构建成功”或“电机能转”标记为生产可用。

本轮具体数据见
[`performance/2026-09-23-A1构建档矩阵.md`](performance/2026-09-23-A1构建档矩阵.md)。

`foc_cfg` 原栈帧约 480 B，叠加 Rust 配置校验和打印调用链后超过 2 KiB FinSH 栈。

`applications/main.c` 增加大量 Shell 文本或浮点解析路径。修正版已经完成无功率 S4：
Calibration 的编译期拒绝门有效，Diagnostic 的 stage `0/1/2/3/4/0` 与 `FTIMING` V2
标签一致，且没有再次溢出。板上当前为修正版 Diagnostic `0D62D11C...E1E66AF`，重启后
恢复默认 `0/0/0`、Vbus 0 mV、输出关闭；完整 ISR WCET 和低压限流 A/B 尚未执行。详见
[`performance/2026-09-24-CM3-Target逆变器补偿配置与时序标签.md`](performance/2026-09-24-CM3-Target逆变器补偿配置与时序标签.md)。

## 12. 2026-09-27 EXP-B3 S2 Identification 构建门

EXP-B3 不再借用 Calibration 档，而是增加独立的 Identification 主档。只有该档具有
`FLUXRT_BUILD_CAP_LSI_IDENTIFICATION`；Calibration 和 Identification 同时具有
`FLUXRT_MOTOR_ARM_DISABLED_BUILD`，使普通 `foc_start` 在应用层与平台层都无法进入
正常电机控制路径。其余三档即使直接调用纯状态机的 `request_start` 也会保持 `IDLE`。

| 指标 | Diagnostic + `s` | Calibration + `s` | Identification + `s` | Production + `s` |
|---|---:|---:|---:|---:|
| ROM (`text+data`) | 130,880 B | 100,304 B | 97,292 B | 98,396 B |
| RAM (`data+bss`) | 23,120 B | 13,072 B | 8,952 B | 8,952 B |
| BIN SHA-256 | `624D440B...B95AC53` | `3BDE7184...BCACE4F` | `DAC031A7...D69AD59` | `0D27BF43...E3906F3` |

Identification 和 Production 的 `ADC1_2_IRQHandler` 均为 1,208 B，反汇编文本 SHA-256

## 14. 2026-09-27 EXP-B3 S4.5 C executor 静态门

S4.5 之后只有 Identification 链接 `foc_lsi_executor_init/step` 与两个 Rust plan 符号；
其它三档均为 0。executor 只做 raw→SI、Rust plan、duty→CCR 和下一拍账本，返回尚未
施加的 `SAFE/WRITE_PRELOAD`，不访问 TIM1。固定窗 COMPLETE 新增同拍快速关断分支，
因此 Identification ISR 由 548 增至 550 条指令，但 executor 不在 ISR 调用链。
